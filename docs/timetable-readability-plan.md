# 시간표 시간축과 현재 시각 강조 개선

요청일: 2026-10-04. 앱 구현 전의 후속 작업 정의다. 관리자 개선 P9와 별도 범위로 관리한다.

## 요청과 확인 근거

- 주간표는 프로젝트 루트 `시간표1.png`, `시간표2.png`, `시간표3.png`처럼 가장 왼쪽에 시간 칼럼을 둔다.
- PNG는 왼쪽 시간 칼럼의 배치 참고다. 사용자 추가 정정에 따라 일정 칸의 시간 값은 예외 없이 모두 시간 칼럼으로 옮긴다.
- P2.13은 시간축 주간표 구현을 이미 완료했으므로 기존 완료 이력을 바꾸지 않고 후속 개선으로 등록한다.
- 현재 `WeekTimeGrid.tsx`에는 왼쪽 시간축이 있으나 헤더의 첫 칸이 빈 View이며 폭은 세로40/가로56이다.
- `needsOwnTimeLabel`은 여러 행에 걸친 일정에도 true를 반환하므로 시간축과 같은 정보가 일정 칸에도 반복된다.
- 주간표는 모든 일정의 원래 색을 동일하게 표시한다.
- `DailyScheduleList.tsx`는 과거 항목만 연하게 표시한다. 진행 중과 미래 항목 모두 원래 색이라 현재 구분이 약하다.
- 요일별 목록은 다른 요일을 보면 전부 upcoming으로 처리하고, 시각 갱신은 오늘일 때만 30초 간격이다.
- 사용자의 설치 앱 화면/버전은 이번 대화에서 직접 확인하지 않았다. 코드에 없는 시간축이라고 단정하지 않는다.

## P10.1 — 일정 칸의 모든 시각을 왼쪽 시간 칼럼으로 이동

주간표에 새 시간 칼럼을 중복 추가하지 않고 기존 시간축을 PNG 형태의 명확한 칼럼으로 정리한다.
헤더는 `시간 | 월 | 화 | 수 | 목 | 금` 순서로 표시하고, 왼쪽은 해당 행의 시작~종료 구간을 읽을 수 있게 한다.
세로/가로에서 시간 헤더·본문·요일 칼럼의 경계가 정렬되어야 한다. 가로의 고정 헤더도 같은 폭 계약을 사용한다.
일정 칸에 표시하던 모든 시작·종료 시각은 왼쪽 시간 칼럼으로 옮긴다. 일정 칸에는 시간 문자열을 전혀 표시하지 않는다.
여기서 시간 문자열은 일정의 startTime/endTime으로 생성하는 시각 라벨을 뜻한다. 사용자가 제목·메모에 직접 입력한 자유문구는 임의로 삭제하거나 시간 데이터로 재해석하지 않는다.
요일마다 시작·종료 시각이 달라도 각 일정의 실제 경계를 시간 칼럼과 행 경계로 정확하게 읽을 수 있어야 한다.
전체 일정의 시작·종료 경계를 시간축에 반영하고, 일정 칸은 해당 경계 사이를 병합한다. 겹치는 일정도 각 시각 경계를 보존한다.
예외 시각을 칸 내부에 남기는 방식은 사용하지 않는다. 제목·메모·아이콘은 유지하며 원본 시간 데이터는 그대로 보존한다.
임의로 PNG의 오타 시각을 실제 DB에 복사하거나 시간 데이터를 바꾸지 않는다.
구간 병합, 시작/끝 경계, 빈 시간 구간, 겹치는 일정, 시간이 없는 항목과 메모·과목·아이콘을 유지한다.
화면 확대 시 시간 숫자를 잘라버리거나 감추지 않고 읽을 수 있는 배치를 사용한다.
기존 요일 글자만 누르면 이동하는 동작과 스크롤 중 일정 칸의 무반응을 유지한다.
세로360/393dp, 가로, 글자 배율1.0/1.3에서 PNG1~3 형태의 데이터를 비교한다.

## P10.2 — 현재 시각만 밝게 표시

요일별 화면에서는 요일을 선택하는 즉시 기기 현재 로컬 시각을 다시 읽고 그 요일 일정과 비교한다.
선택한 요일이 오늘이 아니어도 같은 현재 시각대의 일정을 강조하는 시각 미리보기로 정리한다.
오늘 화면의 실제 진행 중 표시와 다른 요일의 `현재 시각 기준` 미리보기를 문구로 구별한다.
사용자에게 두 기준을 질문했으며, 별도 답이 오면 구현 착수 전에 그 기준으로 계획과 작업을 조정한다.
주간 한눈에 보기에는 선택 요일 상태가 없으므로 오늘 요일의 실제 진행 중 일정만 강조한다.
다른 요일 미리보기 정책을 주간표 전체 요일의 실제 진행 중 표시로 확장하지 않는다.

진행 판정은 `시작 <= 현재 < 종료`다. 진행 중만 원래 과목색과 분명한 테두리·상태 문구를 사용하고,
지난 항목과 앞으로 할 항목은 연한 배경 또는 회색 배경을 사용한다. 글자는 읽을 수 있는 대비를 유지한다.
색만으로 구분하지 않으며 현재 시각에 일정이 없으면 임의로 다음 일정을 진행 중으로 표시하지 않는다.
동시에 진행 중인 겹침 일정은 모두 강조하고, 잘못되거나 없는 시각은 강조 대상에서 제외한다.
화면을 계속 켜 두어도 시작·종료 시점에 맞춰 강조가 바뀌어야 하며, 요일 전환·탭 재진입·앱 복귀·자정·세트 변경 시 즉시 갱신한다.
시간 판정은 공통 함수로 두어 주간표와 요일별 화면에서 동일한 경계 규칙을 사용한다.
타이머/리스너는 화면 이탈·백그라운드·unmount 때 정리하고 오래된 비동기 결과가 이전 요일/세트의 강조를 덮지 않도록 한다.
시각은 화면 표시용 판단에만 사용한다. DB 일정·요일·알림 예약·위젯 정책을 변경하지 않는다.

## 검증과 상태

- 전/시작 직후/종료 직전/종료 시점, 일정 사이 공백, 마지막 일정 종료 후, 겹침과 잘못된 시각을 단위 테스트한다.
- 요일 전환 직후·앱 복귀·자정·주간/요일별 전환·세트 변경과 테마별 글자 대비를 확인한다.
- 현재 항목1개/겹침2개/없음 사례에서 현재만 밝고 나머지는 연하게 보이는 화면 근거를 남긴다.
- 구현 완료에는 관련 테스트, 버전 동시 수정, 전체 품질 검사, 등록된 리뷰 및 세로/가로 화면 확인이 필요하다.
- 설치 앱 확인과 에뮬레이터 근거는 구분한다. 현재 두 작업은 todo이며 실제 코드 구현은 하지 않았다.
