# 주간 시간표 "첫 칼럼=시간" 표 배치 가능성 검증 (P2.12)

기준: 사용자 엑셀 시간표 `시간표1.png`(학기), `시간표2.png`(7/27~31 방학 특강 주). 계산 함수는 `src/utils/timetableGrid.ts`, 픽스처 테스트는 `__tests__/timetable-grid.test.ts`.

## 방식
- 한 주의 모든 일정의 시작·종료 시각을 합쳐 **행 경계**로 삼고, 어떤 요일에도 일정이 없는 구간은 행에서 뺀다(압축).
- 일정은 걸친 행만큼 하나의 칸으로 합친다(`rowSpan`). 같은 요일에 시간이 겹치면 칸을 나란히 놓는다(`lane`).
- 행 높이는 시간 비례(분당 dp)에 최소·최대 높이를 둔다. 5교시 수업처럼 긴 행이 화면을 다 차지하지 않게 하기 위함이다.

## 검증 결과 (실데이터)
| 항목 | 학기(시간표1) | 방학 주(시간표2) |
| --- | --- | --- |
| 행 경계로 만든 행 수 | 14행 | 6행 |
| 시간 비례 1.2dp/분, 최소 28dp | 756dp | - |
| 최소 28 / 최대 64dp 제한 | 520dp 이하 | 400dp 이하 |
| 10분 이하 얇은 행 | 4개 (14:45/14:50, 16:10/16:20, 17:00/17:10, 18:00/18:10) | 없음 |

- 방학 주는 일정 구분이 단순해 6행이면 충분하다.
- 학기 시간표는 요일마다 시각이 5~10분씩 어긋나 **얇은 행 4개**가 생긴다. 최소 높이를 주면 읽을 수는 있지만 시간 비례가 깨진다.
- 표 자체는 "요일마다 시간이 달라도 한 주 전체의 시간 경계를 합쳐 첫 칼럼으로 쓸 수 있다"는 결론이다. 우려했던 행 폭발은 없었고(14행), 오히려 일정 종료 시각 오차가 행을 늘리는 주된 원인이다.

## 폭·높이 산정 (표 본문만, 헤더 제외)
검증됨(테스트): 행 수 14/6, 최소 36·최대 64dp 기준 학기 592dp, 방학 주 400dp 이하. 아래 폭 수치는 손계산 추정이며 P2.13 구현 후 에뮬레이터(API 36, 가로 2400x1080)로 실측했다: 시간표1 데이터가 세로에서는 스크롤로, 가로에서는 헤더·탭을 숨기고 한 번 스크롤하면 전체가 보인다.

| 구분 | 세로(약 360dp 폭) | 가로(약 800dp 폭) |
| --- | --- | --- |
| 요일 칸 폭 | 시간 칼럼 약 40dp + 5칸 각 약 60dp | 시간 칼럼 약 56dp + 5칸 각 약 140dp |
| 제목 | 11sp 한글 약 5자/줄, "생명융합과학"(6자)은 2줄 | 한 줄 |
| 자기 시각 표기(rowSpan>1 칸) | "14:10~16:20"은 한 줄에 안 들어가 2줄("14:10~" / "16:20") | 한 줄 |
| 최소 행 높이 | 36dp (제목 2줄) | 28dp (한 줄, 분당 0.8dp, 최대 48dp) |
| 표 필요 높이 | 학기 약 592dp / 방학 주 약 350dp | 학기 약 520dp / 방학 주 약 320dp |
| 화면에서 표가 쓸 수 있는 높이 | 약 640dp 화면에서 헤더·제목·탭 제외 약 400~450dp (추정) | P2.14 에뮬레이터 실측: 위쪽 영역을 줄이기 전 약 200dp, 줄여도 약 300dp 안팎 (추정) |
| 세로 스크롤 | 필요(학기) | 필요(학기), 방학 주는 거의 들어감 |

- 가로에서도 학기 시간표(약 520dp)는 스크롤 없이 들어가지 않는다. 가로의 이점은 **세로 높이가 아니라 칸 폭**(제목 한 줄, 시각 한 줄)이다. 그러므로 가로에서도 세로 스크롤을 허용한다. P2.13에서 가로 주간 보기는 앱 헤더·하단 탭을 숨기고, 학기/방학 이름·"요일별로 보기" 버튼·요일 헤더를 스크롤 밖에 고정했다(시간 칼럼은 스크롤과 함께 움직인다).
- 얇은 행 때문에 최소 높이가 시간 비례를 넘어서므로, 학기 표는 실제 시간 길이보다 얇은 행이 부풀어 보인다.
- 시간표1도 모든 시각이 이미지에 적힌 것은 아니다. 수요일 수업 종료 13:10(다음 일정 시작에서 추론), 수·금 해법수학 등 일부는 칸 위치로 읽은 값이다. 수요일 수업이 13:00에 끝나면 경계가 하나 늘어 15행이 된다.
- 압축으로 시간이 끊기는 구간(모든 요일이 빈 시간)은 시간 칼럼에서 표시할지 아직 정하지 않았다(질문 목록 참고).
- 시간표1의 "(일루스터 16:45 차)" 같은 부가 문구는 이 계산 대상이 아니며 P2.11(부가 메모) 결정에 따른다.

## 채택안 (P2.13 입력)
1. 모든 경계를 행으로 쓰는 표(후보 a) + 시간 비례 높이에 최소 36/최대 64dp 제한(후보 b의 일부).
2. 여러 행에 걸친 칸(`rowSpan>1`)은 칸 안에 자기 시작~종료 시각을 적는다(후보 c).
3. 세로·가로 모두 세로 스크롤을 허용한다. 가로는 위쪽 영역을 줄이고 제목·시각을 한 줄로 쓰며, 요일 헤더와 해제 버튼을 스크롤 밖에 고정한다.

## 결정 사항 (2026-09-30 사용자)
- 10분 이하 얇은 행은 **합치지 않고 정확한 시각을 그대로 둔다.** 시간 변경을 놓치지 않는 것이 앱의 핵심이라 표시가 실제와 달라지면 안 된다.
- 시간표1 수요일 "수업(4교시)" 종료 13:10은 **임시값**이다. NEIS 시간표 가져오기(P8.1)를 하면 실제 값으로 대체한다.

## 남은 확인
- 시간표1·2의 일부 칸 경계는 이미지에서 읽은 근사값이다. 실제 시간과 다르면 픽스처를 고친다.
- 모든 요일이 비어 압축된 구간을 시간 칼럼에서 구분해 표시할지는 정하지 않았다(현재는 앞 행의 끝 시각과 다음 행의 시작 시각이 나란히 나온다).
- 가로에서 여러 행에 걸치지 않는 칸(rowSpan=1)에도 자기 시각을 적을지(현재는 시간 칼럼이 대신 보여준다).
- 주간 표는 요일 템플릿만 보여준다. 특정 날짜의 예외(`day_exceptions`)나 이번 주만 바뀐 시간은 반영하지 않는다.
