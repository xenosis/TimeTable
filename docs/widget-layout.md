# 홈 화면 위젯 레이아웃

홈 화면 위젯은 두 종류다. 위젯 선택 화면에 따로 보이고 하나만 또는 둘 다 올릴 수 있다(사용자 결정 2026-09-30).

| 위젯 | 기본 크기 | 조절 | 보여주는 것 |
| --- | --- | --- | --- |
| 오늘 일정 (`TodayWidgetProvider`) | 4 x 2 (약 250 x 110dp) | 세로로 최대 약 300dp까지 | 정규 수업을 뺀 학원·방과후·돌봄·생활 일정 |
| 오늘 할 일 (`TaskWidgetProvider`) | 2 x 2 (약 110 x 110dp) | 세로로 최대 약 300dp까지 | 오늘의 할 일과 완료 상태, 못 한 일을 눌러 완료 |

두 위젯은 같은 데이터 파일(`widget-data.json`, 7일치 v2)을 읽고, 같은 갱신 경로를 공유한다. 앱이 데이터를 쓰거나 갱신 시각이 되면 `WidgetUpdater.updateAll`이 두 위젯을 함께 다시 그린다.

## 갱신 경로

| 계기 | 동작 |
| --- | --- |
| 앱이 데이터를 씀(앱 실행·복귀·백그라운드 작업·알림 재예약 뒤) | 파일을 쓰고 두 위젯을 다시 그린다 |
| 오늘 일정의 다음 시작·끝 시각, 자정 직후(00:00:01) | `WidgetRefreshReceiver`가 깨어 두 위젯을 다시 그린다. 정확한 알람(`setExactAndAllowWhileIdle`, 권한이 없으면 1분 범위 `setWindow`)으로 예약한다. 예전 `setAndAllowWhileIdle`은 딸 폰에서 1~6분 넘게 늦었다(2026-10-05, P5.4) |
| 부팅 · 시간 변경 · 시간대 변경 · 앱 업데이트 | `WidgetBootReceiver`가 다음 갱신을 다시 잡고 위젯을 바로 다시 그린다 |
| 시스템 주기 갱신 | `updatePeriodMillis` 30분(안전망. 기기가 깨어 있을 때만 전달) |
| 위젯 크기 변경 | 제공자가 위젯을 다시 그리고 목록을 새로 만든다(목록이라 크기만큼 자연스럽게 보인다) |
| 위젯을 모두 삭제 | 다음 갱신 알람을 취소한다(배터리). 다시 올리면 제공자가 예약을 되살린다 |

## 구조: 무엇을 보일지와 어떻게 그릴지를 나눈다

| 역할 | 파일 | 특징 |
| --- | --- | --- |
| 무엇을 보일지 계산 | `WidgetScheduleView.kt`, `WidgetTaskView.kt` | 안드로이드 API 없음. JUnit으로 검증 |
| 오늘 날짜 고르기·다음 갱신 시각 | `WidgetDayResolver.kt` | 기기 로컬 날짜 문자열 비교. JUnit |
| 할 일 체크 계산 | `WidgetChecks.kt` | 안드로이드 API 없음. JUnit |
| 그리기 | `ScheduleWidgetRenderer.kt`, `TaskWidgetRenderer.kt` | `RemoteViews`. 제목·상태 문구·스크롤 목록(`ListView`) 연결 |
| 목록 항목 만들기 | `TodayListService.kt`, `TaskListService.kt` | `RemoteViewsService`. 목록의 줄을 하나씩 만든다 |
| 파일 저장 | `WidgetCheckStore.kt`, `WidgetDataStore.kt` | 위젯 데이터와 대기 체크를 같은 잠금 안에서 쓴다 |
| 공용 그리기 도우미 | `WidgetRenderSupport.kt` | 색 변환, 목록 서비스 연결, 앱 열기(목록 템플릿 포함) |
| 제공자 | `TodayWidgetProvider.kt`, `TaskWidgetProvider.kt` | 다시 그리고 `notifyAppWidgetViewDataChanged`로 목록 항목도 새로 만든다 |

## 스크롤 목록 (P5.13, 2026-10-05)

두 위젯의 항목 영역은 안드로이드 표준 스크롤 목록(`ListView` + `RemoteViewsService`)이다. 줄 수를 계산하지 않고 위젯 크기만큼 보이며, 더 있으면 위젯 안에서 손가락으로 올려 본다. 글자 크기 설정이 커도 줄이 그만큼 커질 뿐 잘리지 않는다.

- 예전에는 줄을 미리 만들어 두고 높이로 줄 수를 계산했다(일정 최대 7줄, 할 일 최대 6줄). 딸 폰에서 일정 위젯을 4x4(459dp)로 늘려도 상한 때문에 다 보이지 않아 사용자 결정으로 목록으로 바꿨다.
- `+ N개`는 이제 앱이 하루 상한 때문에 위젯 데이터에 못 담은 개수가 있을 때만 목록 아래에 나온다.
- 목록 줄을 누르면 목록에 걸어 둔 템플릿(`setPendingIntentTemplate`)에 줄이 채운 내용(`setOnClickFillInIntent`)이 더해진다. 안드로이드 12+에서 템플릿은 mutable이어야 한다.

## 오늘 일정 위젯

1. 제목: `오늘 수요일`처럼 오늘 요일. 글자는 16sp 굵게.
2. 일정 줄: `색 표식 · 시작 시각 · 제목`. 시작 시각 순서. 글자는 14~15sp.
   - 지금 진행 중인 일정은 과목 색을 옅게 깐 배경으로 강조한다.
   - 이미 끝난 일정은 글자와 표식을 흐리게 한다(끝나는 시각 정각부터 지난 일정).
3. 오늘 일정 전체를 목록에 담는다. 끝난 일정은 위에 흐리게 남기고, 위젯을 그릴 때 지금 진행 중이거나 다음에 올 첫 일정이 처음 보이게 스크롤 위치를 맞춘다(`setScrollPosition`). 앱이 하루 상한 때문에 못 담은 일정이 있으면 `+ N개`.
4. 위젯(제목·줄)을 탭하면 앱의 오늘 화면으로 이동한다.

### 상태 문구

| 상태 | 문구 |
| --- | --- |
| 오늘 데이터가 없음(7일이 지났거나 읽기 실패) | `앱을 열어 새로고침해 줘` |
| 오늘 학교 수업만 있는 날 | `오늘은 수업 뒤 일정이 없어요` |
| 오늘 일정이 전혀 없음 | `오늘 일정이 없어요` |

학교 수업은 위젯에 싣지 않으므로, 두 번째와 세 번째를 나누기 위해 데이터에 날짜별 `hasSchool`(그날 학교 수업이 있는지)을 싣는다.

## 오늘 할 일 위젯

1. 제목: `오늘 할 일 1/3`(끝낸 개수/전체). 앱이 하루 상한 때문에 못 담은 할 일이 있으면 개수를 알 수 없으므로 `오늘 할 일`만 쓴다.
2. 할 일 줄: `☐/☑ · 제목`. **원래 순서를 그대로** 모두 목록에 담고, 끝낸 일은 그 자리에서 흐려지고 제목에 취소선이 그어진다. 줄이 빠지거나 움직이지 않으므로 누른 자리에서 다시 눌러 되돌릴 수 있다(예전의 '누른 줄 1분 유지' 규칙은 목록 방식으로 필요 없어져 지웠다).
3. 모두 끝내도 목록은 그대로 보여 주고(취소선) 제목 아래에 칭찬 문구 한 줄을 더한다. 그래야 잘못 눌렀을 때 다시 눌러 되돌릴 수 있다.
4. 앱이 하루 상한 때문에 못 담은 할 일이 있으면 목록 아래에 `+ N개`.
5. 목록 줄은 위아래 여백 5dp로 손가락으로 누르기 쉽게 했다.

### 체크 동작: 누를 때마다 완료와 미완료가 번갈아 바뀐다 (토글)

| 누른 곳 | 동작 |
| --- | --- |
| 못 한 일의 줄 | 그 할 일을 완료로 바꾸고(☑, 흐린 글자, 취소선) 위젯을 바로 다시 그린다 |
| 끝낸 일의 줄 | 다시 누르면 미완료로 되돌린다(☐, 진한 글자, 취소선 없음) |
| 제목·여백 | 앱이 열린다 |

사용자 결정(2026-10-01): 앱 안에서 체크하는 것과 같게 누를 때마다 토글한다. 취소하면 앱 안에서 취소한 것과 같은 규칙으로 연속 달성(실물 보석 자격) 기록이 다시 계산된다. 보석 장부 개수는 체크로 바뀌지 않는다(P13·P4.13 정책).

**기록 흐름** (DB에는 앱만 쓴다. 보석 계산과 중복 방지 규칙을 한 곳에 두기 위해서다):

1. 줄을 누르면 `WidgetTaskToggleReceiver`가 오늘 날짜의 줄인지 확인한다(자정 직후 어제 화면이 눌려도 어제 날짜로 기록되지 않는다). 맞으면 `WidgetCheckStore.toggle`이 위젯 데이터에서 그 할 일의 완료 상태를 뒤집고, `widget-pending.json`에 `{taskId, date, completed}`를 남긴다. 대기 목록을 먼저 쓰므로 그 뒤에 죽어도 눌렀는데 기록이 없는 일은 없다.
2. 이어서 `WidgetChecksHeadlessService`를 시작해 앱 화면 없이 JS 작업 `TimeTableWidgetChecks`(`src/widgets/widgetHeadlessTask.ts`, 진입 파일 `index.ts`에서 등록)를 실행한다. 이 작업이 바로 아래 3~5단계를 수행하므로 앱을 열지 않아도 곧바로 DB 기록과 알림 재예약이 끝난다(2026-10-05 사용자 결정, 딸 폰에서 앱 프로세스가 꺼진 상태로 확인). 서비스를 시작할 수 없으면 대기 체크가 남아 앱 실행이나 15분 백그라운드 작업(알림 재예약 흐름이 위젯 갱신을 부른다) 때 반영된다.
3. 앱(JS)이 실행되면(`widgetRefresh`) 대기 체크를 **읽기만** 한다(`peekPendingChecks`). 각 체크를 앱 안 체크와 같은 `setTaskCompletionWithRewards`로 DB에 기록한다(완료 이력·중복 방지·보석 규칙 동일). 그새 지워진 할 일의 체크는 버린다.
4. **기록에 성공한 체크만** `ackPendingChecks`로 대기 목록에서 지운다. 일시적 오류로 못 쓴 체크는 남겨 다음에 다시 시도한다(앱이 도중에 죽어도 체크가 사라지지 않는다). 그 사이 새로 눌린 체크도 남는다.
5. 한 건이라도 기록했으면 할 일 알림을 다시 예약해(끝낸 할 일의 재알림이 울리지 않게) 열려 있는 오늘 화면에 알린다(`widgetChecksSignal`). 오늘 화면이 완료 상태와 연속 기록을 다시 읽는다.
6. 앱이 위젯 데이터를 쓸 때(`WidgetCheckStore.writeData`) 아직 기록되지 않은 대기 체크를 새 데이터에 다시 입힌다. 앱이 DB를 읽은 뒤 쓰기 전에 눌린 체크가 위젯에서 되돌아가 보이지 않게 하기 위해서다.
7. 보석 트랜잭션(`rewardRepository`)은 한 DB 연결에서 겹치지 않게 순서대로 실행한다(화면의 체크와 위젯 체크 반영이 동시에 돌아도 안전).

접근성: 할 일 줄에 `"제목, 아직 안 했어요. 누르면 했다고 표시해요"` / `"제목, 했어요"` 설명을 붙였다. 일정 줄에는 아직 설명이 없다.

## RemoteViews 제약

RemoteViews는 `View`를 쓸 수 없어 색 표식도 `TextView`의 배경색으로 만든다. 본체는 `LinearLayout`·`TextView`·`ListView`, 목록 줄(`today_widget_item`, `task_widget_item`)은 `LinearLayout`·`TextView`만 쓴다. 데이터는 파일로 주고받아 앱이 죽어 있어도 읽힌다.

## 테마 반영 범위

앱 데이터 파일의 `theme`에서 아래 색만 쓴다. 값이 없거나 깨졌으면 기본색(흰 바탕, 진한 남색 글자)을 쓴다.

| 용도 | ThemeDefinition 토큰 |
| --- | --- |
| 위젯 바탕 | `colors.background` |
| 기본 글자 | `colors.text` |
| 보조 글자·흐린 글자 | `colors.textMuted` |
| 체크 상자·칭찬 문구 | `colors.primary` |
| 과목 표식 | 해당 `color_key`의 `backgroundColor` |

`accentShape`, `stickerShape`, 이미지 장식, 앱 배경 장식은 위젯에 넣지 않는다. 바탕은 단색이며 둥근 모서리는 런처가 처리한다.

## 위젯 선택 화면

- Android 12 이상: `previewLayout`(`today_widget_preview`, `task_widget_preview`)으로 실제와 같은 모양의 예시를 보인다.
- Android 11 이하: `previewImage`(`widget_preview_schedule`, `widget_preview_tasks`) 도형 그림을 보인다.
- 각 위젯에 설명 문구(`widget_schedule_description`, `widget_tasks_description`)가 붙는다.
