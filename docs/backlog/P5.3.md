# P5.3: 할 일 위젯에서 체크

## 목적

할 일 위젯의 각 행을 눌러서 앱을 열지 않고도 완료를 기록합니다. 네이티브에서 위젯 데이터와 DB를 동기화해 위젯이 즉시 갱신되고, 나중에 앱을 열었을 때 같은 완료 상태와 보석이 반영됩니다.

---

## 쉬운 설명

홈 화면의 할 일 위젯에서 행을 탭하면:
1. 앱을 열지 않고도 "완료"로 기록됨
2. 위젯이 즉시 갱신되어 체크 표시가 나타남
3. 나중에 앱을 열었을 때 그 완료가 이미 반영되어 있음
4. 보석도 마찬가지로 차감되거나 적립됨

누를 때마다 완료와 미완료가 번갈아 바뀝니다(토글, 사용자 결정 2026-10-01). 완료한 줄은 제목에 취소선이 그어지고 다시 누르면 원래대로 돌아옵니다.

---

## 필요한 입력

- 위젯 데이터: `widgetDataV2.ts` (할 일 목록, 완료 상태)
- 할 일 DB: `tasks`, `task_completions`, `task_completion_history` 테이블
- 보상 규칙: `rewardPolicy.ts` (보석 계산)

## 수행 순서

### 1. 네이티브 계층 (Kotlin)

1. `WidgetTaskToggleReceiver.kt` 구현
   - 각 할 일 행의 `PendingIntent`에서 할 일 ID 수신
   - `WidgetCheckStore.toggleTask()` 호출
2. `WidgetCheckStore.kt` 구현
   - widget-data.json 로드
   - 해당 할 일의 `completed` boolean 반전
   - widget-data.json에 다시 저장
   - widget-pending.json에 `{task_id, completed, timestamp}` 기록 (백업)
3. `WidgetUpdater.update()` 호출
   - `TaskWidgetRenderer`로 RemoteViews 다시 그리기
   - 완료/미완료 상태 즉시 반영
4. `TaskWidgetRenderer.kt`에서 각 행에 `PendingIntent` 설정
   - `WidgetTaskToggleReceiver` 액션으로 호출

### 2. JS 계층 (React Native)

1. `widgetRefresh.ts` 수정
   - 앱 시작/위젯 데이터 갱신 시 `peekPendingChecks()/ackPendingChecks()` 호출
   - 대기 중인 체크 목록 조회
2. `applyPendingWidgetChecks` 서비스 구현
   - 각 대기 체크에 대해 `setTaskCompletionWithRewards()` 호출
   - 앱 안 체크와 동일한 규칙 적용:
     - 중복 방지: 이미 완료된 상태면 스킵
     - 보석 적립: 같은 로직 (`rewardPolicy.calculateRewards()`)
     - 완료 이력: `task_completions`, `task_completion_history` 기록
   - 성공하면 widget-pending.json에서 제거
3. 할 일 알림 재예약
   - 앱이 반영한 뒤 `requestTaskRollingScheduleRefresh()` 호출

### 3. 테스트

1. JUnit 10개 (`WidgetChecksTest.kt`)
   - `complete()` 동작 (미완료 → 완료, 이미 완료면 변경 없음)
   - widget-data.json 변경 확인
   - widget-pending.json 기록 확인
   - 여러 할 일 연속 완료, 날짜가 오늘이 아닌 체크 무시
   - 에러 처리 (데이터 없음, 파일 손상 등)
2. Jest (`widget-pending-checks.test.ts`, `widget-refresh.test.ts`)
   - 실제 SQLite DB와 동기화 검증
   - 중복 방지, 보석 계산 확인
   - 이력 저장 확인

### 4. 에뮬레이터 확인

1. 홈 화면에 할 일 위젯 올림
2. 위젯의 할 일 행 탭
3. widget-data.json과 widget-pending.json 파일 변경 확인 (adb shell)
4. 위젯이 즉시 완료 상태로 갱신됨 확인
5. 앱을 열어 같은 할 일이 완료된 상태인지 확인
6. 완료된 행을 다시 탭해 취소선이 사라지고 미완료로 돌아가는지 확인

## 한계와 제약

### 기술적 제약

1. **RemoteViews의 액션 제약**: `PendingIntent`로만 상호작용 가능. 복잡한 로직은 `BroadcastReceiver`에서 처리해야 함.
2. **백그라운드 DB 접근**: 앱 프로세스 없이 Kotlin에서 SQLite를 직접 쓸 수 없으므로, 대기 파일(`widget-pending.json`)에 기록해뒀다가 앱이 실행될 때 동기화.
3. **개발 빌드 제약(해소)**: 2026-10-04 에뮬레이터에서 Metro를 연결해 위젯→앱 반영 전체 경로를 확인했다.

### 데이터 일관성

1. **네이티브-JS 동기화 시간차**: 위젯이 즉시 갱신되지만 앱이 나중에 깨어나서 DB를 업데이트. 그 사이 앱이 실행되면 데이터 불일치 가능성:
   - 대기 파일을 먼저 확인해 같은 완료를 두 번 기록하지 않도록 방지 (중복 방지 로직)
   - 타임스탬프로 순서 보장

2. **토글 설계(사용자 결정 2026-10-01)**: 위젯에서 다시 누르면 앱 안에서 취소한 것과 같게 완료가 취소되고 취소선이 제거됩니다.
