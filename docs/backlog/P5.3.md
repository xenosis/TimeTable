## 목적

할 일 위젯의 각 행을 눌러서 앱을 열지 않고도 완료를 기록합니다. 네이티브에서 위젯 데이터를 갱신하고 Headless JS 작업으로 DB와 알림을 즉시 동기화해, 위젯이 즉시 갱신되고 나중에 앱을 열었을 때도 같은 완료 상태와 기록이 반영됩니다.

---

## 쉬운 설명

홈 화면의 할 일 위젯에서 행을 탭하면:
1. 앱을 열지 않고도 "완료"로 기록됨
2. 위젯이 즉시 갱신되어 체크 표시와 취소선이 나타남
3. 나중에 앱을 열었을 때 그 완료가 이미 반영되어 있음
4. 할 일 알림이 다시 예약돼 끝낸 할 일의 알림이 울리지 않음

누를 때마다 완료와 미완료가 번갈아 바뀝니다(토글, 사용자 결정 2026-10-01). 완료한 줄은 제목에 취소선이 그어지고 다시 누르면 원래대로 돌아옵니다. 방금 누른 줄은 1분간 유지되어 그 사이에 다시 눌러 되돌릴 수 있습니다(사용자 결정 2026-10-05).

---

## 필요한 입력

- 위젯 데이터: `widgetDataV2.ts` (할 일 목록, 완료 상태)
- 할 일 DB: `tasks`, `task_completions`, `task_completion_history` 테이블
- 보상 규칙: `rewardPolicy.ts` (보석 정책, 연속 달성 자격)

## 수행 순서

### 1. 네이티브 계층 (Kotlin)

1. `WidgetTaskToggleReceiver.kt` 구현
   - 각 할 일 행의 `PendingIntent`에서 할 일 ID와 날짜 수신
   - `WidgetCheckStore.toggleTask()` 호출
2. `WidgetCheckStore.kt` 구현
   - widget-data.json 로드
   - 해당 할 일의 `completed` boolean 반전
   - widget-data.json에 다시 저장
   - widget-pending.json에 `{task_id, date, completed}` 기록 (대기 목록)
   - 누른 할 일 id와 시각을 `widget-touched.json`에 기록 (1분 유지용)
3. `WidgetUpdater.update()` 호출
   - `TaskWidgetRenderer`로 RemoteViews 다시 그리기
   - 완료/미완료 상태 즉시 반영
   - 약 1분 뒤 `setWindow(61초, 5초)`로 재그리기 예약 (누른 줄이 사라지도록)
4. `WidgetChecksHeadlessService.kt` 구현
   - IntentService로 화면 없이 Expo 작업 시작
   - 진입 파일 `index.ts`로 등록 (Expo Router 초기화 전에 작업 등록)
5. `TaskWidgetRenderer.kt`에서 각 행에 `PendingIntent` 설정
   - `WidgetTaskToggleReceiver` 액션으로 호출

### 2. JS 계층 (React Native)

1. Headless 작업 `TimeTableWidgetChecks` 구현 (`src/widgets/widgetHeadlessTask.ts`)
   - `peekPendingChecks()`로 대기 체크 목록 조회 (읽기만)
   - 각 대기 체크에 대해 `setTaskCompletionWithRewards()` 호출 (직렬화)
   - 앱 안 체크와 동일한 규칙 적용:
     - 중복 방지: 이미 완료된 상태면 스킵
     - 연속 달성: 자격 재계산
     - 완료 이력: `task_completions`, `task_completion_history` 기록
   - 기록 성공하면 `ackPendingChecks()` 호출
   - 할 일 알림 재예약 전에 대기 체크 먼저 반영
   - 할 일 알림 재예약: `requestTaskRollingScheduleRefresh()`
2. `index.ts`에 작업 등록 (Headless 작업 시작)
3. `widgetRefresh.ts` 갱신
   - 대기 체크 처리를 Headless 작업이 담당하므로, JS 진입점에서도 겹치지 않게 관리

### 3. 테스트

## 한계와 제약

### 기술적 제약

1. **RemoteViews의 액션 제약**: `PendingIntent`로만 상호작용 가능. 복잡한 로직은 `BroadcastReceiver`에서 처리해야 함.
2. **백그라운드 DB 접근**: Kotlin에서 SQLite를 직접 쓸 수 없으므로, 대기 파일(`widget-pending.json`)에 기록해뒀다가 Expo Headless 작업이나 앱 실행 시 동기화.
3. **Headless 작업 실패 대비**: 서비스 시작 실패 시 대기 파일이 남아 앱 실행 또는 15분 백그라운드 작업(알림 재예약) 때 반영됨.

### 데이터 일관성

1. **네이티브-JS 동기화 시간차**: 네이티브가 데이터를 먼저 갱신하고 Headless 작업이 DB를 업데이트.
   - 대기 파일 구조로 중복 방지
   - Headless 작업 실패 시에도 대기 파일이 남아 나중에 처리

2. **토글 설계(사용자 결정 2026-10-01)**: 위젯에서 다시 누르면 앱 안에서 취소한 것과 같게 동작.
   - 완료 취소 시 연속 달성 자격도 다시 계산
   - 보석 장부는 변경 없음(P13 정책)

3. **1분 유지(사용자 결정 2026-10-05)**: 방금 누른 줄은 1분간 제거되지 않아 다시 눌러 취소할 수 있음.
   - widget-touched.json에 누른 시각 기록
   - 1분 뒤 setWindow로 위젯을 다시 그려 남은 할 일이 올라옴
