# P6.11 — (선택) 완료 알림

- 상태(기준 입력): `done`
- schema version: `1.1`
- SHA-256: `451e4323fbdcb9f4d78193901a3361acdcafd3315f10d90a602674c214b420c4`
- 기준 입력 수정 시각: `2026-10-11T15:23:24.207Z`

## 목적

딸이 오늘 할 일을 모두 끝냈을 때 아빠 폰에 푸시를 보내 완료 사실을 알린다.

## 쉬운 설명

딸이 오늘 할 일을 마지막까지 체크하면 서버가 기존 푸시 발송 흐름에 완료 알림을 전달한다. 아빠 폰에 알림이 도착하고, 알림을 눌렀을 때 최신 완료 현황을 볼 수 있어야 한다. 오늘 할 일이 하나도 없으면 완료 알림을 보내지 않는다.

## 필요한 입력

- 같은 가족에 연결된 딸·아빠 계정과 기기 등록 정보
- 딸 기기의 오늘 할 일 및 완료 상태
- 아빠 기기의 푸시 토큰과 알림 수신 권한
- P6.9에서 마련한 푸시 발송 큐와 작업자
- 실제 수신 확인에 사용할 두 기기와 완료 가능한 검증용 할 일

## 결과물

- 오늘 할 일 전체 완료를 기존 푸시 큐에 연결하는 서버 구현
- 가족·역할·날짜·완료 상태에 따른 대상 및 발송 검증, 중복 방지와 재시도
- 완료 알림을 받은 아빠 폰과 알림 탭 후 최신 현황의 실기기 확인 기록

## 선행 작업

- 부모 작업: P6
- 직접 의존 작업: P6.9 변경 푸시 — 기준 입력에서 `done`

## 수행 순서

1. 오늘 할 일이 1개 이상이고 딸 계정에서 전부 완료된 때 완료 이벤트를 큐에 넣는다.
2. 같은 가족·날짜의 중복 발송을 막고, 실제 발송 직전에도 완료 상태와 대상 역할을 확인한다.
3. 기존 작업자가 같은 가족의 아빠 기기로 보내도록 연결하고 실패·receipt 처리와 재시도 경로를 확인한다.
4. 역할·가족·날짜·이벤트 순서, 0개 할 일, 반복 완료 및 알림 탭 후 최신 조회를 자동 검증한다.
5. 변경 SQL이 있으면 롤백 검증을 하고, 운영 적용 뒤 딸의 전체 완료부터 아빠 폰 알림 표시와 탭 결과까지 두 기기에서 확인한다.

## done_when 확인 방법

완료 조건은 “딸의 전체 완료 시 아빠 폰에 푸시 도착”이다. 딸 기기에서 오늘 할 일을 모두 체크한 뒤 아빠 폰의 알림창에 완료 푸시가 실제 표시되는지 확인한다. 큐 생성·작업자 발송 기록만으로 실제 도착을 대신하지 않는다. 알림을 눌러 최신 완료 현황이 보이는지도 함께 확인하고, 0개 할 일에는 알림이 생성되지 않는지 자동 검증 근거로 확인한다.

## 현재 확인 기록

2026-10-11 기준 1.63.2/182 구현의 자동 검사와 SQL 롤백 검증이 통과했고 운영 적용 및 작업자 배포가 기록되어 있다. 기준 입력의 마지막 기록은 양쪽 실기기에서 딸의 실제 1/1 완료, 큐 219의 정상 cron 발송, 아빠 알림창 도착, 알림 탭 후 최신 완료 현황과 100% 표시를 확인했다고 적는다. 임시 할 일은 체크 취소·삭제했고 보석 32는 유지했다. 전체 검사는 소스 변경이 없어 기존 통과 결과를 재사용했다. 정상 receipt 확인은 기준 입력 시점에 대기 중이며 실제 알림 도착 증거와 구별한다.

상세 실기기 기록: [2026-10-12 완료 알림 검증](../device-verification-2026-10-12.md). 기준 입력의 상태는 `done`이며, 이 문서는 상태 변경이나 완료 판정을 하지 않는다.

## 확인 질문

- 기준 입력 시점에 정상 receipt의 후속 확인이 대기 중이다. 실제 알림 표시와 탭 검증 뒤 receipt 결과가 확인되었는지는 제공된 백로그 입력만으로 알 수 없다.
