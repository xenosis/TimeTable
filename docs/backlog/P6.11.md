# P6.11 — (선택) 완료 알림

- 상태: needs_info
- schema version: 1.1
- SHA-256: 8d21e722c632186a5b9d4aa48f2865aacb405d5a3699c17d0ae1cdc5672451f7

## 목적

딸이 오늘 할 일을 모두 끝내면 아빠 폰에 푸시 알림을 보내, 아빠가 완료 사실을 바로 알 수 있게 한다.

## 쉬운 설명

딸 폰에서 오늘 할 일을 마지막까지 체크하면 서버가 완료 알림을 보낼 준비를 한다. 기존 푸시 발송 작업이 같은 가족의 아빠 기기로 알림을 보내고, 알림을 눌렀을 때 최신 내용을 확인한다. 오늘 할 일이 0개일 때는 완료 알림을 보내지 않는다.

## 필요한 입력

- 가족 및 역할이 연결된 앱 계정과 기기 등록 정보
- 딸 기기의 오늘 날짜 할 일과 완료 상태
- 아빠 계정의 푸시 토큰 및 알림 수신 권한
- 기존 변경 알림 발송 큐와 작업자

## 결과물

- 완료 알림을 큐에 넣고 기존 Edge Function 작업자가 발송하는 서버 구현
- 같은 가족 아빠 기기만 받도록 하는 토큰·역할·가족 검증
- 날짜별 중복 방지, 발송 직전 완료 상태 재확인 및 실패 재시도
- 관련 자동 검증과 운영 적용·실기기 수신 확인 기록

## 선행 작업

- P6 (부모 단계)
- P6.9 (변경 푸시; 직접 deps)

## 수행 순서

1. 오늘 할 일이 1개 이상이며 딸 계정에서 전체 완료된 경우에만 완료 이벤트를 큐에 넣는다.
2. 하루·가족 단위 중복을 막고, 발송 시점에도 완료 상태를 다시 확인한다.
3. 기존 푸시 작업자가 같은 가족의 아빠 기기 토큰을 대상으로 발송하고 실패 건을 재시도하게 한다.
4. 역할·가족·날짜·이벤트 순서 및 중복 토큰 필터링과 알림 탭 후 최신 조회를 검증한다.
5. SQL 변경은 롤백 방식으로 검증하고, 운영 적용 뒤 아빠 폰에서 실제 알림 수신을 확인한다.

## done_when 확인 방법

완료 시나리오에서 딸의 오늘 할 일이 모두 완료된 뒤 아빠 폰에 푸시가 실제 도착하는지 확인한다. 자동 테스트와 전체 검사는 큐 생성·중복 방지·수신 대상 제한·재시도를 뒷받침하지만, 실제 아빠 폰 수신 확인까지 있어야 `딸의 전체 완료 시 아빠 폰에 푸시 도착`을 입증한다. 0개 할 일에서는 알림이 생기지 않는지도 확인한다.

## 현재 확인 기록

2026-10-11 기준 1.63.1/181 보완 검증 기록이 있다. 한국시간 기준 오늘 할 일이 1개 이상일 때 전체 완료 큐 생성, 하루 중복 차단, 발송 전 재확인, 작업자 재시도, 아빠 토큰 등록, 네이티브 가족·역할·날짜·순서 차단 및 알림 탭 후 최신 조회를 구현했다. 리뷰에서 확인된 접수 뒤 receipt 추적과 lease 종료 경로를 보완해 완료 ticket·receipt 저장·조회·재시도, 만료 토큰 처리, 발송 시도별 lease UUID 보호를 포함했다. 전체 검사 통과(92 suites/547 tests, Android build, 푸시 13건); SQL 롤백 검증에서 receipt 실패 재시도·현재 토큰 폐기·이전 receipt 및 임대 종료 보호를 확인했고 검증 뒤 객체 미잔존을 확인했다.

운영 적용과 아빠 폰의 실제 푸시 도착은 아직 확인되지 않았다. 현재 ADB 연결 기기가 없어 실기기 수신 확인을 보류했고, 등록 재리뷰가 요청된 상태다. 그러므로 자동 검사와 SQL 검증은 구현 근거이며 `done_when` 충족 근거는 아니다.

## 확인 질문

- 아빠 폰의 재로그인 및 알림 권한 확인이 필요한 것으로 착수 기록에 적혀 있다. 실제 수신 확인을 위해 이 조치가 여전히 필요한지, 완료되었는지는 현재 입력만으로 알 수 없다.
