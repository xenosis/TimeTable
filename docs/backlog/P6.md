## 목적

아빠가 자신의 휴대폰에서 시간표와 할 일을 관리하고, 딸 휴대폰이 변경 내용을 받아 표시하게 한다. 딸의 완료 체크와 상태를 아빠가 확인할 수 있도록 Supabase 서버, 각 기기의 로컬 SQLite, 동기화와 알림을 연결한다.

## 쉬운 설명

아빠가 시간표를 바꾸면 서버에 저장되고 딸 휴대폰이 새 내용을 가져온다. 인터넷이 잠시 끊겨도 딸 휴대폰은 저장된 내용을 이용하고, 연결이 돌아오면 완료 체크를 서버에 보낸다. 아빠 화면에서는 딸의 완료 현황과 마지막 동기화 시각을 볼 수 있다.

## 필요한 입력

- 선행 단계 P5가 완료되어 있어야 한다.
- D4 결정: Doro에서 사용하던 Supabase 계정을 사용하고 이 앱 테이블을 추가한다. 같은 프로젝트를 쓸지는 P6.2에서 확정했다.
- D7 결정: 딸 휴대폰의 PIN은 로컬에서 확인한다. 서버 PIN RPC 작업 P6.10은 취소됐다.
- 가족 데이터·역할·기기 접근 정책, 로컬 시간표·할 일 데이터, 푸시 및 Firebase 설정이 필요하다.
- 두 기기에서 실제 로그인·원격 변경·완료 체크를 확인할 수 있어야 한다.

## 결과물

- Supabase 마이그레이션, RLS 정책 및 역할별 정책 검증
- 로그인과 아빠/딸 화면 분기, 최초 로컬 데이터 업로드
- 서버와 SQLite 간 동기화, 오프라인 체크 대기열, Realtime 및 앱 복귀 동기화
- 아빠의 시간표·할 일 편집, 딸 완료 현황·스티커·마지막 동기화 시각 표시
- 딸 기기 변경 푸시와 선택 기능인 전체 완료 푸시
- 서버 장애 중 로컬 알림·위젯 동작 확인
- 요구된 동작을 뒷받침하는 검사, 리뷰 및 두 기기 실기기 기록

## 수행 순서

1. D4·D7 결정을 문서화한다.
2. Supabase 스키마와 RLS를 만들고 실제 정책 검증을 수행한다.
3. 로그인 역할 분기와 최초 로컬 데이터 이전을 구현한다.
4. 온라인/오프라인 동기화, 로컬 알림·위젯 갱신, Realtime 및 앱 복귀 처리를 연결한다.
5. 아빠 관리 화면과 변경 푸시를 구현하고 기기별 동작을 확인한다.
6. 선택 완료 푸시와 서버 일시정지 대비를 확인한다.
7. 동기화 누락 조사를 포함해 완료 조건을 확인하고, 검사·리뷰 및 실기기 근거를 기록한다.

## done_when 확인 방법

기준 완료 조건은 “아빠 폰에서 수정하면 딸 폰에 반영됨”이다. 아빠 기기에서 시간표 또는 할 일을 저장하고 딸 기기에서 반영된 내용을 확인한다. P6의 상세 기록에는 두 기기 원격 편집·완료 체크·원격 지급, 오프라인 동작, 변경 푸시, 전체 완료 알림, 마지막 동기화 시각 및 P6.18 동기화 누락 수정에 대한 실기기 근거가 연결돼 있다. 하위 작업의 검사와 등록 리뷰 기록도 각 하위 항목의 evidence/log에 기록돼 있다.
