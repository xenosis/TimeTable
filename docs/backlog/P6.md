## 목적

Supabase와 기기별 SQLite를 연결해 아빠 폰에서 시간표·할 일을 수정하면 딸 폰에 반영되게 한다. 딸의 완료 상태를 아빠가 확인할 수 있고, 인터넷이 끊긴 동안에도 로컬 자료와 체크 기록을 유지한다.

## 쉬운 설명

아빠가 바꾼 일정은 서버에 저장되고 딸 폰이 받아온다. 딸이 할 일을 체크하면 서버에 올라가 아빠 화면에서도 보인다. 연결이 끊기면 딸 폰은 이미 저장된 일정과 알림을 사용하고, 다시 연결되면 변경 내용을 맞춘다.

## 필요한 입력

- P5 완료: 바탕화면 위젯을 포함한 MVP.
- D4 결정: Doro에서 사용하던 Supabase 계정을 사용하고 이 앱의 테이블을 추가한다. P6.2에서 프로젝트·스키마 적용을 확정했다.
- D7 결정: 딸 폰 PIN은 로컬에서 확인한다. 서버 RPC 방식인 P6.10은 취소됐다.
- 가족·계정·역할, 로컬 데이터, 서버 스키마와 RLS, 푸시 설정 및 두 기기에서 검증할 수단.

## 결과물

- Supabase 스키마, 역할별 RLS, 로그인 및 역할별 화면.
- 최초 데이터 이전과 서버·SQLite 동기화, 오프라인 체크 대기열, Realtime·앱 복귀·백그라운드 주기 동기화.
- 아빠의 편집·완료 현황·보석 지급·딸 기기의 마지막 동기화 시각 표시.
- 딸 기기의 변경 알림과 선택 완료 알림.
- 서버 장애 시 로컬 알림·위젯 동작 및 두 기기의 검증 기록.

## 선행 작업

- P5 완료.
- 자식 작업의 선행 관계는 기준 입력에 포함된 각 작업의 `deps`를 따른다. P6.10은 D7로 취소됐다.

## 수행 순서

1. D4·D7 결정에 맞춰 서버 스키마와 RLS를 준비하고 검증한다.
2. 로그인·역할 분기와 최초 로컬 데이터 이전을 구성한다.
3. 서버↔SQLite 동기화, 오프라인 기록, 알림 재예약·위젯 갱신을 연결한다.
4. Realtime, 앱 복귀 및 화면 없는 백그라운드 주기 동기화를 확인한다.
5. 아빠 화면, 변경 푸시와 선택 완료 푸시를 구현하고 검증한다.
6. 서버 연결 장애 중 로컬 동작, 두 기기 간 편집·체크 반영을 확인한다.
7. 하위 작업별 완료 근거와 검토·검사 기록을 대조해 P6 완료 조건을 판단한다.

## done_when 확인 방법

기준 조건은 “아빠 폰에서 수정하면 딸 폰에 반영됨”이다. 아빠 폰에서 시간표나 할 일을 수정하고 딸 폰에서 변경된 내용을 확인한 실기기 기록을 대조한다. 기준 입력의 P6.8 및 P6.18 기록에는 두 기기 간 원격 편집·체크 반영 근거가 있고, P6.19에는 화면 없는 주기 작업의 서버 변경 반영 근거가 있다. 하위 작업의 검사·리뷰·상세 시나리오는 각 하위 작업의 evidence와 log를 따른다. 자식 작업 완료만으로 부모의 등록 리뷰 완료를 대신하지 않는다.
