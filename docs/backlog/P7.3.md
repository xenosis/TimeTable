## 작업 목적

개발자(아빠)가 로컬 PC에서 앱을 검사하고 APK를 만들어 딸 폰에 설치·업데이트할 때 필요한 절차를 명확히 정리한다. APK 종류별 대상 환경(에뮬레이터 vs 실기기), 아키텍처(x86_64 vs arm64-v8a), 서명 방식(개발용 vs 정식)의 차이를 구체적으로 기록하여 실수를 방지한다.

---

## 쉬운 설명

앱을 완성하고 배포하려면 여러 단계를 거친다:

1. **PC에서 검사**: 코드 품질, 타입, 빌드 가능성 확인
2. **APK 만들기**: 목적에 따라 개발용, 테스트용, 정식 릴리즈 APK 생성
3. **폰에 설치**: USB 디버깅으로 APK를 딸 폰에 설치 또는 업데이트
4. **서명 키 보관**: 정식 릴리즈 서명 키를 안전하게 백업

이 문서는 각 단계의 명령어, 준비물, 주의사항을 정리한다.

## 결과물

**파일**: `docs/build-commands.md`

**필수 포함 내용**:

1. **준비물 섹션**
   - JDK 21 (또는 TIMETABLE_JAVA_HOME)
   - Android SDK (API 34~36)
   - Node.js 및 npm install
   - USB 디버깅을 켠 실기기
   - Expo Go 개발 불가 이유 (알람, 위젯)

2. **검사 명령 표**
   - `npm run check`: 모든 검사 (지침, 길이, lint, 타입, Jest, Android 빌드)
   - `npm run build`: x86_64 debug 빌드 + Kotlin JUnit (에뮬레이터용)
   - `npm test`: Jest만
   - 단일 검사: typecheck, lint, code-length
   - ⚠️ 주의: `npm run build`와 `npm run check` APK는 에뮬레이터용(x86_64), 딸 폰에는 설치 금지

3. **버전 올리기 섹션**
   - 동시 수정 파일 3개: app.json, package.json, android/app/build.gradle
   - patch/minor/major 정의

4. **APK 만들기 테이블** (딸 폰용 arm64-v8a)
   - `-OfflineTest -Target Device`: 개발 서버 없이 실제 화면·알람·위젯 확인
   - `-Target Device`: debug (Metro 개발 서버 필요)
   - `-Release -Target Device`: 정식 업데이트용
   - ✓ release.properties 필수, 없으면 중단

5. **APK 대상 구분 안내**
   - 딸 폰(SM-A245N): ARM, arm64-v8a만 가능 → 파일명에 "Device-arm64-v8a" 확인 후 설치
   - PC 에뮬레이터: x86_64 (Medium_Phone_API_36.0, Android 16 / API 36)

6. **폰에 설치·업데이트 절차**
   - adb devices 확인
   - adb -s <시리얼> install -r <APK 파일>
   - 같은 서명 APK: 덮어 설치 가능, 데이터 유지
   - **서명 다름**: 덮어 설치 실패 → 앱 삭제(adb uninstall) → 데이터 소실 → 알림/권한 재설정
   - 강제 종료 시 알람 예약 삭제, 앱 재실행으로 복구

7. **서명 키 백업 섹션**
   - 정식 릴리즈 서명 키 손실 시 이후 업데이트 불가능
   - 저장소 **외부**에 이중 보관 필수
   - 백업 위치: 아직 정하지 않음 (P7.6, 배포 직전 사용자가 직접 백업)
   - 비밀번호는 이 문서나 저장소에 절대 기록 금지

8. **자주 겪은 문제 테이블**
   - Gradle 증분 빌드 (Windows 타임스탐프 갱신)
   - Metro 포트 충돌 (8081)
   - 위젯 렌더링 지연
