# P1.7 — 빌드 준비: 서명 키 · APK 빌드 스크립트

## 기준 입력

- 백로그 schema version: `1.1`
- 백로그 SHA-256: `c605f66f8744992874eeecd72094e826abacf03da6f0297bbe3d65e7c17d54ce`
- 기준 항목: `P1.7`
- 기준 상태: `in_review`
- 이 문서만 갱신하며 원본 `backlog.json`과 프로그램 코드는 수정하지 않는다.

## 목적

새 릴리즈 서명 키를 만들고 안전하게 보관할 수 있는 설정을 준비하며, Doro의 빌드 방식을 참고한 `scripts/build-apk.ps1`을 제공한다. 완료 조건은 새 서명 키 생성·백업과 빌드 스크립트 존재다.

## 쉬운 설명

앱을 실기기에 설치할 APK를 반복해서 만들고, 업데이트 때 같은 서명 키를 사용할 수 있게 준비하는 작업이다. 서명 비밀번호와 키 파일은 공개하지 않는다.

## 필요한 입력

- P1.7 백로그 항목과 `P1.2` 선행 작업 결과
- `app.json` 버전 정보
- `android/release.properties`와 `android/release-keystore.jks`
- JDK 21 및 Android Gradle 환경
- 실기기용 ABI `arm64-v8a` 또는 스크립트가 허용하는 빌드 대상

외부 백업 위치, 키 비밀번호, 장기 보관 정책은 백로그에 없으므로 임의로 정하지 않는다.

## 결과물

- `scripts/build-apk.ps1`
- 새 릴리즈 서명 키와 릴리즈 설정
- 서명된 실기기용 릴리즈 APK
- 키 외부 백업 여부와 남은 확인 사항 기록

## 선행 작업

- `P1.2` 개발 빌드 설정 및 실행 결과 확인
- P1.7 로그의 키·릴리즈 설정·APK 생성 결과 확인
- `android/release.properties`의 비밀값을 문서에 기록하거나 공개하지 않음

## 수행 순서

1. P1.7의 `done_when`과 `P1.2` 의존성을 확인한다.
2. 새 키와 릴리즈 설정을 생성하고 비밀값 노출 여부를 확인한다.
3. `scripts/build-apk.ps1`의 debug·오프라인 테스트·release 및 ABI 분기를 확인한다.
4. 새 키로 실기기용 APK를 생성하고 설치·실행 및 서명 일치를 확인한다.
5. 프로젝트 밖 안전한 백업 여부를 확인한다. 사용자 결정대로 첫 장기 사용·실제 배포 직전에 수행할 수 있다.
6. `done_when`을 대조하고 미확정 사항은 질문으로 남긴다.
