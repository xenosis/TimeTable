# P3.8 — 공휴일 처리

## 기준 입력

- 기준 백로그 SHA-256: `098b05c9f159c9b2bff0e24cfe7aa6124ba61b42638e49e5240615a939a08c35`
- 기준 백로그 항목: `P3.8`
- 개발 상태: `done`
- 문서화 상태: 최종 구현·테스트·검토 근거를 반영했다. 문서화 완료와 개발 작업 완료는 별도로 관리한다.

## 목적

`day_exceptions`에 저장된 공휴일·방학 등 날짜 구간을 롤링 알림 조회 범위와 겹치는지 조회하고, 그 범위에 해당하는 학교 알림을 제외한다. 학원·생활 일정은 같은 날짜에도 유지한다.

## 쉬운 설명

알림을 만들 기간과 예외 기간이 하루라도 겹치면 해당 예외를 가져온다. 그 뒤 예외 날짜의 일정 타입에 따라:
- **공휴일** (type `holiday`): 해당 날짜의 모든 범주(학교·학원·생활) 알림을 제외한다.
- **학교만 쉬는 날** (type `discretionary`, 재량휴업일·개교기념일 등): 학교 알림만 제외하고, 학원·생활 알림은 그대로 유지한다.
- **방학** (별도 관리): 학원·생활 일정은 공휴일에도 알림 대상에 남는다.

## P8.8 반영 (2026-10-10)

P8.8 구현 이후 공휴일 처리가 세분화되었다:

- **type `holiday`** (공휴일): 한글날, 추석, 설날 등 국가 공휴일. P3.8의 롤링 알림 조회에서 해당 날짜의 **모든 범주 알림**(학교, 학원, 생활)을 건너뜀.
- **type `discretionary`** (재량휴업일 등): 개교기념일, 재량휴업일 등 학교 단위 휴업일. **학교 알림만** 건너뛰고, 학원·생활 알림은 그대로 유지. (기존과 동일)
- **방학** (여름방학, 겨울방학): day_exceptions에 넣지 않고 별도로 관리. 학원·생활 알림은 유지.

겹침 처리: 같은 날짜에 holiday와 discretionary가 겹치면 holiday(공휴일) 우선.

## 필요한 입력

- 가족 범위 식별자(`family_id`, 기본 로컬 가족 범위).
- 롤링 조회의 시작일과 종료일.
- `day_exceptions`의 `start_date`, `end_date` 기간, `type`.
- 알림을 계산할 일정의 요일, 시작 시각, category, 알림 방식과 미리 알림 분.

## 결과물

- `src/db/dayExceptionRepository.ts`
  - `getDayExceptionsInRange`가 `start_date <= 조회 종료일` 및 `end_date >= 조회 시작일` 조건으로 겹치는 예외 기간을 조회한다.
  - 가족 범위로 결과를 제한하고 시작일·종료일·id 순으로 정렬한다.
- `src/utils/rollingNotifications.ts`
  - type `holiday` 일정은 해당 날짜의 모든 범주(school·academy·life) 알림을 제외한다.
  - type `discretionary` 일정은 해당 날짜의 school 알림만 제외하고, academy·life 알림은 유지한다.
- `src/notifications/rollingSchedule.ts`
  - DB에서 조회한 예외 기간과 타입을 롤링 알림 계산에 전달한다.
  - 최대 미리 알림 시간만큼 예외 조회 종료 범위를 확장해 7일 창 경계의 학교 알림도 판정한다.
- `__tests__/database.test.ts`
  - 롤링 조회 범위와 겹치는 `day_exceptions` 기간을 조회하는 SQL 인자와 결과를 확인한다.
- `__tests__/rolling-notifications.test.ts`, `__tests__/rolling-schedule.test.ts`
  - type `holiday` 범위의 모든 범주 알림 제외 확인.
  - type `discretionary` 범위의 학교 알림만 제외·비학교 알림 유지 확인.
  - 7일 창 밖의 일정이 미리 알림 시간으로 창 안에 들어올 때도 해당 날짜의 예외와 타입을 조회하는지 확인.

## 선행 작업

`day_exceptions` 테이블과 일정 category 계약을 제공하는 P2.2 로컬 DB 작업 결과를 사용한다. 이 문서의 기준 입력에 포함되지 않은 별도 선행 작업이나 공휴일 데이터 공급 방식은 추가로 정하지 않는다.

## 수행 순서

1. 가족 범위와 롤링 조회 시작일·종료일을 입력한다.
2. 조회 범위와 겹치는 `day_exceptions`를 양 끝점 조건으로 가져온다.
3. 각 일정의 날짜와 예외의 타입(type)을 확인한다.
4. type `holiday`이면 해당 날짜의 모든 범주(school·academy·life) 알림을 제외한다.
5. type `discretionary`이면 해당 날짜의 school 알림만 제외하고, academy·life 알림은 유지한다.
6. 겹침 조회와 타입별 분기 테스트를 실행한다.
7. 전체 `npm run check`로 지침 동기화, 코드 길이, lint, typecheck, Jest, Android debug build를 확인한다.
