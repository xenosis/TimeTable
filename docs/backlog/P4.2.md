# P4.2 — 로컬 DB: tasks / task_completions / sticker_ledger / rewards

## 기준

- 백로그 schema version: `1.1`
- 백로그 SHA-256: `8fc3563a11c3932ec3153f5fdd0220037923ec48858d83eafb01d3ff1ff6795f`
- 백로그 상태: `in_review`
- 기준 백로그 항목: `P4.2`

## 작업 목적

오늘의 할 일과 완료 기록을 저장하고, 스티커 적립·사용 내역과 보상 목표를 로컬 SQLite에 보존한다.

## 쉬운 설명

앱을 다시 열어도 할 일과 완료 여부가 남도록 네 개의 표를 만든다. 스티커는 현재 잔액을 직접 덮어쓰지 않고 원장에 변동 내역을 쌓으며, 보상 목표는 별도 표에서 관리한다.

## 필요한 입력

- P4.2 백로그 항목과 `docs/research.md`의 데이터 모델
- 기존 SQLite 마이그레이션 버전과 실행기
- 현재 보상 정책 설정(`src/rewards/rewardPolicy.ts`)

보상 수량과 목표값은 기존 보석 시스템과의 밸런스 결정이 필요하므로 이 작업에서 확정하지 않는다. 테이블 구조와 마이그레이션은 값 결정과 독립적으로 진행한다.

## 결과물

`src/db/migrations.ts`의 schema v3에 다음 네 테이블과 필요한 인덱스가 등록되어 있다.

| 테이블 | 핵심 컬럼 | 역할 |
| --- | --- | --- |
| `tasks` | `family_id`, `title`, `repeat_weekdays`, `task_date`, `remind_time`, `alert_mode`, `sticker_reward` | 반복 또는 특정 날짜의 할 일과 알림·보상 설정을 저장한다. 반복 요일 또는 날짜 중 하나가 있어야 한다. |
| `task_completions` | `task_id`, `completion_date`, `done_at`, `done_by` | 할 일이 날짜별로 완료된 기록을 저장한다. 같은 할 일과 날짜의 중복 완료를 막는다. |
| `sticker_ledger` | `family_id`, `delta`, `reason`, `task_id`, `created_at` | 스티커 적립·사용 변동을 원장으로 저장한다. 연결된 할 일이 삭제되어도 원장 기록은 남는다. |
| `rewards` | `family_id`, `title`, `sticker_goal`, `achieved_at` | 사용자가 정한 보상 목표와 달성 시각을 저장한다. |

### v3 마이그레이션

1. 현재 `PRAGMA user_version`을 읽는다.
2. 버전이 3보다 낮으면 트랜잭션 안에서 네 테이블을 `CREATE TABLE IF NOT EXISTS`로 만든다.
3. `tasks_family_date`, `task_completions_date`, `sticker_ledger_family` 인덱스를 만든다.
4. 성공하면 `PRAGMA user_version = 3`을 기록하고 커밋한다. 실패하면 롤백한다.
5. 이미 버전 3 이상이면 마이그레이션을 다시 실행하지 않는다.

보상 금액, 할 일당 스티커 수, 전체 완료 보너스는 `null` 설정 변수로 남겨 두었다. 이 값이 미정이어도 `sticker_reward` 컬럼과 `rewards.sticker_goal`의 저장 구조 및 v3 마이그레이션은 생성할 수 있다.

## 선행 작업

백로그에 기록된 P4.2 의존 작업과 기존 SQLite 마이그레이션을 확인한다. 보상 값 결정은 이 테이블 생성의 선행 조건이 아니다.

## 수행 순서

1. `docs/research.md`의 로컬 데이터 모델과 P4.2의 `done_when`을 확인한다.
2. 기존 마이그레이션 뒤에 schema v3를 추가한다.
3. 네 테이블의 제약, 외래 키, 중복 방지 규칙과 인덱스를 등록한다.
4. 버전 0에서 v3까지 실행되는지와 이미 적용된 버전에서 재실행하지 않는지 확인한다.
5. 보상 값은 결정하지 않고 설정 변수로 남긴다.

## done_when 확인 방법

- `schemaV3`에 `tasks`, `task_completions`, `sticker_ledger`, `rewards`의 네 `CREATE TABLE IF NOT EXISTS` 문이 있는지 확인한다.
- 버전 0 mock DB에서 `migrateDatabase`를 실행해 네 테이블 문과 `PRAGMA user_version = 3`, `COMMIT`이 호출되는지 확인한다.
- 현재 버전 3 mock DB에서 실행해 DB 명령이 추가로 호출되지 않는지 확인한다.
- `npm run check` 결과에서 lint, typecheck, Jest, Android debug build가 모두 통과했는지 확인한다.
