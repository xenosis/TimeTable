## 기준 입력 및 현재 상태

- schema version: 1.1
- 기준 백로그 SHA-256: 4f912bbb6ecdfa4eb303043bdd95337007a702f71c359ac594c653be9c969704
- 백로그 상태: done
- 상위 작업: P12 (done)
- 선행 작업: P12.1 (done)
- 등록 리뷰어의 테마 범위 재검토·문서화와 최종 전체 검사 및 실제 화면 근거를 확인하여 완료했다.

## 목적

두 테마를 오늘·시간표·내 보석과 꾸미기 선택기에 적용하고 선택을 저장한다.

## 쉬운 설명

아이가 시나모롤 또는 쿠로미를 선택하면 배경·캐릭터·보석 장식이 해당 테마로 바뀌고 완전히 종료 후 다시 열어도 선택이 유지된다. 과목 색과 보석 수량 정책은 바꾸지 않는다.

## 필요한 입력

- [최신 테마 계획 및 사용자 결정](../character-theme-plan.md)
- 승인된 P12.1 캐릭터/보석 자산 및 화면 시안
- 기존 테마 저장·복원, 오늘·시간표·내 보석 화면

## 결과물

- 두 테마 레지스트리, 선택기/미리보기, 오늘·시간표·내 보석 및 탭 적용
- 앱 종료/재진입 뒤 선택 유지
- 해당 변경의 회귀 검사와 화면 근거

## 수행 순서

1. 계획서에서 최종 테마와 자산 적용 범위를 확인한다.
2. 두 테마를 선택기에 등록하고 제거된 ID 이전 및 선택 저장/복원을 구현한다.
3. 캐릭터·배경·카드·보석 장식을 오늘·시간표·내 보석에 적용한다. 의미 색, 보석 장부·수량·권리·목표는 유지하고 큰 보석 5점은 그림 표현에만 쓴다.
4. 각 테마 선택 후 force-stop/re-entry, 화면·글자·방향, 테스트·품질검사 결과를 기록한다.
5. dispatcher freeze 결과와 등록 리뷰 결과를 구분한다. freeze 실패를 리뷰 통과로 보고하지 않는다.

## done_when 확인 방법

> 테마별 캐릭터·배경·카드·보석 장식과 선택 미리보기가 다르며 앱 재시작 후 선택을 유지한다.

- **테마 차이:** 시나모롤/쿠로미 선택 시 캐릭터, 배경, 카드, 보석 장식이 바뀌는 근거를 확인한다.
- **선택 미리보기:** `.tmp/p12-picker-final.png`에서 두 테마가 구분되는지 확인한다.
- **선택 영속성:** 두 테마 모두 force-stop 뒤 재진입해 선택이 유지되는 근거를 확인한다. 쿠로미 근거는 `.tmp/p12-kuromi-restart.png`; 계획서에도 양쪽 절차가 기록되어 있다.
- **범위 회귀:** 과목 의미 색, 보석 수량/권리/목표 로직이 유지되는지 테스트 및 화면 근거를 대조한다.

## 현재 확인 근거와 제한

- 에뮬레이터 화면: `.tmp/p12-cinnamon-final.png`, `.tmp/p12-kuromi-final.png`; 작은 2개+큰 3개 입력에서 수량은 2/3, 그림은 시각적 17점으로 표시된 뒤 0/0으로 복원.
- `.tmp/p12-large-font.png`, `.tmp/p12-picker-large-font.png`: 배율 1.5에서 캐릭터/본문 분리, 한 열 선택기, 두 캐릭터, 선택 영역과 스크롤 확인. `.tmp/p12-landscape.png`: 가로 화면. `.tmp/p12-timetable-final.png`: 과목 의미 색 유지. `.tmp/p12-loading-large-font.png`: 로딩 문구와 캐릭터 분리 확인.
- 테마 선택 테스트에서 새 ID의 저장/유지와 제거된 ID 마이그레이션 확인. 대비, 시각 단계 11개 및 응원 문구 날짜 경계 검사 통과.
- 최종 `.tmp/p12-quality-resumed.log`: 48 suites / 313 tests, lint, typecheck, Android debug 모두 통과 (1m14s).
- Dispatcher의 두 agent가 exit 0을 반환했지만 Claude `GemCountEditor` 동시 변경으로 repository freeze 확인은 실패했다. 이를 전체 리뷰 통과로 표현하지 않는다. reviewer Medium 체크리스트와 양 테마 force-stop 재시작 기록을 계획서에 보완했다. 동일 기준 입력 재검토에서 Critical/High/Medium 지적은 없었고, 최종 CLI 상태는 done이다.
- 실기기 설치/배포/커밋/푸시는 수행하지 않았다. P12.2 상태는 `done`이다.
