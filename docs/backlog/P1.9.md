# P1.9 — 테마 계약 · 레지스트리

## 기준 입력

- 백로그 schema version: `1.1`
- 백로그 SHA-256: `c21379241f2ca2bb858d094c615e02dac9c2d99c130cb13cf340e9b427cb8ea9`
- 기준 입력 갱신 시각: `2026-09-17T00:17:39.534Z`
- 기준 항목: `P1.9` — 테마 계약 · 레지스트리
- 기준 상태: `done`
- 직접 선행 작업: `P1.4` (`done`)

## 목적

시간표에 실제 색상·아이콘 모양을 저장하지 않고 `color_key`·`icon_key` 의미 키를 저장하도록 테마 계약과 레지스트리를 제공한다. 선택된 테마가 키를 표시값으로 해석하며, 기존 `colors`·`categoryPalette` export와 기존 의미 키·색상은 계속 호환되어야 한다.

## 쉬운 설명

시간표에는 “수학”이라는 의미만 남기고 색과 아이콘은 테마가 정한다. 테마를 바꿔도 시간표 데이터의 의미는 바뀌지 않는다. 모르는 테마 ID나 의미 키는 안전한 기본값으로 처리한다.

## 필요한 입력

- 기준 stdin JSON의 P1.9 `summary`, `done_when`, `deps`, 상태와 로그
- 선행 작업 P1.4의 기존 테마 토큰·과목 팔레트
- D8 및 1-9 요구사항의 `docs/research.md`, `docs/tasks.md`
- `src/theme/index.ts`, `src/theme/contrast.ts`, `__tests__/theme.test.ts`
- 기준 입력의 schema version과 SHA-256

## 결과물

- `ThemeColors`, `ThemeCategory`, `ThemeIcon`, `ThemeDecorations`, `ThemeDefinition` 계약
- 기본 `daylightTheme` 및 검증·동결되는 `themes` 레지스트리
- `defaultThemeId`, `defaultTheme`, `getTheme()`와 테마 ID fallback
- 색상과 아이콘을 독립 해석하는 `resolveThemeColor()`·`resolveThemeIcon()` API 및 `other` fallback
- 기존 `colors`·`categoryPalette` 호환 export
- 대비·유일성·fallback·호환성을 다루는 단위 테스트 소스

## 선행 작업

- 직접 의존성은 `P1.4` 하나이며 기준 입력에서 `done`이다.
- `P1.10`~`P1.12`는 후속 작업이다. 로컬 저장, 선택 UI, 최소 두 개 테마는 이 작업의 완료를 의미하지 않는다.

## 수행 순서

1. stdin 기준 메타데이터와 P1.9 완료 조건을 기록한다.
2. D8·1-9 요구사항 및 P1.4 기존 export를 대조한다.
3. 테마 계약, 기본 테마, 장식·스티커 토큰을 확인한다.
4. 레지스트리 유일성·필수 키·대비·기본 테마 검증과 동결을 확인한다.
5. 테마 ID fallback, 색상/아이콘 독립 해석, 알 수 없는 키 fallback을 확인한다.
6. 호환 export와 테스트 사례를 대조한다.
7. 실행하지 않은 검사 결과는 추정하지 않고 정적 확인과 질문만 기록한다.

## done_when 확인 방법

- `ThemeDefinition`과 하위 계약 및 기본 테마를 확인한다.
- `assertValidTheme()`·`assertValidRegistry()`의 필수 값, `other` fallback, 유일성, 기존 키 보존, 대비 검증을 확인한다.
- `resolveThemeColor()`는 categories만, `resolveThemeIcon()`은 icons만 조회하고 알 수 없는 키를 fallback하는지 확인한다.
- `ThemeDecorations`의 카드·강조 도형·스티커 토큰을 확인한다.
- `colors`·`categoryPalette`가 기존 의미 키·색상을 계속 노출하는지 확인한다.
- `__tests__/theme.test.ts`에 위 조건의 사례가 있는지 확인한다. 실행 통과는 실행 기록이 있을 때만 인정한다.

## 현재 확인 기록

- `src/theme/index.ts`에서 요구된 계약과 `daylightTheme`을 확인했다.
- `assertValidTheme()`는 식별 정보, `other` fallback, 색상·장식·아이콘 유효성, 4.5:1 대비를 검사한다.
- `assertValidRegistry()`는 레지스트리·테마 ID·키 유일성, 기본 테마 정의 불변, 기존 color/icon key 전체 지원과 의미 라벨 보존을 검사한 뒤 동결한다.
- 레지스트리에는 `daylightTheme` 1개가 등록되어 있다. 테마 수 최소값은 P1.9에 없고, 최소 두 개 테마는 P1.12 조건이다.
- `getTheme()`은 알 수 없는 테마 ID를 기본 테마로 복구한다. 색상·아이콘 해석은 독립 목록과 `other` fallback을 사용하며 검증되지 않은 레지스트리와 미등록 테마 객체는 거부한다.
- 장식 토큰, 기존 호환 export, 관련 테스트 사례를 정적으로 확인했다.
- 기준 입력은 schema `1.1`, SHA-256 `8b4ec781f0b220714a12541d45990170e123e47409bb6ed7cc0625942455b8c7`만 사용했다.
- 원본 JSON 직접 읽기·수정, npm 명령, `backlog-review`, 품질 검사, 상태 변경, gate 실행은 하지 않았다. 따라서 실행 통과와 최종 `done`은 확인하지 않았다.

## 확인 질문

- 최소 두 개 이상의 독자 테마를 P1.9에도 요구할지, P1.12에 유지할지 확인이 필요하다.
- 미등록 테마 객체 거부 정책을 P1.9 요구사항에 명시할지 확인이 필요하다.
