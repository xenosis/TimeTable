## 작업 목적

TimeTable 앱이 Supabase 서버에 시간표·할 일·완료 기록·보석·보상 데이터를 안전하게 저장하고 아빠 폰에서 원격으로 관리하게 할 기반이 됩니다.

---

## 쉬운 설명

## 사용자 결정 반영 (2026-10-05)

### D4: Supabase 프로젝트 선택
- **결정**: Doro 프로젝트(공유)에 tt_ 테이블 추가
- **이유**: 매일 쓰는 Doro 덕분에 무료 플랜 1주 미사용 일시정지 회피, 관리 간소화
- **계정**: 아빠·딸 기기용 이메일+비밀번호 2개를 Supabase 대시보드 Authentication에서 생성
- **적용 방식**: `npx supabase` CLI로 로그인한 상태에서 `supabase db query --linked -f` 실행

### D7: 딸 폰 PIN과 권한
- **결정**: PIN은 화면 잠금만(로컬 확인), 서버에서 권한 확인하지 않음
- **영향**: 딸 계정에 시간표·할 일·교시·휴일·보상 목표·보석 원장의 쓰기 권한 모두 부여
- **설계**: 오프라인에서 체크한 기록이 나중에 올라올 수 있으므로 날짜 제한 없음

### 테이블 권한(Supabase 2026-10-30 changelog 45329 대응)
- **배경**: Supabase는 2026-10-30부터 기존 프로젝트에서도 public의 새 테이블을 Data API에 자동 노출하지 않음
- **대응**: RLS 파일(`20261001000100_tt_rls.sql`)에서 tt_ 테이블과 id 시퀀스에만 authenticated·service_role 권한을 직접 부여, anon 권한은 회수
- **효과**: Doro 테이블에 전체 스키마 grant를 쓰지 않으므로 Doro 데이터 접근 권한이 그대로 유지됨
