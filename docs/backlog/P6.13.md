## 작업 목적
서버 Supabase에서 가족의 모든 데이터를 받아와, 딸 폰의 로컬 SQLite를 업데이트하고, 알림·위젯·화면을 동시에 갱신한다. 첫 동기화는 서버 기준으로 로컬 데이터를 초기화한다.

## 쉬운 설명
쉽게 말해, 앱이 시작되거나 사용자가 '지금 서버와 맞추기'를 눌렀을 때:
1. 서버에 접속해 가족의 모든 데이터(시간표, 할 일, 완료 기록, 보석, 보상 등)를 받아온다.
2. 받아온 데이터를 로컬 SQLite 형식으로 변환한다.
3. 로컬 데이터를 서버 데이터로 통째로 교체한다(한 트랜잭션, 중간 실패 시 원복).
4. 위젯에서 눌린 체크를 먼저 로컬에 기록한다(만약 있다면).
5. 할 일 알림을 다시 예약하고, 위젯과 화면을 갱신한다.
6. 마지막 동기화 시각을 서버에 기록한다.

## 필요한 입력
1. **로그인 상태**: 가족에 연결된 Supabase 인증 토큰(로그인된 사용자)
2. **네트워크**: 인터넷 연결
3. **선행 조건**: P6.4(로그인·역할 분기) 완료, P6.5(로컬 데이터 서버 이전) 완료

## 결과물
- 서버 데이터가 로컬 SQLite에 저장됨
- 할 일 알림 재예약됨
- 위젯이 갱신됨
- 화면(오늘 일정, 오늘 할 일)이 최신 데이터를 표시함
- 서버에 마지막 동기화 시각(UTC)이 기록됨

## 선행 작업
- P6.4 로그인·역할 분기 (완료)
- P6.5 로컬 데이터 서버 이전 (완료)
- P6.6 부모 작업 범위 정의

## 수행 순서
1. 서버와의 데이터 연동 전략을 확인한다(첫 동기화는 서버 기준).
2. `pullFamilySnapshot()`: 서버에서 가족의 모든 테이블을 받아온다.
3. `toLocalSnapshot()`: 서버 형식(tt_ 테이블)을 로컬 형식으로 변환한다.
4. `replaceLocalWithSnapshot()`: 로컬 데이터를 서버 데이터로 교체한다(트랜잭션).
5. `runSync()`: 동기화 전체 흐름(위젯 체크 반영 → 서버 호출 → 로컬 교체 → 알림 재예약 → 위젯 갱신 → 마지막 시각 기록)을 관리한다.
6. `SyncPanel`: UI에 마지막 동기화 시각과 '지금 맞추기' 버튼을 보여 준다.
7. 오프라인·재시작 후 복구를 확인한다.

## done_when 확인 방법
다음 모든 조건이 충족되어야 한다:

1. **첫 동기화(로그인 후 앱 시작)**
   - 앱이 자동으로 동기화를 수행한다.
   - 옛 로컬 데이터(P6.5 이전 시험 데이터 등)는 정리되고 서버 데이터로 교체된다.
   - 화면에 서버의 시간표·할 일이 나타난다.
   - 위젯이 서버의 시간표·할 일을 표시한다.
   - 관리자 '서버 연결'에 마지막 동기화 시각이 표시된다(예: "오늘 23:38").

2. **서버 데이터 변경 감지**
   - 서버에서 할 일 이름을 바꾼 후 앱을 복귀하면, 앱 화면에 새로운 이름이 나타난다.
   - 서버에서 할 일을 지운 후 앱을 복귀하면, 앱과 위젯에서 그 할 일이 사라진다.
   - 알림 설정 변경(켜기/끄기)이 반영되어 할 일 알림이 예약/취소된다.

3. **오프라인 상태**
   - 비행기 모드에서 앱을 열어도 폰에 저장된 데이터가 계속 표시된다.
   - 인터넷 연결 후 앱을 복귀하면 서버와 다시 동기화하고, 서버의 최신 상태를 반영한다.

4. **동시 호출 보호**
   - 동기화가 진행 중인데 다시 호출되어도 진행 중인 동기화 하나만 실행된다(Promise 캐시).
   - UI의 '맞추는 중' 상태가 정확하게 표시된다.

5. **트랜잭션 보호**
   - 동기화 중 오류가 발생하면(네트워크 실패, 서버 오류) 로컬 데이터는 그대로 유지되고, 오류 메시지가 UI에 표시된다.
   - 로컬 데이터가 부분적으로 업데이트되지 않는다(all-or-nothing).

6. **데이터 형식 변환**
   - 서버의 ISO 형식 시각(예: `2026-10-06T23:58:00+00:00`)이 로컬 SQLite 형식으로 변환된다(예: `2026-10-06 23:58:00` UTC).
   - 서버의 요일 배열(예: `[1, 2, 3]`)이 로컬 CSV 형식으로 변환된다(예: `1,2,3`).
   - 서버 id는 그대로 로컬에 사용된다(이후 체크 기록이 같은 id를 가리키게 함).

7. **검사 통과**
   - `npm run check` 전체 검사 통과.
   - Jest 동기화 테스트 모두 통과(`sync-pull.test.ts`).
