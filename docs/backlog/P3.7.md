# P3.7 — 알림 탭 이동

**기준 스냅샷**: Schema version 1.1 | SHA-256: `61568fc7225e3df4e0b71db6293ab317e7874f64874dee78360c9f89f588cef7`

## 목적

앱이 실행 중이든 백그라운드 상태든, 또는 완전히 종료된 상태든 관계없이, 알림을 탭하면 해당 일정 상세 화면으로 바로 이동하도록 하기 위함.

---

## 쉬운 설명

알림 센터에서 알림을 탭하면:
1. 앱이 켜지고 (또는 이미 켜져 있으면)
2. 그 알림이 나온 일정의 상세 화면으로 이동
3. 관리자 설정 화면에 있던 상태에서도 같은 일정 화면으로 이동
4. 일정이 삭제되었으면 안내 메시지를 표시

## done_when 확인 방법

### 완료 기준

**앱 종료 상태 포함**, 다음 **모든** 조합에서 알림 탭 시 해당 화면으로 이동해야 함:

1. **일반 알림 (진행 중 알림)**
   - 앱 실행 중: 해당 일정 상세 화면 이동
   - 앱 백그라운드: 해당 일정 상세 화면 이동
   - 앱 종료: 콜드 스타트 후 해당 일정 상세 화면 이동

2. **전용 알람**
   - 앱 실행 중: 해당 일정 상세 화면 이동 (AlarmActivity에서)
   - 앱 백그라운드: 해당 일정 상세 화면 이동
   - 앱 종료: 콜드 스타트 후 해당 일정 상세 화면 이동

3. **할 일 알림**
   - 모든 상태(실행 중, 백그라운드, 종료)에서 **홈 화면**(또는 첫 화면)으로 이동
   - 이유: 할 일 상세 화면이 없음

4. **삭제된 일정**
   - 알림 탭 시 "이 일정이 더 이상 없습니다" 등 안내 메시지 표시

5. **엣지 케이스**
   - 관리자 PIN 화면에 있을 때 일정 알림 탭 → 일정 화면으로 이동 (PIN 화면 건너뜀)

### 실행 방법

**검증할 조합**(실측 결과는 아래 '검증 결과' 표가 기준이다):

| 알림 종류 | 앱 상태 | 기대 동작 | 2026-10-01 실측 |
|---------|--------|---------|------|
| 일반 알림 | 실행 중 | 일정 상세 | - |
| 일반 알림 | 백그라운드 | 일정 상세 | - |
| 일반 알림 | 종료 | 콜드 스타트 → 일정 상세 | - |
| 전용 알람 | 실행 중 | 일정 상세 | - |
| 전용 알람 | 백그라운드 | 일정 상세 | - |
| 전용 알람 | 종료 | 콜드 스타트 → 일정 상세 | - |
| 할 일 알림 | 모든 상태 | 홈 화면 | - |

**구체적 테스트**:
1. 앱에서 오늘 시간표에 여러 일정 생성
2. 예약 알림 목록에서 상태 확인 (rolling 진행 보임)
3. 알림 센터에서 특정 알림 탭
4. 해당 일정 화면이 나타나는지 확인
5. 앱을 백그라운드로 보냈다가 알림 탭 → 같은 화면으로 이동 확인
6. 앱을 완전히 종료 → 알림 탭 → 앱 재시작 후 해당 화면으로 이동 확인

**관리자 화면에서의 테스트**:
- 앱을 열고 관리자 PIN 입력 → PIN 화면 진입
- 이 상태에서 일정 알림 탭
- 일정 상세 화면이 나타나고 PIN 화면은 뒤로 밀림

## 검토 반영 (2026-10-01, critical-reviewer)

- **앱 종료 상태는 대체 검증**: 강제 종료(프로세스 없음)가 알림도 지우므로 실제 알림 탭 대신, 알림의 PendingIntent와 같은 구성(`ACTION_VIEW` + `kidtimetable://schedule/<id>` + 명시적 `MainActivity`, 추가 extra 없음: `AlarmNavigation.pageIntent`)의 인텐트로 콜드 스타트해 같은 화면을 확인했다. 코드상 JS는 알림 전용 처리 없이 URL만 읽으므로 동등하다고 판단하지만, SystemUI가 보내는 실제 탭은 검증하지 않았다. 잠금 상태에서 탭하면 키가드 해제를 거치는 경로도 확인하지 않았다.
- `am kill`은 이 앱에서 프로세스를 종료하지 못했다(프로세스 유지). 그래서 "알림은 남고 프로세스만 죽은" 상태는 재현하지 못했다.
- **화면 해석**: 일반 시간표 알림은 일정 화면, 할 일 알림은 홈(`AlarmNavigation`), 전용 알람 알림 본문은 알람 화면(`AlarmActivity`)으로 간다. 알람이 울리는 동안은 서비스가 프로세스를 잡고 있어 "죽은 앱 + 알람 알림" 조합은 사실상 생기지 않는다.
- 앱을 강제 종료하면 안드로이드가 앱의 알람 예약도 모두 지우므로, 테스트 뒤 앱을 다시 열어 재예약이 일어나게 했다(재예약 확인: 07:30·08:00 재등록).
