# P8.4 — 아빠용 주간 리포트

## 기준 입력

- 백로그 schema version: `1.1`
- 기준 백로그 SHA-256: `4d9faf2e4e870d0d37817335094b290371153dfe995274af78727fdd249b19c0`
- 기준 작업 상태: `needs_info`
- 상위 작업: `P8`
- 기준 입력의 작업 갱신 시각: `2026-10-10T13:22:20.231Z`

## 목적

아빠 역할 화면에서 이번 주 할 일 완료율과 최근 주별 보석 변화를 확인할 수 있게 한다.

## 쉬운 설명

아빠 계정으로 로그인한 화면에 주간 리포트를 보여 준다. 이번 주는 월요일부터 일요일까지이며, 이번 주 할 일은 오늘까지 날짜별 예정·완료 수와 완료율로 표시한다. 작은 보석과 큰 보석은 최근 4주 각각의 증감과 주 끝의 개수로 보여 준다. 가족 계정이 바뀌면 이전 가족의 집계가 남아 보이지 않도록 새 가족 데이터를 조회한다.

## 필요한 입력

- 아빠 계정의 역할 화면과 로그인한 현재 `familyId`
- 동기화가 완료된 현재 가족의 할 일 및 완료 상태와 날짜
- 현재 가족의 작은·큰 보석 장부 기록과 각 기록의 delta 및 날짜
- 확정된 주간 기준: 월요일~일요일. 보석 추이는 주 단위로 집계한다.
- 가족 전환 때 이전 가족 집계를 숨기고 새 가족 조회를 수행하는 상태 처리

## 결과물

- 아빠 화면의 주간 리포트 카드
- 이번 주 월요일~오늘의 날짜별 할 일 예정 수, 완료 수, 완료율
- 최근 4주간 작은 보석·큰 보석의 주별 증감 및 각 주 끝의 보유 개수
- 가족 전환 시 이전 가족 집계를 숨기고 새 가족 기준으로 조회하는 동작
- 구현 위치(작업 로그): `src/components/ParentWeeklyReportCard.tsx`, `parentWeeklyReport.ts`
- 확인한 구현: 카드가 `familyId`·날짜별 로딩 결과를 구분하고, 서버 동기화 전에는 집계를 숨긴다. 위젯 체크 반영·앱 복귀 때 다시 읽는다. 집계 유틸은 월요일 기준 주간과 최근 4주 보석 장부를 계산한다.

## 선행 작업

- 직접 의존성(`deps`)은 없다.
- 작업 로그의 설계 근거는 P6.6 서버 동기화 및 P6.8 아빠 화면 이후 해당 역할 화면과 서버 데이터를 사용하는 것이다.
- P8.4는 `P8`의 하위 선택 기능이다.

## 수행 순서

1. 로그인한 가족의 서버 동기화 데이터가 준비되었는지 확인하고, 준비 전에는 이전 가족 집계를 표시하지 않는다.
2. 현재 가족의 이번 주 날짜별 할 일 예정·완료 수와 완료율을 월요일부터 오늘까지 집계한다.
3. 보석 장부의 delta를 주별로 합산해 최근 4주의 작은·큰 보석 증감과 주 끝의 개수를 계산한다.
4. 아빠 화면에서 리포트를 표시하고 가족이 전환되거나 조회 응답이 늦게 도착해도 다른 가족의 결과가 표시되지 않는지 확인한다.
5. 회귀 테스트, 전체 검사, 등록 리뷰 및 가능한 기기 화면 확인 결과를 대조해 완료 조건의 충족 여부를 판단한다.

## done_when 확인 방법

백로그의 완료 조건은 **“주간 완료율·스티커 추이 리포트가 표시됨”**이다. 다음 근거를 확인한다.

- 아빠 계정 기기 화면에서 주간 완료율과 주별 스티커(보석) 추이 리포트가 표시되는지 확인한다.
- 이번 주의 날짜별 예정·완료 수와 완료율이 현재 주의 할 일 완료 상태를 반영하는지 확인한다.
- 최근 4주의 작은·큰 보석 변화가 각 주의 장부 delta 합 및 주 끝 보유 개수와 맞는지 확인한다.
- 가족 전환 중 이전 가족 집계가 숨겨지고 현재 `familyId` 조회 결과만 표시되는지 확인한다. 늦게 도착한 이전 조회 응답도 현재 결과를 덮지 않는지 확인한다.
- 테스트·전체 검사·등록 리뷰 기록과 기기 확인 기록을 함께 대조한다. 로그에 없는 동작을 확인된 것으로 간주하지 않는다.
