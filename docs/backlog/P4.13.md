## 목적

할 일을 모두 끝낸 날이 5일 연속되면 딸이 실물 보석을 받을 자격을 얻는다. 앱은 자격 개수만 기록하고, 요청·지급 흐름을 통해 아빠가 언제 줄지를 관리한다. 보석 개수(장부)는 딸이 직접 입력한다.

## 쉬운 설명

1. 할 일을 5일 연속 끝내면 보석을 1개 받을 수 있는 '자격'이 생긴다.
2. 딸이 "아빠한테 보석 달라고" 버튼을 누르면 아빠에게 요청이 간다.
3. 아빠가 실물 보석을 주고 앱에서 "줬어요"를 누르면 요청 처리가 완료된다.
4. 앱이 보석 개수를 자동으로 늘리거나 줄이지는 않는다. 딸이 직접 수정한다.

## 필요한 입력

- 연속 달성 계산: 할 일 없는 날은 건너뛰고 연속을 끊지 않음, 기간 5일 고정
- `task_completions` 테이블과 완료 여부 조회
- 자격 상태 관리: available (요청 전), requested (요청됨), given (지급됨)
- earned_date 유니크 제약: 같은 날에 같은 상태의 자격은 1개만 생성
- 딸 화면: 현재 연속 일수, 받을 수 있는 보석 개수, '아빠한테 보석 달라고 하기'
- 아빠 화면(PIN 관리자): 요청된 자격 리스트, '줬어요' 버튼 (오래된 요청부터 처리)
- 자격은 큰 목록이 아니라 "받을 수 있는 N개"라는 숫자 하나로만 표시

## 확정된 정책 (2026-10-05 최종)

### 보석의 성격
- 보석은 집에 있는 **실물**이다
- 앱은 자격 기록(gem_rights)만 관리하고, 개수(장부)는 관리하지 않는다

### 자격 생성 조건
- **기간**: 5일 고정
- **기준**: 할 일을 모두 끝낸 날이 연속 5일
- **할 일 없는 날**: 건너뛰고 연속을 끊지 않음 (예: 일요일 할 일 없음 → 월화수목금 5일 완료 → 금요일에 자격 생성)
- **중복 방지**: earned_date 유니크 제약 (같은 날의 자격 1개만)

### 자격 상태 전이
- `available`: 요청 전 자격 (오늘 체크 취소하면 회수, 아래 아님)
- `requested`: 딸이 "아빠한테 보석 달라고" 버튼 누른 상태 (취소 시 회수 안 함)
- `given`: 아빠가 "줬어요" 누른 상태 (취소 시 회수 안 함)

### 딸 화면
- 현재 연속 달성 일수 표시
- "받을 수 있는 보석 N개" (available 자격 개수)
- "아빠한테 보석 달라고 하기" 버튼: 모든 available 자격을 requested로 변경

### 아빠 화면 (PIN 관리자 보상 영역)
- 요청된 자격 개수 표시 (requested 상태)
- "줬어요" 버튼: 오래된 requested부터 최대 N개를 given으로 변경 (기본 N=전체)
- 버튼 누른 후에도 딸 화면의 장부 개수는 바뀌지 않음 (딸이 직접 입력)

### 장부 개수 (보석 개수)
- 딸이 직접 입력하는 필드 (앱이 자동으로 늘리거나 줄이지 않음)
- 요청·지급과 무관하게 동작 (딸의 '진짜 갖고 있는 개수' 추적용)
- Codex P11에서 구현 (app/(tabs)/stickers.tsx에 수정 입력 필드)

### 큰 보석 단계

## 확정 정책 이후 변경 (사용자 인계 반영)

- 오늘 화면의 수량 문구는 **작은 보석 · 큰 보석**으로 표시한다.
- 보상 목표의 `markRewardAchieved`는 달성 시각만 기록한다. 보석 장부 개수를 자동으로 차감하지 않는다.
- 새 할 일은 생성한 날부터만 완료·연속 판정에 반영한다. 과거 날짜를 검증하는 테스트는 할 일 생성 후 `created_at`을 해당 검증 날짜 이전으로 맞춘다.
- 앱에서 장부 개수를 바꾸는 경로는 딸이 직접 입력하는 `gemCountRepository`뿐이다. 체크·자격 생성·요청·지급·목표 달성은 장부를 자동으로 늘리거나 줄이지 않는다.
- P12의 큰 보석 5점 환산은 캐릭터 그림 변화에만 사용한다. 자격 정책과 실제 장부 수량은 그대로 유지한다.
