# P7.4 회귀 테스트

- schema version: `1.1`
- 기준 입력 SHA-256: `9fd62d6123685111ae43be0ee903cae351175ba1735d0ec1e48a281ba459a702`
- 현재 상태(기준 입력): `done`

## 목적

릴리즈 전에 `docs/test-checklist.md`의 회귀 항목과 기존 자동·실기기 근거를 대조해 앱의 주요 기능이 정상인지 확인한다. 실제 수행 결과, 자동 검사 결과, 사용자가 미실시 범위를 수용한 결과를 구분해 기록한다.

## 쉬운 설명

새 업데이트가 시간표·할 일·알림·위젯·동기화처럼 이미 동작하던 기능을 망가뜨리지 않았는지 확인하는 마지막 점검이다. 모든 항목을 이번에 다시 실행했는지, 이전에 확인된 근거를 재사용했는지, 사용자가 시험 생략을 수용했는지를 각각 알아볼 수 있게 남긴다.

## 필요한 입력

- `docs/test-checklist.md`: 원래 수동 회귀 절차와 범위.
- `docs/regression-verification-2026-10-12.md`: 영역별 기존 검사 근거, 제외 및 한계, 최종 수용 판정.
- `docs/device-verification-2026-10-12.md` 및 관련 이전 실기기 기록: 설치, 동기화, 알림 예약 등 실제 기기 확인 근거.
- P7.4의 기준 백로그 항목: `deps`는 P7.2 설치와 P3.9 체크리스트 작성, `done_when`은 전체 체크리스트 항목 통과.

## 결과물

- 체크리스트 영역별 확인 근거와 판정, 미실시 항목 및 한계를 담은 `docs/regression-verification-2026-10-12.md`.
- 이 문서의 완료 조건 대조와 현재 확인 기록.
- 완료 여부를 결정할 수 있도록 실제 PASS와 자동 검사 PASS, 사용자 수용을 서로 구분한 기록.

## 선행 작업

- P7.2 릴리즈 APK 설치: `done`.
- P3.9 수동 테스트 체크리스트 작성: `done`.
- 상위 P7의 선행 P6: `done`.

## 수행 순서

1. `docs/test-checklist.md`의 항목을 영역별로 나눈다.
2. 항목마다 이번 실측, 자동 검사, 기존 증거, 사용자 수용 여부를 확인해 근거 문서에 적는다.
3. 미실시·제외 항목은 실제 PASS로 기록하지 않고 확인 범위와 이유를 함께 쓴다.
4. 임시 데이터나 예약을 만든 경우 서버 데이터와 기기 예약을 정리하고, 정리 상태를 직접 확인해 기록한다.
5. 전체 체크리스트 완료 조건을 근거와 대조하고, 남은 판정이나 불확실성은 확인 질문으로 남긴다. 사람의 판단이 필요한 조건은 추정으로 채우지 않는다.

## done_when 확인 방법

기준 완료 조건은 `전체 체크리스트 항목 통과`다. 체크리스트의 각 영역에 연결된 근거와 상태를 확인하고, 실측하지 않은 항목은 실측 PASS와 구별한다. 완료 판정은 이번 시험의 결과와 명시적 사용자 수용의 범위를 함께 대조해 기록한다.

## 현재 확인 기록 (2026-10-12)

- 사용자는 알람 검증은 넘기고 실사용 중 문제가 있으면 고치겠다고 했으며, 업데이트 중 이상이 없었고 P7.4도 통과한다고 명시했다. 이에 따라 미실시 항목의 사용자 수용을 완료 근거로 기록한다. 이는 해당 항목들을 실제로 시험해 PASS한 것으로 뜻하지 않는다.
- 전체 검사 1.63.5 결과는 Jest 93개 묶음·557개 테스트, Android debug build, 푸시 테스트 13건 통과로 기록돼 있다. 소스 변경 없이 해당 근거를 재사용했다.
- 딸 폰에서 1.63.5/185의 화면 없는 주기 동기화와 위젯 반영을 확인했다. 임시 할 일·시간표 데이터 정리 뒤 재연결 및 동기화 종료 상태에서 활성 `RollingNotificationReceiver`와 `AlarmReceiver` 예약이 0건임을 직접 확인했고, 앱의 오늘 할 일도 비어 있었다.
- P7.2와 P3.9 선행 작업은 완료 상태다. 구체적인 항목별 근거와 제한은 [최종 회귀 근거](../regression-verification-2026-10-12.md), [체크리스트](../test-checklist.md), [실기기 기록](../device-verification-2026-10-12.md)을 참조한다.
- 실제 알림 탭 6가지 조합과 알람 소리 재시험은 이번에 수행하지 않았다. 자동 검사·기존 기록·사용자 수용을 실제 새 실측 결과와 혼동하지 않도록 기록했다.
- 요구사항에 없는 추가 확인 질문은 현재 남아 있지 않다. 이 문서는 완료 조건의 근거 정리이며 최종 백로그 상태 전이는 메인 실행이 판단한다.

## 최종 완료 기록

과거 summary·done_when의 ‘전체 체크리스트 항목 통과’ 문구만으로 전체 실측 PASS를 해석하지 않는다. 현재 계약은 항목별 기존 검증·실측·미실시 범위 기록과 2026-10-12 사용자의 업데이트 이상 없음·P7.4 패스 수용을 함께 적용한 완료다. 운영 규칙상 백로그 변경은 add/set-status만 허용되므로 완료 항목의 과거 메타데이터를 직접 편집하지 않고, 최종 evidence·log와 이 문서에 현재 계약을 명시한다.

등록 재리뷰 두 역할 정상 종료 후 사용자 수용과 기존 실제·자동 검증을 구분해 P7.4를 done으로 기록했다. 미실시 6조합·알람 재시험은 실측 PASS가 아니며 2026-10-12 사용자 패스 결정에 따른 완료다. 문서 선택지와 미래 예약 관찰 순서의 Medium도 정정했다.
