# P6.4 — 로그인 · 역할 분기

## 기준

- 백로그 sha256: 5ba7f3702bc0778bc880e9556be168d370f51896c54b16f622c5b8c9adddfbe1
- 백로그 bytes: 확인 필요
- 개발 상태: in_review
- 문서화 상태: 작성됨

## 작업 목적
서버 로그인과 parent/child 역할별 화면 분기를 구현하여, 아빠 폰과 딸 폰에서 다른 화면을 볼 수 있게 한다.

## 쉬운 설명
로그인하지 않으면 지금처럼 이 폰에만 저장하며 쓴다. 아빠는 PIN 뒤 관리자 설정에서 로그인해 '아빠 화면'을 본다. 딸은 아이 화면(오늘·시간표·보석)을 그대로 본다.

## 필요한 입력
기준 백로그 P6.4의 요구사항과 사용자 결정 내용:
- 로컬 모드 유지: 로그인하지 않으면 지금처럼 이 폰에만 저장하며 쓴다.
- 로그인 위치: PIN 뒤 관리자 '기타 → 서버 연결'에서 한다.
- 가족 등록: 앱에 가족 만들기 화면 없이 CLI로 한 번 등록한다.
- 아빠 실제 편집: P6.8에서 구현한다.

## 결과물
서버 로그인과 역할별 화면 분기가 정확히 동작함. 로그인 정보는 expo-sqlite의 localStorage에 저장되어 앱을 다시 켜도 유지됨.

## 선행 작업
deps: P6.3(RLS 정책, done). 부모는 P6(서버 연동 · 아빠 원격 관리)이다.

## 수행 순서
1. 범위와 입력을 확인한다.
2. 선행 작업 결과를 준비한다.
3. 서버 로그인, 역할 확인, 화면 분기를 구현하고 결과를 기록한다.
4. done_when을 확인한다.
5. 개발 완료와 문서화 완료를 구분해 기록한다.

## done_when 확인 방법
done_when 원문은 "역할별 화면 분기가 정확히 동작함"이다. 같은 APK에서 로그인한 계정의 역할로만 화면이 나뉘므로, 딸 폰 한 대에서 딸·아빠 계정을 바꿔 가며 두 역할을 모두 확인했다. 아빠 실제 폰 확인은 아빠 화면을 만드는 P6.8에서 한다.

- `src/server/account.ts`: 로그인/로그아웃, 역할 확인(parent/child), 캐시 읽기·쓰기

## 리뷰 반영 (critical-reviewer SHA 5ba7f370, 1.48.2)
- H1: 토큰이 만료됐는데 인터넷이 없으면 `getSession()`이 세션 없음과 오류를 함께 돌려줘(auth-js `GoTrueClient` 확인) 아빠 폰이 아이 화면이 되던 문제 → 마지막으로 확인한 계정(사용자·이메일·역할)을 유지. 인터넷이 돌아와 토큰이 갱신되면(`TOKEN_REFRESHED`) 다시 확인하고, `SIGNED_OUT`이면 로컬 모드로 바꾼다.
- M1: 오프라인 + 토큰 만료에서 로그아웃이 실패하면 supabase-js 기본 저장 키(`sb-<프로젝트>-auth-token`)를 직접 지워 다음 시작 때 다시 로그인되지 않게 함.
- M2: 사용자가 직접 로그인·로그아웃한 뒤 늦게 끝난 자동 확인 결과는 버림(조작 횟수 비교).
- M3: 확인 결과 해당 없음. 백업 규칙(expo-secure-store가 넣는 `secure_store_backup_rules`·`secure_store_data_extraction_rules`)이 sharedpref만 포함해, 로그인 정보가 든 SQLite 데이터베이스는 클라우드 백업·기기 이전에 들어가지 않는다.
- Q2: 가족 등록 SQL의 실제 이메일을 자리표시자로 바꿈.
- Q5(아빠 계정 기기의 아이용 로컬 알림): 아빠 폰에는 로컬 시간표가 없으면 예약할 알림이 없다. 아빠 화면을 만드는 P6.8에서 함께 정한다.
