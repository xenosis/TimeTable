# P2.16 — 메모 저장: 시간표 항목에 짧은 메모 컬럼 추가

## 기준 입력

- 백로그 schema version: `1.1`
- 백로그 SHA-256: 최신 상태 기준
- 기준 항목: `P2.16`
- 백로그 상태: `todo`
- 우선순위: P3 (핵심 기능 아님)
- 부모 작업: 없음 (최상위)
- 선행 작업: P2.11 (결정: 시간표 항목 부가 메모 지원 여부)

## 목적

시간표 항목에 짧은 한 줄 메모를 저장할 수 있도록 DB 스키마에 memo 컬럼을 추가하고, 저장소 계층에서 메모를 지원한다. 기존 항목은 빈 메모로 유지된다. 예: "일루스터 16:45차", "선생님 데리러"

## 쉬운 설명

시간표 항목(예: "수학 학원 14:00")에 추가 정보를 붙일 수 있도록 한다. "과제 테스트", "엄마가 데리러옴" 같은 짧은 메모를 저장했다가 화면에 표시할 수 있게 한다.

## 필요한 입력

- P2.11 사용자 결정: 메모 필드 추가 (확정됨)
- 기존 `timetable_items` 테이블 스키마
- 현재 마이그레이션 버전 (V8 기준)
- 기존 항목 CRUD 저장소 함수

## 결과물

### 데이터베이스 마이그레이션
- 새 마이그레이션(V10 이후, V9는 시간표 세트가 사용함): `timetable_items`에 `memo TEXT DEFAULT ''` 컬럼 추가
- 기존 항목은 모두 빈 메모(`''`)로 유지
- 마이그레이션은 일회성으로 수행되고 재실행되지 않음

### 저장소 계층
- `src/db/timetableRepository.ts` 수정
  - `createTimetableItem`: 메모 파라미터 추가 (선택사항, 기본값: `''`)
  - `updateTimetableItem`: 메모 수정 지원
  - `getEditableTimetableItems`·`getTimetableItemsForWeekday`: 메모 조회
  - `getTimetableItemsForWeekday`: 메모 포함 조회
  - `copyTimetableWeekday`: 메모도 함께 복사

### 타입 정의
- `src/db/types.ts` 수정
  - `TimetableItem`·`TimetableItemInput`(src/db/types.ts, timetableRepository.ts)에 `memo` 필드 추가

### 단위 테스트
- `__tests__/database.test.ts` 또는 `__tests__/timetable-sets.test.ts` 추가
  - 메모 컬럼 마이그레이션 테스트
  - 항목 저장 시 메모 저장 테스트
  - 항목 수정 시 메모 수정 테스트
  - 항목 조회 시 메모 포함 테스트
  - 요일 복사 시 메모 복사 테스트
  - 기존 데이터 마이그레이션 뒤 빈 메모 확인

## 완료 기준

완료 조건: memo 컬럼 마이그레이션이 기존 데이터를 보존하며 적용되고, 항목 저장·수정·조회·요일 복사에서 메모가 유지됨. 단위 테스트 통과, npm run check 통과

| 조건 | 확인 방법 |
|---|---|
| 새 마이그레이션(V10 이후, V9는 시간표 세트가 사용함) 존재 | `src/db/migrations.ts`에 테이블 수정 DDL이 포함되었는지 확인 |
| 메모 저장 | `createTimetableItem(title, ..., memo?)` 호출해 메모가 저장되는지 테스트 |
| 메모 수정 | `updateTimetableItem(id, title, ..., memo)` 호출해 메모가 변경되는지 테스트 |
| 메모 조회 | `getEditableTimetableItemById(id)` 결과에 메모가 포함되는지 테스트 |
| 요일 복사 포함 | `copyTimetableWeekday(...)` 뒤 복사된 항목의 메모도 복사되었는지 테스트 |
| 빈 메모 처리 | 메모 미입력 시 기본값(`''`) 또는 null 처리가 일관되는지 확인 |
| 단위 테스트 | 모든 테스트가 npm test에서 통과 |
| npm run check | 전체 검사 통과 (지침, 코드 길이, lint, typecheck, Jest, build) |

## 수행 순서

1. P2.11 완료 확인 (사용자 결정: 메모 추가)
2. 현재 마이그레이션 버전과 `timetable_items` 스키마 확인
3. 새 마이그레이션(V10 이후, V9는 시간표 세트가 사용함) 작성 (`ALTER TABLE timetable_items ADD COLUMN memo TEXT DEFAULT ''`)
4. `src/db/timetableRepository.ts` 저장소 함수 수정
   - `createTimetableItem`, `updateTimetableItem`, `getEditableTimetableItems`·`getTimetableItemsForWeekday` 등에 메모 파라미터 추가
5. `src/db/types.ts` 타입에 `memo: string` 필드 추가
6. 단위 테스트 작성
   - 마이그레이션 테스트: 기존 데이터가 빈 메모로 변환됨
   - 저장·수정·조회 테스트
   - 요일 복사 테스트
7. `npm run check` 실행해 모든 검사 통과 확인
8. 실기기 검증 (P2.17 입력 폼 이후)

## 참고

- 메모는 한 줄 텍스트로 제한 (개행 불가, 길이 제한은 사용자 결정 필요)
- 빈 메모 처리: 기본값 `''` 또는 `null` (후속 P2.17에서 결정)
- 서버 스키마(P6.2)에도 같은 컬럼이 필요하므로 그 항목에 메모를 남김
- 후속 작업: P2.17 (메모 입력 UI), P2.18 (메모 표시)

## 확인 질문

1. 메모 최대 길이는 몇 글자인가?
   - 예: 50글자, 100글자, 무제한?

2. 빈 메모를 기본값 `''` (빈 문자열)으로 할지 `null`로 할지?
   - 빈 문자열: 항상 문자열 타입 보장, 비교 간편
   - null: 메모 유무 명시적 표현

3. 마이그레이션 후 기존 항목의 메모를 모두 빈 값으로 두는 것이 맞는가?
   - 여기서는 마이그레이션만 수행하고, 기존 데이터 채우기는 P2.17에서?
