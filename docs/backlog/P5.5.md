# P5.5 — 탭하면 앱 이동

## 기준

- 백로그 schema version: `1.1`
- 기준 CLI 조회 스냅샷 SHA-256: `6d2acffdc77fd64f6f044212c54c4ebb459a9530ab8ae03f63a78dc8e1295ac1`
- 기준 레코드 상태: `in_review`
- 백로그 ID: `P5.5`
- 백로그 `deps`: `P5.2`
- 백로그 `done_when`: `위젯 탭 시 해당 화면으로 이동함`

이 문서는 위 기준 스냅샷의 P5.5 레코드만 설명한다. 원본 `backlog.json`은 수정하지 않는다.

## 작업 목적

홈 화면 위젯의 현재 일정 영역을 탭하면 앱의 `MainActivity`를 열고, 앱이 지정한 화면으로 이동하게 한다.

## 쉬운 설명

위젯에서 일정 문구를 눌렀을 때 앱 아이콘을 다시 찾아 누르지 않고 앱이 바로 열려야 한다. 이 연결에는 `kidtimetable://` 딥링크를 사용한다.

## 필요한 입력

- 기준 백로그 P5.5 레코드와 `deps`에 기록된 P5.2 완료 결과
- 위젯 레이아웃의 현재 일정 뷰 ID `widget_current`
- 앱의 `MainActivity`와 `kidtimetable://` 딥링크 intent-filter
- 위젯 탭 동작을 확인할 수 있는 개발 빌드와 Android 실기기

백로그에 없는 특정 화면 경로, 탭 후 화면 전환 정책, 탭 응답 시간 기준은 임의로 정하지 않는다.

## 결과물

- `widget_current`에 `kidtimetable://` URI로 `MainActivity`를 여는 immutable `PendingIntent`
- 위젯 탭과 앱의 딥링크 수신 경로가 연결된 Android 구현
- 자동 검사 결과와 실기기 탭 확인 기록

## 선행 작업

- P5.2 위젯 데이터 브릿지 완료 결과
- Android 위젯의 `widget_current` 뷰와 `MainActivity` 등록 상태

## 구현 요약

`TodayWidgetProvider`가 위젯을 갱신할 때 `widget_current`에 `PendingIntent.getActivity`를 연결한다. intent는 `Intent.ACTION_VIEW`와 `Uri.parse("kidtimetable://")`를 사용하고, `MainActivity`를 명시적으로 대상으로 지정한다. `FLAG_ACTIVITY_CLEAR_TOP`과 `FLAG_ACTIVITY_SINGLE_TOP`으로 기존 앱 인스턴스가 있으면 중복 화면 생성을 줄인다. Android 12 이상에서 사용할 수 있도록 `FLAG_IMMUTABLE`을 포함한다.

앱 manifest에는 `kidtimetable` scheme을 처리하는 `MainActivity` intent-filter가 있어야 한다. 이 작업은 위젯 탭의 앱 진입 연결을 확인하며, 딥링크 이후 앱 내부의 추가 화면 선택은 백로그에 정의된 범위를 넘지 않는다.

## 수행 순서

1. 기준 schema version, SHA-256, P5.5의 `deps`와 `done_when`을 확인한다.
2. P5.2 위젯 데이터 브릿지와 `widget_current` 뷰가 준비되어 있는지 확인한다.
3. `widget_current` 갱신 시 `kidtimetable://`를 대상으로 하는 immutable `PendingIntent`가 연결되어 있는지 확인한다.
4. `MainActivity`가 해당 scheme을 받을 수 있도록 manifest intent-filter가 연결되어 있는지 확인한다.
5. `npm run check` 전체 검사를 실행하고 결과를 기록한다.
6. 등록된 `critical-reviewer`와 `backlog-explainer`의 검토 결과를 확인한다.
7. 아래 실기기 수동 테스트를 수행하고 관찰 결과를 기록한다.
8. 구현, 자동 검사, 리뷰, 실기기 확인, 문서화를 각각 구분해 백로그 상태와 문서에 반영한다.

## done_when 확인 방법

`위젯 탭 시 해당 화면으로 이동함`을 다음 근거와 대조한다.

- 구현 근거: `widget_current`에 `PendingIntent.getActivity`가 연결되고, intent의 URI가 `kidtimetable://`이며 대상이 `MainActivity`인지 확인한다.
- manifest 근거: `MainActivity`가 `kidtimetable` scheme의 `VIEW` intent를 받을 수 있는지 확인한다.
- 자동 검증 근거: `npm run check`가 지침 동기화, 코드 길이, lint, typecheck, 테스트, Android debug build를 모두 통과해야 한다.
- 사람 확인 근거: 실기기에서 위젯의 현재 일정 영역을 탭했을 때 앱이 열리고, 앱 아이콘이나 최근 앱 목록을 별도로 선택하지 않아도 앱 화면이 표시되는지 확인한다.

## 사용자 실기기 수동 테스트

테스트 전에 개발 빌드를 설치하고 홈 화면에 TimeTable 위젯을 배치한다. 각 항목에서 기기 모델·Android 버전, 테스트 시각, 앱이 열리기까지의 관찰, 결과를 기록한다.

### 1. 현재 일정 영역 탭

1. 위젯에 일정 문구가 표시되는 상태에서 `widget_current`에 해당하는 현재 일정 영역을 누른다.
2. 앱이 자동으로 열리는지 확인한다.
3. 앱 아이콘을 직접 누르거나 최근 앱 목록에서 앱을 선택하지 않고도 앱 화면이 표시되는지 기록한다.

판정 기준: 탭 한 번으로 `MainActivity`가 열리면 통과다. 아무 반응이 없거나 위젯만 선택되고 앱이 열리지 않으면 실패다.

### 2. 앱이 이미 실행 중인 상태

1. 앱을 먼저 열어 둔 상태에서 홈 화면으로 이동한다.
2. 위젯의 현재 일정 영역을 다시 탭한다.
3. 앱이 중복으로 여러 개 열리지 않고 기존 앱 화면으로 돌아오는지 확인한다.

판정 기준: 앱이 정상적으로 foreground로 돌아오면 통과다. 탭할 때마다 중복 화면이나 오류 화면이 나타나면 관찰 내용을 기록하고 실패로 남긴다.

### 3. 앱이 백그라운드 또는 최근 앱에서 제거된 상태

1. 앱을 백그라운드로 보낸 뒤 위젯이 보이는 홈 화면으로 이동한다.
2. 필요하면 최근 앱 목록에서 TimeTable을 제거한다.
3. 위젯의 현재 일정 영역을 탭하고 앱이 다시 시작되는지 확인한다.

판정 기준: 백그라운드 상태와 최근 앱 제거 상태 모두에서 탭으로 앱이 열리면 통과다. 한 상태에서만 열리는 경우 상태별 결과를 따로 기록한다.

### 4. 다른 위젯 영역과 구분

1. 현재 일정 영역을 탭하기 전 위젯의 표시 문구와 위치를 기록한다.
2. 현재 일정 영역을 정확히 탭한다. 위젯 바깥이나 다른 컨트롤을 탭한 결과는 P5.5 판정에 사용하지 않는다.
3. 앱이 열렸는지와 오류 메시지 유무를 기록한다.

판정 기준: `widget_current` 탭에 대해 앱 진입 결과가 재현되면 통과다. 백로그에 지정되지 않은 다른 위젯 영역의 동작은 별도 요구사항으로 확장하지 않는다.

## 확인 질문

- 백로그에는 탭 후 앱에서 표시할 정확한 내부 화면 경로가 정의되어 있지 않다. 실기기에서 현재 `MainActivity` 진입 결과를 확인한 뒤, 특정 화면으로 바로 이동해야 한다면 별도 요구사항으로 결정해야 한다.
- 백로그에는 탭 응답 시간의 허용 기준이 없다. 실제 관찰된 시간을 기록하되, 별도 제품 기준을 임의로 만들지 않는다.
