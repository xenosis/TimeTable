## 작업 목적 (취소됨)

원래는 재부팅 후 사용자가 화면 잠금을 풀기 전에도 롤링 알람(timetable, tasks owner)이 예약되도록 구현하려 했습니다. 그러나 아이가 사용하는 앱이고 재부팅 빈도가 낮을 것으로 예상되어 사용자가 이 기능을 취소 결정했습니다.

---

## 쉬운 설명

휴대폰을 재부팅하면 시간표와 할 일 알람이 처음부터 다시 예약됩니다. 그런데 지금은 사용자가 화면 잠금을 풀 때까지 기다렸다가 그 후에 예약이 됩니다. 이 작업은 원래 "잠금을 풀기 전에도 미리 예약해두기"를 구현하려 했지만, 지금은 하지 않기로 했습니다.

---

## 발견된 문제 (P3.4 검증 결과)

P3.4 실기기 검증(2026-10-01)에서 다음을 확인했습니다:

1. **현재 동작**: 예약 복구(`restoreAfterBoot`)는 `WidgetBootReceiver`의 `BOOT_COMPLETED`에서만 실행됨
2. **기술적 제약**:
   - Android `LOCKED_BOOT_COMPLETED` 및 `directBootAware` 설정 없음
   - 세대 저장소: 기본(CE) SharedPreferences 사용
3. **결과**: 사용자가 화면 잠금을 풀기 전에는 예약 복구가 시작되지 않음
4. **실기기 확인**: 딸 폰에서 잠금 해제 직후(00:03:12)에야 프로세스가 시작되고 예약이 복구됨

## 원래 구현 예정 내용 (미시행)

만약 이 기능을 구현했다면:

1. AndroidManifest.xml에 `LOCKED_BOOT_COMPLETED` 권한 추가
2. `WidgetBootReceiver` 수정 또는 새로운 receiver 추가
3. 세대 저장소를 `directBootAware`로 마크하고 기기 보호(DE) SharedPreferences로 이전
4. 기존 세대 데이터 마이그레이션
5. 단위 테스트 추가

---

## 현재 구현 상태 (as-is)

**재부팅 후 동작:**
1. 휴대폰 전원 재부팅
2. 사용자가 화면 잠금 해제
3. `BOOT_COMPLETED` 브로드캐스트 수신
4. `WidgetBootReceiver` 실행
5. `restoreAfterBoot()` 호출
6. 미래 롤링 알람 예약 복구

**제약 사항:**
- 잠금 해제 전에는 알람이 울리지 않을 수 있음
- 밤에 재부팅되고 아침까지 잠금을 풀지 않으면 그 사이 알람 손실 가능

## done_when (해당 없음 — 취소됨)

원래 done_when:
> 재부팅 뒤 잠금을 풀기 전에도 미래 롤링 알람(timetable·tasks 두 owner)이 dumpsys alarm에 복구됨. 딸 폰 실기기에서 알람 항목을 만든 뒤 재부팅하고 잠금을 풀지 않은 채 dumpsys alarm으로 확인. 세대 저장소를 DE로 옮기는 경우 기존 저장 세대 이전(마이그레이션)과 단위 테스트, npm run check 통과

## 사용자 취소 결정 (2026-10-01)

**결정**: 재부팅 뒤 잠금 해제 전 알람 복구는 하지 않음  
**근거**: 
- 아이가 사용하는 앱이므로 재부팅 빈도가 낮을 것으로 예상
- 학원 시간 변경 대응이 핵심 목적
- 현재 동작(잠금 해제 후 복구)도 실제 사용에 충분

**문서화**: docs/build-commands.md에서 현재 동작(재부팅 후 첫 잠금 해제 후 복구)을 안내함

## 참고: 어떤 상황에서 영향을 받을 수 있나

- 휴대폰이 밤중에 재부팅되는 경우 (배터리 방전, OTA 업데이트 등)
