# P6.17 — 변경 푸시 외부 설정과 실기기 수신 확인

## 기준 입력

- Schema version: `1.1`
- SHA-256: `f5689bc9b966bcbd178ac4b81e96b667cf613783e0d83548473b8a1acc51daca`
- 입력 크기: `486598` bytes
- 기준 시각: `2026-10-10T17:10:48.949Z`
- 기준 상태: `in_progress`

## 목적

Firebase·Expo·FCM 및 서버 발송 작업자를 운영 환경에 연결하고, 아빠가 저장한 시간표 변경이 딸 폰에 보이며 알림을 눌렀을 때 최신 내용이 적용되는지 실제 기기에서 확인한다.

## 쉬운 설명

아빠가 시간표를 바꾸면 딸 폰에 알림이 오고, 알림을 눌렀을 때 바뀐 시간표가 바로 보이도록 푸시 설정과 서버 처리를 마무리하는 작업이다. 코드를 만들고 서버가 요청을 받았다는 것만으로는 완료가 아니다. 두 실제 기기의 전체 흐름을 확인해야 한다.

## 필요한 입력

- Firebase Android 앱 등록과 `google-services.json`, Expo 프로젝트의 FCM V1 자격 설정
- 운영 푸시 마이그레이션 적용 및 `tt-notify-change` 함수 배포 근거
- 작업자 배포·호출에 필요한 사용자 승인 및 인증 설정. 기준 기록은 기본 JWT 검사와 `TT_PUSH_WORKER_SECRET` 헤더를 유지하는 방식을 명시한다.
- 아빠 계정 로그인 기기와 딸 계정 로그인 기기, 딸 폰에 설치된 확인 대상 앱
- 서버 시간표 변경을 만들고 알림 수신·탭 후 반영 결과를 직접 관찰할 수 있는 절차

## 결과물

- Firebase·Expo·FCM 외부 설정과 운영 적용 상태가 기록되어 있음
- `tt-push-worker`가 기본 JWT 검사 및 서버 비밀 헤더를 유지한 채 배포되고 호출 인증이 확인됨
- 변경 대기열의 자동 재시도 실행이 연결됨
- 아빠의 서버 저장부터 딸 폰 알림 표시, 알림 탭 후 최신 내용 적용까지 실기기 확인 기록

## 선행 작업

- 부모 작업: P6.9 변경 푸시
- 의존 작업: P6.6 동기화
- P6.17은 P6.9의 외부 설정·운영 작업자·실기기 전체 경로를 마무리한다.

## 수행 순서

1. `docs/push-notification-setup.md`의 실제 설정과 운영 배포 기록을 확인한다.
2. 기본 JWT 검사를 끄거나 우회하지 않고 `tt-push-worker`를 배포한다. 서버 비밀 헤더 인증을 포함해 호출 인증을 검증한다.
3. 작업자의 자동 재시도 실행 연결 및 실패 후 재처리 흐름을 확인한다.
4. 아빠 계정 기기에서 시간표를 저장하고 딸 폰에 보이는 알림이 도착하는지 확인한다.
5. 딸 폰 앱을 정상 종료한 상태와 프로세스를 종료한 상태에서 알림을 탭하고 최신 시간표 내용이 반영되는지 확인한다.
6. 결과와 남은 사항을 문서에 기록하고, 완료 조건 전체가 충족됐는지 대조한다.

## 완료 조건 및 확인 방법

완료 조건: 외부 설정 및 배포가 승인·완료되고, 서버 시간표 변경 후 딸 폰에서 보이는 알림 도착과 탭 후 최신 내용 적용을 직접 확인한다.

- 외부 설정과 서버 배포의 실제 상태·승인 기록을 확인한다.
- 아빠 기기에서 저장한 한 건에 대해 딸 폰 알림 표시를 직접 확인한다.
- 알림을 탭한 뒤 서버 변경에 해당하는 최신 내용이 적용됐는지 화면에서 확인한다.
- 작업자 배포·인증 검증·자동 실행 연결을 별도로 확인한다. 이들이 완료 조건 문장에 구체적으로 적혀 있지는 않지만 현재 진행 기록상 남은 작업으로 보고되므로, P6.17 완료 판단 전 범위 포함 여부를 확인한다.

## 현재 확인 기록 (기준 입력 기준)

- 외부 설정은 완료 기록이 있다: Firebase `routineplanner-e9bbd`에 `com.chaea.timetable` 등록 및 `google-services.json` 추가, Expo FCM V1 자격 업로드, 푸시 마이그레이션 2개 운영 적용·검증, `tt-notify-change` 배포.
- 1.62.12 두 실제 기기에서 아빠 저장→딸 알림 도착과 앱 정상 종료 및 프로세스 종료 후 알림 탭→최신 내용 반영을 확인했다고 기록되어 있다.
- 현재 상태는 `in_progress`. 서버 재시도 작업자 배포·인증 검증·자동 실행 연결이 남아 있다고 최신 로그에 명시되어 있다.
- 백로그의 `gate`에는 아빠 저장부터 최신 내용 확인까지 필요하다고 적혀 있지만, 같은 입력의 최신 로그에는 두 기기에서 이 확인을 마쳤다고 적혀 있다. 아래 확인 질문을 정리하기 전까지 두 기록의 불일치를 완료 판정 근거로 단정하지 않는다.

## 확인 질문

- 완료 조건의 “외부 설정 및 배포”에 `tt-push-worker`의 배포·인증 검증·자동 재시도 실행 연결이 모두 포함되는가? 최신 로그는 이를 남은 일로 적었으나 완료 조건 문장에는 작업자가 직접 언급되지 않는다.
- `gate`가 요구하는 아빠 저장→딸 알림 도착·탭 후 최신 내용 확인은 최신 로그의 1.62.12 실기기 기록으로 해소된 것으로 처리해도 되는가?
