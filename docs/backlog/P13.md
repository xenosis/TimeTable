# P13 — 자동 보석 지급 중단과 아이의 보석 수 수정

## 기준 입력 및 상태

- schema version: `1.1`
- 기준 백로그 SHA-256: `1efc75d2e5a3536986545592fdc55ce541f68e04b24e3e290aacd03713655a06`
- 백로그 상태: `in_review` (고정 CLI 입력)
- 담당: `codex`; 선행 작업: 없음 (`deps: []`)
- 기준 `where`: `src/db/rewardRepository.ts`, `src/components/StickerBoard.tsx`
- 관련 정책: [`docs/tasks.md` P13 결정](../tasks.md), [P4.13](P4.13.md)

## 목적

완료·취소나 주간/월간 완료로 실제 보석 장부가 자동 증감하지 않게 하고, 아이가 실물 보유량에 맞춰 작은 보석과 큰 보석 수를 직접 저장하게 한다.

## 쉬운 설명

앱은 실물 보석을 자동으로 더하거나 빼지 않는다. 아이가 실제 가진 수를 직접 적으며, 앱을 다시 열어도 유지된다. 할 일을 마쳤을 때의 칭찬과 연속 기록, 실물 보석을 받을 자격과 요청·지급 절차는 계속 쓸 수 있다. 이 절차들은 장부 수량을 바꾸지 않는다.

## 필요한 입력

- 아이가 PIN 없이 일반·큰 보석의 정수 수량(0~99,999)을 직접 입력한다.
- `gemCountRepository`만 장부 수량을 변경한다. 저장은 기존 잔액을 다시 계산하거나 과거 원장을 지우지 않고 입력한 절대 수량과 기존 수량의 차액을 기록한다.
- 여러 수량 저장이 겹치면 마지막 저장의 절대 수량이 우선한다.
- 보석 자격·요청·실물 지급 상태는 P4.13의 절차를 따른다. 어느 단계도 보석 장부를 자동 증감하지 않는다.
- 새 할 일은 생성일부터 완료·연속 계산에 반영하며, 큰 보석 5개 환산은 캐릭터 그림 변화에만 사용한다.

## 결과물

- 체크/취소·주간/월간 완료 및 보상 목표가 장부를 자동 변경하지 않는 동작
- 기존 수량·원장 보존을 포함한 V12 이전 처리 근거
- 수동 절대 수량 저장, 앱 재시작 유지, 취소·오류·저장 중 닫기 예외 흐름 근거

## 선행 작업

기준 CLI 입력의 `deps`는 비어 있다. P4.13은 실물 보석 자격·요청·지급 정책의 선행 근거다. 기존 완료 보석 원장을 보존하는 V12 이전은 P13에서 확인할 필수 증거이며, 이를 별도 선행 작업 상태로 바꾸지는 않는다. P12 캐릭터 테마는 별도 작업이다.

## 수행 순서

1. 자동 수량 변경 경로와 기존 장부·원장을 확인한다.
2. P4.13의 V12 이전이 과거 완료 보석을 조정 행으로 옮기고 총 보유량을 보존하는지, 이후 완료 기록을 취소해도 장부가 유지되는지 확인한다.
3. 체크·취소·주간/월간 완료와 보상 목표 및 자격·요청·지급이 장부를 자동 변경하지 않는지 테스트한다.
4. 직접 입력한 두 절대 수량의 원장 차액 저장, 재시작 유지, 여러 저장이 겹칠 때 마지막 절대값 우선 동작을 확인한다.
5. 입력 화면의 취소, 빈/잘못된 입력, 저장 중 닫기 차단, 저장 실패 재시도를 확인한다. 별도 실제 UI 키보드 조작은 검증 여부를 분리해 기록한다.
6. 검증용 값을 원래 값으로 복원하고 원본 데이터 일치 여부를 확인한 뒤 전체 검사와 dispatcher 리뷰 결과를 기록한다.

## done_when 확인 방법

백로그 원문 조건:

> 체크·취소·주간·월간 완료로 보유량이 변하지 않음·기존 보유량 보존·모든 자동 지급 중단·아이가 수를 수정하고 재시작 뒤 유지·동시 지급 보존·검사와 리뷰 확인

이 문서에서 “자동 지급 중단”은 자동 보석 장부 증감 중단을 뜻한다. P4.13의 실물 자격 생성·요청·지급 상태는 유지되며 장부와 독립적이다. “동시 지급 보존”은 수량 저장과 자격/요청/지급 처리를 혼동하지 않고, 겹친 수량 저장은 마지막 절대 입력값을 보존한다는 기준으로 확인한다. 기존 완료 보석 원장은 V12 이전 뒤 총량이 보존되고 취소로 감소하지 않아야 한다.

수량과 원장 차액, 재시작 후 값, 입력 컴포넌트 예외 흐름, 검사 및 같은 입력의 리뷰를 각각 확인한다. 실제 UI 키보드 흐름이 아직 확인되지 않았다면 검사 통과와 분리해 미검증으로 남긴다. 아래에 적힌 결과만으로 작업 상태를 `done`으로 바꾸지 않는다.

- `__tests__/reward-repository.test.ts`의 관련 테스트는 반복 완료·한 달 완료·취소 뒤 수량 불변 및 자동 reward 행 부재, 과거 지급 원장 보존, 0 포함 수동 입력, 잘못된 값 무기록, 한쪽 insert 실패 시 양쪽 rollback, 체크/위젯/여러 수량 저장 직렬화(최종 절대값 3/1), DB 재개방 후 수량 유지를 확인한다.
- `__tests__/gem-count-editor.test.tsx`의 네 컴포넌트 테스트는 취소 시 장부 쓰기/저장 콜백 없음, 빈 입력 안내와 무저장, 저장 중 입력·취소·Android 뒤로 닫기 차단, 저장 실패 시 입력 보존 및 재시도를 확인한다. PC 에뮬레이터의 실제 키보드 첫 탭 동작은 별도 수동 근거 아래에 적었으며, 컴포넌트 테스트가 그 화면 확인을 대체하지 않는다.
