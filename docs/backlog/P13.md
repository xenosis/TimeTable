## 목적

할 일 체크 및 주간·월간 완료를 보석 자동 지급과 분리한다. 앱은 완료와 칭찬 흐름을 유지하고, 아이가 일반 보석과 큰 보석의 실제 보유량을 직접 입력해 기록한다. 이미 기록된 수량과 원장 내역을 보존한다.

## 쉬운 설명

보석은 앱이 숙제를 했다고 자동으로 주는 보상이 아니라, 아이가 실제로 가진 보석 개수를 적어 두는 장부가 된다. 아이는 PIN 없이 두 종류의 개수를 맞출 수 있다. 할 일을 체크하거나 취소해도 개수는 바뀌지 않고, 칭찬과 완료 기록은 계속 동작한다.

## 필요한 입력

- 사용자 정책: 자동 지급 중단, 기존 보유량 보존, 아이의 수동 수량 조정.
- 변경 대상: `src/db/rewardRepository.ts`, `src/components/StickerBoard.tsx`.
- 검증 대상: 체크·취소, 주간·월간 완료, 모든 자동 지급 경로, 기존 잔액과 원장, 사용자 수동 조정 및 동시 변경.
- 하위 작업이나 외부 입력은 기준 백로그에 지정되어 있지 않다.

## 결과물

- 완료·보상 계산 경로에서 자동 보석 지급을 막고 기존 잔액을 보존하는 구현.
- PIN을 요구하지 않고 일반·큰 보석 수량을 수정하는 아이용 화면. 입력은 0~99,999 정수로 제한한다.
- 수동 조정액을 원장에 기록하며 앱 재시작 후에도 입력 수량을 유지한다.
- 자동 변경과 수동 수정이 겹쳐도 업데이트가 유실되지 않는 테스트·검증 기록.

## 선행 작업

직접 선행 작업은 없다(`deps: []`). 변경 전에 체크/취소 및 주간·월간 완료에서 잔액을 바꾸는 호출 경로와 기존 원장 데이터를 확인한다. P12 캐릭터 테마는 이 작업 범위에서 제외한다.

## 수행 순서

1. 기존 잔액·원장과 할 일 완료, 주간/월간 보상 및 기타 자동 지급 호출 경로를 확인한다.
2. 모든 자동 지급을 중단하되 완료 이력, 칭찬, 보상 목표 등 명시된 유지 기능을 보존한다.
3. 아이가 PIN 없이 일반·큰 보석 수를 입력하고 저장할 수 있도록 한다. 기존 수량과 새 수량의 차액을 원장에 반영한다.
4. 기존 보유량·과거 원장 보존, 체크/취소 및 주간·월간 완료 전후 불변, 수동 수정과 앱 재시작 뒤 지속을 확인한다.
5. 동시 지급·수정 상황의 보존을 검증하고 전체 검사와 등록 리뷰 결과를 기록한다.

## done_when 확인 방법

기준 완료 조건: `체크·취소·주간·월간 완료로 보유량이 변하지 않음·기존 보유량 보존·모든 자동 지급 중단·아이가 수를 수정하고 재시작 뒤 유지·동시 지급 보존·검사와 리뷰 확인`.

- 체크, 취소, 주간 완료, 월간 완료 각각 전후의 일반·큰 보석 잔액을 비교한다.
- 기존 수량과 원장 이력이 그대로 남고, 각 자동 지급 경로가 차단되는지 확인한다.
- 아이가 두 수량을 변경한 뒤 차액 원장이 남고, 앱 재시작 후 값이 유지되는지 확인한다.
- 수동 수정과 지급 요청이 동시에 발생하는 경우에도 최종 잔액·원장 정합성이 유지되는지 시험한다.
- 전체 검사와 critical-reviewer 및 backlog-explainer 결과를 확인한다. 근거가 없는 항목은 완료로 표시하지 않는다.
