- 관련 정책: [`docs/tasks.md` P13 결정](../tasks.md), [P4.13](P4.13.md)

## 목적

완료·취소나 주간/월간 완료로 실제 보석 장부가 자동 증감하지 않게 하고, 아이가 실물 보유량에 맞춰 작은 보석과 큰 보석 수를 직접 저장하게 한다. P4.13의 실물 자격·요청·지급 정책은 유지되지만 장부를 자동으로 변경하지 않는다.

## 쉬운 설명

앱은 실물 보석을 자동으로 더하거나 빼지 않는다. 아이가 실제 가진 수를 직접 적으며, 앱을 다시 열어도 유지된다. 할 일을 마쳤을 때의 칭찬과 연속 기록, 실물 보석을 받을 자격과 요청·지급 절차는 계속 쓸 수 있다. 이 절차들은 장부 수량을 바꾸지 않는다.

## 필요한 입력

- 아이가 PIN 없이 일반·큰 보석의 정수 수량(0~99,999)을 직접 입력한다.
- `gemCountRepository`만 장부 수량을 변경한다. 저장은 기존 잔액을 다시 계산하거나 과거 원장을 지우지 않고 입력한 절대 수량과 기존 수량의 차액을 기록한다.
- 여러 수량 저장이 겹치면 마지막 저장의 절대 수량이 우선한다.
- 보석 자격·요청·실물 지급 상태는 P4.13의 절차를 따른다. 어느 단계도 보석 장부를 자동 증감하지 않는다.
- 새 할 일은 생성일부터 완료·연속 계산에 반영하며, 큰 보석 5개 환산은 캐릭터 그림 변화에만 사용한다.

## 결과물

- 체크/취소·주간/월간 완료 및 보상 목표가 장부를 자동 변경하지 않는 동작
- 기존 수량·원장 보존을 포함한 V12 이전 처리 근거
- 수동 절대 수량 저장, 앱 재시작 유지, 취소·오류·저장 중 닫기 예외 흐름 근거

## 선행 작업

P4.13은 실물 보석 자격·요청·지급 정책의 선행 근거다. P4.13이 `done` 상태이므로 그 정책을 기준으로 P13을 구현한다. 기존 완료 보석 원장을 보존하는 V12 이전은 P13에서 확인할 필수 증거이며, 이를 별도 선행 작업 상태로 바꾸지는 않는다. P12 캐릭터 테마는 별도 작업이다.

## 수행 순서

1. 자동 수량 변경 경로와 기존 장부·원장을 확인한다.
2. P4.13의 V12 이전이 과거 완료 보석을 조정 행으로 옮기고 총 보유량을 보존하는지, 이후 완료 기록을 취소해도 장부가 유지되는지 확인한다.
3. 체크·취소·주간/월간 완료와 보상 목표 및 자격·요청·지급이 장부를 자동 변경하지 않는지 테스트한다.
4. 직접 입력한 두 절대 수량의 원장 차액 저장, 재시작 유지, 여러 저장이 겹칠 때 마지막 절대값 우선 동작을 확인한다.
5. 입력 화면의 취소, 빈/잘못된 입력, 저장 중 닫기 차단, 저장 실패 재시도를 확인한다. 별도 실제 UI 키보드 조작은 검증 여부를 분리해 기록한다.
6. 검증용 값을 원래 값으로 복원하고 원본 데이터 일치 여부를 확인한 뒤 전체 검사와 dispatcher 리뷰 결과를 기록한다.

## done_when 확인 방법

체크·취소·주간·월간 완료와 목표 달성으로 보유량(작은·큰 보석 장부)이 자동 증감하지 않음. P4.13 V12 이전으로 기존 보유량이 보존되고 체크 취소 뒤에도 유지됨. 실물 보석 자격·요청·지급(P4.13)은 유지하되 장부를 바꾸지 않음. 아이가 수를 수정하고 재시작 뒤 유지됨. 동시 수량 저장은 마지막 저장의 절대값 우선. 수량 입력 취소·잘못된 입력·저장 실패 흐름 테스트, 전체 검사와 리뷰 확인.

완료 판정 기준:
- 자동 지급 중단: 체크·취소·주간/월간 완료·보상 목표 달성 시 장부 개수 불변
- 기존 보유량 보존: V12 마이그레이션 뒤 과거 일일 완료 보석을 조정 행으로 이전, 체크 취소 후에도 합계 유지
- P4.13 자격·요청·지급 유지: 실물 보석 자격 생성·요청·지급 상태는 독립적으로 동작, 장부와 무관
- 수동 수량 관리: 아이가 직접 입력한 절대 수량이 저장되고 재시작 후 유지
- 동시 저장 안정성: 여러 수량 저장이 겹칠 때 마지막 절대값 우선
- 입력 예외 흐름: 취소·빈 입력·잘못된 입력·저장 중 닫기 차단, 저장 실패 재시도
- 자동 검사 통과: `npm run check` (lint, typecheck, Jest, Android build)
- 리뷰 통과: 등록 dispatcher 성공, Critical/High 지적 해결
