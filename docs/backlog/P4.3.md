# P4.3 — 할 일 편집 (PIN)

## 기준 입력

- schema version: `1.1`
- source SHA-256: `db7fceeb11675ad9955a3b2c41dcfde026a73f0d782c6e2ad5372b9a1abb4e61`
- 기준 백로그 항목: `P4.3`
- 기준 상태: `in_review`
- 선행 작업: `P4.2`, `P2.8`

이 문서는 제공된 stdin JSON(schema version `1.1`, SHA-256 `db7fceeb11675ad9955a3b2c41dcfde026a73f0d782c6e2ad5372b9a1abb4e61`)만을 기준으로 작성했다. 원본 `backlog.json`은 읽거나 수정하지 않았고, JSON·프로그램 코드·상태도 변경하지 않았다.

## 목적

요일 반복 할 일과 특정 날짜 할 일을 관리자 PIN 뒤에서 추가·수정·삭제한다.

## 쉬운 설명

아이 화면에서는 할 일 편집 기능을 바로 사용할 수 없고, PIN을 확인한 뒤에만 편집할 수 있다. 관리자는 반복 요일 또는 특정 날짜를 정해 할 일을 만들고, 기존 할 일을 바꾸거나 삭제한다.

## 필요한 입력

- `P4.2`의 할 일 관련 로컬 DB 구조
- `P2.8`의 PIN 확인 기능
- 관리자 PIN
- 할 일 제목
- 반복 요일 또는 특정 날짜

요구사항에 없는 입력은 확정하지 않는다.

## 결과물

- PIN 확인 후에만 접근 가능한 할 일 편집 화면
- 요일 반복 할 일 CRUD
- 특정 날짜 할 일 CRUD
- 편집·저장 결과의 오늘 할 일 화면 반영
- 날짜 선택 UI와 완료 이력 항목 보호 보완
- 실패 PIN 잠금 및 5분 자동 잠금 관련 동작

구현 확인 대상은 `app/index.tsx`, `src/components/PinGate.tsx`, `src/components/TaskEditor.tsx`, `src/db/taskRepository.ts`, `src/db/rewardRepository.ts`이다.

## 선행 작업

- `P4.2`: 할 일 관련 DB 구조
- `P2.8`: PIN 확인 및 보호 기능

기준 입력에서 두 선행 작업은 모두 `done`으로 기록되어 있다.

## 수행 순서

1. schema version `1.1`과 source SHA-256을 확인한다.
2. `P4.2`, `P2.8`의 완료 여부와 P4.3의 `deps`를 확인한다.
3. PIN을 통과하지 않은 상태에서 CRUD가 차단되는지 확인한다.
4. 올바른 PIN 뒤에서 반복 할 일과 특정 날짜 할 일을 추가한다. 반복 할 일은 생성일부터 적용되는지 함께 확인한다.
5. 완료 이력이 없는 기존 할 일을 수정하고 삭제한다. 완료 이력이 있는 항목은 수정·삭제가 차단되는지 확인한다.
6. 달력 선택과 저장 결과를 확인한다.
7. 자동 검사 및 전체 품질 검사 결과를 기록한다.
8. 실기기에서 CRUD, PIN 차단·자동 잠금, 완료 이력 보호를 확인한다.
9. `done_when` 충족 여부와 검토 결과를 대조한다. 백로그 상태 변경은 별도 메인 실행에서 수행한다.

실기기 확인은 `docs/manual-device-tests.md`의 P4.3 절차(반복 할 일, 특정 날짜 할 일, PIN 차단·자동 잠금, 완료 이력 보존)를 기준으로 기록한다.

## done_when 확인 방법

`PIN 확인 후 반복·특정 날짜 할 일을 추가할 수 있고, 완료 이력이 없는 항목만 수정·삭제 가능함`을 다음처럼 확인한다.

- PIN 전에는 할 일 추가·수정·삭제가 실행되지 않는다.
- 올바른 PIN 후에는 반복 할 일과 특정 날짜 할 일을 추가할 수 있다.
- 완료 이력이 없는 항목만 수정·삭제할 수 있고, 완료 이력이 있는 항목은 보존 정책에 따라 수정·삭제가 차단된다.
- 실기기에서 PIN 차단과 CRUD 결과가 확인된다.
- PIN 실패 잠금·5분 자동 잠금과 완료 이력 항목의 수정·삭제 차단도 구현 결과와 함께 대조한다.
- 코드상 편집 진입은 `PinGate` 내부에 있고, 저장·수정·삭제는 `TaskEditor`에서 수행되며, 완료 이력이 있는 항목은 저장소 정책에 따라 보호되는지 확인한다.

자동 검사 통과만으로 실기기 확인을 대신하지 않으며, 실기기 확인만으로 자동 검증을 대신하지 않는다.

## 현재 확인 기록

- 기준 상태: `in_review`.
- 최신 로그는 반복·특정 날짜 CRUD, PIN 차단·자동 잠금, 달력 선택·저장, 완료 이력 항목 수정·삭제 차단을 실기기에서 모두 확인했다고 기록한다.
- 최신 로그는 구현·전체 품질 검사 완료 후 최종 검토를 실행한다고 기록한다.
- 최신 로그는 사용자가 확인·승인한 완료 이력 보존 정책에 맞게 완료 조건을 구체화했으며, 반복 할 일은 생성일부터 적용한다고 기록한다.
- 최신 로그 시각은 `2026-09-19T02:26:00.374Z`이며, 당시 상태는 `in_review`이다.
- 이전에는 실기기 확인이 사용자 담당으로 남았으나, 이후 실기기 확인 완료 기록으로 갱신되었다.
- 코드 확인 기록: `PinGate`가 PIN 미설정/검증, 실패 잠금, 5분 편집 세션 만료를 처리하고, `TaskEditor`가 반복 요일·특정 날짜의 추가·수정·삭제와 저장 후 갱신을 연결한다. 저장소는 완료 이력이 있는 항목의 수정·삭제를 보호하도록 보완되었다.
- 수동 확인 절차는 `docs/manual-device-tests.md`에 있으며, 기준 로그는 반복·특정 날짜 CRUD, PIN 차단·자동 잠금, 달력 선택·저장, 완료 이력 보호가 모두 확인됐다고 기록한다.
- 검증 기록에는 전체 품질 검사 통과가 포함되지만, 구체적인 기기 모델·Android 버전·빌드 식별값·명령 출력은 기준 stdin에 없다.
- `done_when`은 “PIN 확인 후 반복·특정 날짜 할 일을 추가할 수 있고, 완료 이력이 없는 항목만 수정·삭제 가능”으로 구체화된 기준으로 확인한다. 현재 백로그 상태는 `in_review`이며, 이 문서는 완료 상태로 변경하지 않는다.

## 확인 질문

- 반복 요일과 특정 날짜를 한 항목에서 동시에 허용할지에 대한 명시적 요구사항은 기준 입력에 없다. 현재 구현·확인 방식으로 확정할지 결정이 필요하다.
- PIN 실패 잠금과 5분 자동 잠금의 정확한 실패 횟수·잠금 해제 동작은 기준 입력에 구체적으로 적혀 있지 않다. 별도 제품 요구사항으로 확정할지 확인이 필요하다.
- 완료 이력 항목의 수정·삭제 차단은 최신 로그에서 승인된 보존 정책으로 기록되었지만, 원래 `done_when` 문구에는 직접 포함되지 않았다. 백로그 완료 조건에 계속 명시할지 확인이 필요하다.
- 반복 할 일이 생성일 당일부터 적용되는 정책은 최신 로그에 기록되었으나, 종료일·시간대 등 추가 반복 규칙은 기준 입력에 없다.
