# P0.4 — 알림 PoC (expo-notifications)

## 기준 입력

- 백로그 schema version: `1.1`
- 백로그 SHA-256: `534c941036988b4fe8000c73f103dfcbc6fcd3ea381a6953108c28ca1fa072ef`
- 기준 항목: `P0.4`
- 기준 상태: `done`
- 상위 작업: `P0`
- 선행 작업(deps): 없음

## 목적

`expo-notifications`로 1분 뒤 로컬 알림을 예약하고, 화면 꺼짐·앱 종료·무음 모드·절전 모드에서 실제 수신 여부를 확인해 일반 알림의 동작 범위를 기록한다.

## 쉬운 설명

알림을 하나 예약한 뒤 딸 폰의 상태를 바꿔 가며 알림이 오는지 확인한다. 모든 상태에서 반드시 와야 한다고 미리 가정하지 않고, 실제 결과를 다음 설계의 근거로 남긴다.

## 필요한 입력

- 실기기: SM-A245N, Android 16
- 개발 빌드에 포함된 `expo-notifications` 구현
- PoC 화면의 1분 뒤 예약 기능
- Android 알림 권한, 알림 채널, 예약 알람 확인 수단
- 확인할 네 가지 상황: 화면 꺼짐/Doze, 일반 앱 종료(최근 앱에서 제거), 무음 모드, 절전 모드

## 결과물

- 1분 뒤 로컬 알림 예약 결과
- 네 가지 상황별 수신 여부와 확인 근거
- 알림 권한 및 `timetable-poc` 채널 확인 기록
- 완료 조건 충족 여부와 후속 알람 설계에 필요한 확인 질문

## 선행 작업

백로그상 `deps`는 없으며, P0.4 자체의 PoC 구현 및 실기기 확인이 필요하다. 일반 알림 PoC 결과는 후속 알람 모드 PoC(P0.5) 및 3단계 알림 구현의 참고 자료로 사용한다.

## 수행 순서

1. P0.4의 `done_when`과 네 가지 시험 상황을 확인한다.
2. PoC 화면에서 1분 뒤 로컬 알림을 예약한다.
3. 실기기에서 화면 꺼짐, 앱 종료, 무음 모드, 절전 모드를 각각 적용한다.
4. 각 상황의 수신 여부를 Android 알림 기록 및 예약·wakeup 관련 확인 결과와 대조한다.
5. 결과와 예외를 상황별로 기록하고 `done_when` 충족 여부를 판단한다.

## done_when 확인 방법

백로그 기준 완료 조건은 “4가지 상황 각각에서 알림 수신 여부를 기록함”이다. 따라서 네 상황에 대해 각각 `수신` 또는 `미수신`을 명시하고, 확인 근거가 있는지 대조한다. 미수신도 시험 결과로 기록하며 성공으로 간주하지 않는다.

## 현재 확인 기록

확인 대상은 SM-A245N(Android 16) 실기기다.

모든 시각은 2026-09-16 KST이며, `AlarmManager`의 예약 생성(`rtc`), 명목 예정(`OW`), 실제 **wakeup 이력**을 대조했다. 표의 마지막 시각은 알림 게시 시각이 아니라 Android가 예약 broadcast를 깨운 시각이고, Android 알림 레코드는 해당 ID가 게시됐는지만 별도로 확인했다. 이 PoC의 Android 예약은 60초 뒤부터 최대 약 45초의 전달 창을 사용했다.

| 상황 | 예약 생성 → 명목 예정 → 실제 전달 | 결과와 확인 기록 |
|---|---|---|
| 화면 꺼짐/Doze | 20:23:25.833 → 20:24:25.768 → 20:25:31.634 | 명목 예정 대비 약 66초 지연 후 수신. 확인 ID `4076bca5-2056-4e65-bd0d-ff712262c09d`; Android 알림 레코드도 확인. 화면은 Doze 상태였음. |
| 일반 앱 종료(최근 앱에서 제거) | 20:40:00.668 → 20:41:00.653 → 20:41:45.654 | 약 45초 지연 후 수신. 최근 앱 카드 제거 뒤 TimeTable 프로세스가 없음을 확인했고, 알림 태그 `b20b4979-ea87-4eeb-9f1e-38c35299e7d2`가 Android 알림 레코드에 남음. |
| 무음 모드 | 20:31:23.196 → 20:32:23.182 → 20:33:08.180 | 약 45초 지연 후 수신. `SILENT` 전환 상태에서 알림 태그 `bbffd2f2-0a36-43a1-b62f-8a448d08a450` 확인 후 `NORMAL`로 복원. 수신 여부만 검증했으며 무음 상태의 소리 재생은 기대하지 않음. |
| 절전 모드(Battery Saver) | 20:33:39.188 → 20:34:39.173 → 20:35:24.163 | 약 45초 지연 후 수신. Battery Saver `ON` 상태에서 태그 `528ea659-a16b-4439-a8c3-4b4ccc2ad640`가 Android 알림 레코드에 남았고 즉시 `OFF`로 복원. |

추가로 알림 권한, `timetable-poc` 채널, Android 알림 레코드 및 `AlarmManager` wakeup을 확인했다. 현재 기록은 백로그의 네 가지 상황을 모두 포함하므로 `done_when`의 기록 요건은 충족된 것으로 판단된다. 이 P0.4 검증에서 “앱 종료”는 **사용자가 최근 앱 화면에서 TimeTable 카드를 제거하는 일반 종료**로 판정한다. 설정에서 Android 앱을 강제 중지한 별도 시험에서는 예약 알람이 취소되어 미수신이었으며, 이는 사용자 일반 종료가 아닌 별도 제한 사항으로 기록한다. P0.4는 결국 수신되는지를 기록한 일반 알림 PoC이고, 정시성 판단은 후속 알람 모드 PoC(P0.5)와 3단계에서 수행한다.

## 후속 확인 범위

- 알림의 정시성, 전체화면·반복음, 사용자 상호작용은 P0.4의 판정 범위가 아니다. 지연 허용 범위와 알람 방식은 P0.5 및 3단계에서 별도로 결정·검증한다.
