# P0.7 재부팅 후 알림 확인

## 기준

- 백로그 schema version: `1.1`
- 백로그 SHA-256: `3a94415489e05353ed1362aada99b710d4293c14816d9110280e80ff7a052779`
- 대상: `P0.7`
- 현재 상태: `done`

## 목적

알림을 예약한 뒤 휴대폰을 다시 시작해도 예약이 복구되는지 확인한다. 쉽게 말해, 재부팅 때문에 알림이 사라지지 않고, 아직 시간이 남았으면 원래 알림이 오며 이미 시간이 지났으면 놓친 알림 이력이 한 번 표시되는지 확인하는 작업이다.

## 필요한 입력

- 실기기: SM-A245N(Android 16)
- 기기에 설치된 TimeTable 개발 빌드
- 알림 권한과 일반 알림 채널이 활성화된 상태
- 앱의 1분 뒤 일반 알림 예약 기능

## 결과물

- 예약 시각, 재부팅 시각, 재부팅 완료 시각, 알림 또는 이력 안내 시각
- 기기 모델·Android 버전
- 재부팅 전 예약 시각이 지나지 않은 경우의 재등록 결과
- 재부팅 중 예약 시각이 지난 경우의 놓친 알림 이력 안내 결과

## 선행 작업

- P0.4(알림 PoC)가 선행되어야 한다(`deps: [P0.4]`).
- 실기기와 TimeTable 빌드가 준비되어야 하며, 알림 권한·채널이 허용되어야 한다.

## 수행 순서

1. 앱에서 1분 뒤 일반 알림을 예약하고 예약 완료를 확인한다.
2. 예약 시각 전에 전원 메뉴에서 기기를 다시 시작한다.
3. 부팅 완료 후 첫 잠금 해제를 진행한다. 예약 시각이 아직 지나지 않았다면 저장된 예약이 한 번 재등록되는지 확인한다.
4. 재등록된 예약이 원래 일반 알림으로 정확히 한 번 도착하는지, 도착 방식과 시각을 기록한다.
5. 별도 반복으로 예약 시각이 재부팅 중 지나도록 한 뒤 첫 잠금 해제를 진행한다.
6. 이 경우 놓친 일반 알림 이력이 중복 없이 정확히 한 번 표시되는지 확인하고, 재부팅 전 도착이나 일반 알림의 중복이 없는지 함께 기록한다.
7. 기기 모델·Android 버전·예약·재부팅·부팅 완료·첫 잠금 해제·알림 또는 이력 안내 시각과 결과를 기록한다.

## done_when 확인 방법

- 첫 잠금 해제 뒤 부팅 완료 시 예약 시각 전이면 재등록되어 원래 일반 알림이 정확히 한 번 도착하는지 확인한다.
- 예약 시각이 재부팅 중 지난 경우에는 중복 알림 없이 놓친 일반 알림 이력이 정확히 한 번 표시되는지 확인한다.
- 미도착, 중복 도착, 재부팅 전 도착 또는 권한 오류가 있으면 완료로 판정하지 않는다.
- 위 결과와 시각·기기 정보를 이 문서에 남긴 뒤 검토한다.

## 현재 확인 기록

SM-A245N(Android 16)에서 사용자가 두 재부팅 경우를 직접 확인했다. 예약 시각 전에 부팅이 끝난 경우에는 일반 알림이 표시됐고, 재부팅 중 예약 시각이 지난 경우에는 `재부팅 중 놓친 일반 알림이에요.` 안내가 표시됐다. 두 결과가 구분되어 표시되는 것을 확인해 P0.7은 완료했다.

## 확인 질문

- 재부팅 중 놓친 알림을 즉시 이력 안내로 남기는 정책을 일반 알림 외의 전체화면 알람에도 동일하게 적용할지는 별도 요구사항에 명시되어 있지 않다.
