# P0.5 — 알람 모드 PoC (react-native-notify-kit)

## 기준 입력

- schema version: `1.1`
- backlog SHA-256: `ca4ddb830d62dca9aa34371ad71ec385a8668d20bb537a0624927240318cd775`
- task: `P0.5`
- status: `in_review`
- parent: `P0`
- deps: `P0.8`
- source: `backlog.json`의 제공된 stdin JSON

이 문서는 기준 입력을 설명하기 위한 문서이며, 원본 `backlog.json`, 프로그램 코드, 작업 상태를 변경하지 않는다.

## 목적

잠금 화면 위에 알람 화면을 띄우고, 반복 소리와 `끄기` 버튼이 동작하는지 딸 폰에서 확인한다. 결과를 바탕으로 D3의 구현 방식을 A(`react-native-notify-kit`) 또는 B(자체 Kotlin 알람 경로)로 결정한다.

## 쉬운 설명

폰이 잠겨 있어도 시간표 알람 화면과 계속 울리는 소리가 나타나고, 아이가 `끄기`를 누르면 모두 멈추는지 확인하는 작업이다. 라이브러리 방식이 충분하지 않으면 Android Kotlin 경로를 사용한다.

## 필요한 입력

- P0.5의 `summary`와 `done_when`
- 관련 요구사항: `docs/research.md`의 F3, 5-1, 5-2, D3
- 선행 PoC 결과: P0.8 잠금 화면 전용 `AlarmActivity`, P0.4 일반 알림
- 검증 기기: SM-A245N, Android 16
- 테스트 조건: 잠금 상태, 전체 화면 알림 특별 접근 허용/미허용, 15초 테스트 알람
- 확인 대상: AlarmManager broadcast, `CATEGORY_ALARM` 전체 화면 알림, 반복 소리, `끄기`, 권한 미허용 시 예약 차단과 설정 안내

기준 입력에 없는 세부 정책이나 운영 절차는 임의로 확정하지 않는다.

## 결과물

- 전체화면·반복소리·끄기 동작의 실기기 확인 기록
- A/B 비교 결과와 D3 결정 근거
- 권한 미허용 상태에서의 예약 차단·설정 안내 확인 기록
- 조건별 통과/미확인 여부 및 남은 확인 질문

## 선행 작업

- `P0.8`: 자체 Kotlin 잠금 화면 전용 AlarmActivity PoC
- `P0.4`: 일반 알림 PoC
- P0.8에서 기록된 Android 16 `BAL_BLOCK` 직접 Activity PendingIntent 실패 결과

P0.8의 직접 Activity 실행 경로와, AlarmManager broadcast가 전체 화면 알림을 게시하는 경로는 구분하여 확인한다.

## 수행 순서

1. P0.5의 `summary`, `done_when`, 관련 요구사항과 선행 결과를 대조한다.
2. A안(`react-native-notify-kit`)에서 전체 화면 표시, 반복 소리, `끄기`, 권한 기본값을 실기기로 확인한다.
3. A안이 잠금 화면 전체화면 UX를 충족하지 못하면 B안 자체 Kotlin 경로를 확인한다.
4. B안의 AlarmManager broadcast, `IMPORTANCE_HIGH`, `CATEGORY_ALARM`, 전체 화면 알림, 전용 `AlarmActivity` 연결을 확인한다.
5. 잠금 상태에서 전용 화면 표시와 잠금 유지, 반복 소리를 확인한다.
6. `끄기`를 눌러 소리·전용 화면·진행 중 알림이 종료되는지 확인한다.
7. 전체 화면 알림 특별 접근이 없을 때 예약이 차단되고 설정 화면으로 안내되는지 확인한다.
8. 조건별 근거와 D3 결정을 기록하고 `done_when` 충족 여부를 검토한다.

## done_when 확인 방법

- 전체화면: 잠금 상태에서 NotificationShade/AOD만이 아니라 전용 알람 화면이 표시되는지 확인
- 반복소리: 전용 화면이 표시된 동안 소리가 계속 반복되는지 확인
- 끄기: 버튼을 눌렀을 때 소리·화면·진행 중 알림이 모두 종료되는지 확인
- 권한 미허용: 전체 화면 알림 특별 접근이 없을 때 예약이 차단되고 설정 화면 이동 안내가 표시되는지 확인
- D3: A안 또는 B안 중 결정 결과와 근거가 `docs/research.md`에 기록되어 있는지 확인

## 현재 확인 기록 (기준 SHA 기준)

### A안 — react-native-notify-kit

- SM-A245N(Android 16)에서 HIGH 중요도, alarm 범주, INSISTENT 알림, 전체 화면 PendingIntent, `끄기` 액션 등록은 확인했다.
- 기본 FSI AppOp와 임시 `allow` 모두에서 잠금 화면 앱 전체화면 대신 NotificationShade/AOD만 표시됐다.
- 따라서 A안은 P0.5의 전체화면·반복소리·끄기 완료 근거가 되지 않는다.

### B안 — 자체 Kotlin 알람 경로

- 사용자가 전체 화면 알림 특별 접근을 허용한 뒤 잠금 상태 15초 테스트를 수행했다.
- 전용 알람 화면, 잠금 유지, 반복음, `끄기` 후 소리·화면·진행 중 알림 종료를 확인했다.
- 확인된 경로는 `AlarmManager broadcast → CATEGORY_ALARM 전체 화면 알림 → 잠금 유지 AlarmActivity`이다.
- 전체 화면 알림 특별 접근 미허용 시 예약 차단과 설정 화면 이동을 SM-A245N에서 확인했다.
- 제공된 기준 입력의 최신 기록은 D3을 B안으로 결정했음을 보여 주며, P0.5 자체 상태는 여전히 `in_review`이다.
