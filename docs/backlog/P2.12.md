## 목적

사용자가 제공한 엑셀 시간표(시간표1~3.png)처럼 첫 칼럼이 시간 범위이고 월~금 칼럼에 일정이 시간에 맞게 배치되는 주간 표를 TimeTable 앱에서 만들 수 있는지 검증한다. 요일마다 시간이 다르므로(예: 수요일 13:10~14:30, 화·목 14:10~16:20), 한 주의 모든 시작·종료 시각을 합친 전체 행의 경계가 몇 개가 되고, 폰 세로(약 360dp) · 가로(약 800dp) 폭에서 표이 얼마나 읽힐 수 있는지 계산한다.

## 쉬운 설명

엑셀 시간표는 세로축이 시간(09:00~09:40, 09:50~10:30 등)이고 가로축이 요일(월~금)이라 "화요일 14:10~16:20 리틀 포레스트"는 화 칼럼의 14:10~16:20 행에 위치한다. 이 레이아웃을 폰 화면에 그리려면 먼저 "한 주에 몇 개 행이 필요한가?"를 알아야 한다. 예를 들어 시간표1.png에서는 월~금의 시작·종료 시각 10개를 모두 취합하면 총 행 경계가 몇 개 되는지, 그리고 세로(약 360dp)·가로(약 800dp) 각 폭에서 5요일 칼럼과 시간 칼럼이 글자 크기·칸 높이와 함께 수용될 수 있는지를 정량적으로 확인한다.

## 필요한 입력

  - 최소 터치 영역 56dp 원칙

## 수행 순서

1. 시간표1.png에서 가독한 일정 데이터를 `TimetableItem` 형식 픽스처로 작성
   - 월~금 각 요일의 수업·학원 시간, 제목, 색상 정보 포함
2. `calculateRowBoundaries` 함수 구현: 요일×시간에서 모든 유일 시간 경계 추출, 시간 오름차순 정렬
3. 각 셀(일정×행)이 몇 개 행을 차지할 것인지 계산하는 로직 추가
4. 단위 테스트 작성
   - 시간표1.png 데이터에서 예상 행 개수 검증
   - 행 높이 계산: 세로(360dp 폭, 56dp 최소 높이 기준), 가로(800dp 폭) 각각에서 행당 최소 높이
   - 칸의 텍스트 "HH:MM~HH:MM 제목"이 수용 가능한지 폭 기준으로 검증(평균 글자폭 × 글자 수 ≤ 셀 폭)
5. 결과를 문서에 정리:
   - 세로: 행 개수 N, 행 높이 약 60dp × N = 화면 높이 대비 약 X배 → 스크롤 필요 여부 판정
   - 가로: 같은 일정에서 행 높이 약 Y dp → 화면에 수용 가능한 행 개수 Z → 스크롤 필요 여부 판정
6. 3가지 후보 평가:
   - `a) 모든 경계를 행`: 행 개수가 많아서 세로 스크롤 필수일 가능성
   - `b) 시간에 비례+빈 구간 압축`: 행 개수 감소, 시간 눈금 해석 용이, 빈 구간 표시 방법 고려 필요
   - `c) 칸에 자기 시각 표기`: 행을 일정개(예: 6시간 = 6행)로 고정, 칸 안에 "14:10~16:20" 텍스트 추가
7. 선택안 결정: 세로 스크롤 허용 여부 포함
