# P2.9 — 단위 테스트: 현재 교시 · 다음 일정 계산

## 기준 입력

- 기준 백로그 schema version: `1.1`
- 기준 백로그 SHA-256: `67df360b987a1337a1e6a5c09fc7f70c6e602b7762bc8b06737ff290128f1ad1`
- 기준 백로그 항목: `P2.9`
- 백로그 개발 상태: `in_review`
- 선행 작업: `P2.4`
- 문서 상태: P2.4에서 상속된 테스트와 경계 테스트 보강 근거를 반영했다. 문서화 완료와 개발 작업 완료는 별도로 관리한다.

## 목적

오늘 일정 계산 순수 함수가 현재 교시, 다음 일정, 다음 일정까지 남은 시간을 정확히 계산하는지 테스트한다. 백로그의 완료 기준은 “현재 교시·다음 일정 계산 테스트가 통과함”이다.

## 쉬운 설명

현재 시각이 수업 중일 때는 그 수업을 `current`로 고르고, 다음 수업이 있으면 `next`와 남은 분을 계산한다. 첫 수업 전과 마지막 수업 후도 별도로 확인한다. 수업 시작 시각은 포함하고 종료 시각은 포함하지 않는 경계를 검증하며, 입력 순서가 뒤섞여도 시작 시각 순으로 계산되는지 확인한다.

## 필요한 입력

- `src/utils/todaySchedule.ts`의 `getTodaySchedule` 순수 함수.
- 시작·종료 시각, 제목, 색·아이콘 키를 가진 일정 목록.
- 현재 시각을 지정한 `Date` 값.

## 결과물 및 테스트

- `__tests__/today-schedule.test.ts`
  - 수업 중 현재 일정과 다음 일정
  - 첫 수업 전 다음 일정과 남은 분
  - 마지막 수업 후 현재·다음 일정 없음
  - 시작 시각 포함, 종료 시각 제외 경계
  - 입력 일정 순서가 뒤섞인 경우 정렬 후 계산
- P2.4에서 사용하던 현재·다음 일정 테스트를 상속하고, 위 경계 사례를 보강했다.

## 수행 순서

1. `P2.4`의 일정 계산 함수 계약과 입력 자료형을 확인한다.
2. 수업 진행 중, 첫 수업 전, 마지막 수업 후의 기준 시각을 준비한다.
3. 시작 시각과 종료 시각에 정확히 걸리는 경계 사례를 준비한다.
4. 입력 일정 순서를 뒤집어 함수가 정렬하는지 확인한다.
5. `current`, `next`, `minutesUntilNext` 결과를 기대값과 대조한다.
6. 전체 품질 검사에서 Jest와 Android debug build까지 통과했는지 확인한다.

## done_when 확인 방법

다음 근거로 백로그의 완료 기준을 대조한다.

- 수업 중 시각에서 현재 일정, 다음 일정, 다음 일정까지 남은 분이 정확히 반환되는지 확인한다.
- 첫 수업 전에는 현재 일정이 없고 가장 가까운 다음 일정과 남은 분이 반환되는지 확인한다.
- 마지막 수업 후에는 현재·다음 일정과 남은 분이 모두 없는지 확인한다.
- 시작 시각은 현재 일정에 포함되고 종료 시각은 제외되는지 확인한다.
- 입력 배열 순서와 무관하게 시작 시각 순으로 현재·다음 일정을 찾는지 확인한다.
- `__tests__/today-schedule.test.ts`의 상속 테스트와 경계 테스트가 통과했다.
- 전체 `npm run check`가 통과했다: 지침 동기화, 파일 길이, lint, typecheck, Jest 37개, Android x86_64 debug build.
- 현재 백로그 개발 상태는 `in_review`이며, 문서화 완료를 개발 작업의 `done` 상태와 혼동하지 않는다.
