# P6.15: 동기화 3 — 로그인 상태 편집은 서버에 먼저 저장

**기준 Schema 1.1 · SHA-256 001af6ae6086283403626351f30f208717636fd61da93f9a4bba7f64d997a340**

## 목적

로그인한 폰(가족 계정과 연결된 기기)에서 시간표, 세트, 교시, 할 일, 보상 목표 같은 데이터를 편집할 때, 변경 내용을 **로컬 폰에만 저장하지 않고 서버에 먼저 저장**한 뒤 반영하도록 한다. 이를 통해 다른 기기에서 같은 가족의 데이터를 바꿨을 때 폰이 최신 상태를 유지하고, 편집 실패 시(인터넷 없음 등) 폰 데이터가 서버와 어긋나지 않게 보호한다. 로그인하지 않은 로컬 모드는 지금처럼 폰에만 저장한다.

## 쉬운 설명

### 로그인 상태에서 편집할 때의 흐름

1. **편집 입력 받기**: 관리자가 '시간표 추가', '할 일 편집' 등 화면에서 변경을 입력한다.
2. **편집 전 데이터 스냅샷**: 로컬 폰의 시간표·할 일 등 7개 테이블(periods, timetable_sets, timetable_settings, timetable_items, day_exceptions, tasks, rewards)의 **모든 행을 저장**한다.
3. **로컬 실행**: 검증 규칙을 포함해 편집을 폰에서 먼저 실행한다(지금과 같음).
4. **편집 후 데이터 스냅샷**: 편집 뒤의 7개 테이블을 다시 읽는다.
5. **차이점 계산**: 전후 데이터를 비교해 **바뀌거나 새로 생긴 행은 upsert, 사라진 행은 delete** 목록을 만든다.
6. **서버에 저장**:
   - 참조되는 테이블부터 넣고(예: 세트 먼저, 항목은 나중에)
   - 지울 때는 참조하는 것부터 지운다(반대 순서).
   - 새로 만든 행의 **로컬 id를 그대로 서버 id로** 사용한다(로컬과 서버 id가 계속 이어짐).
7. **저장 실패 시**:
   - "인터넷 연결이 필요해요. 바꾼 내용은 저장하지 않았어요." 안내.
   - 폰의 편집을 **편집 전 상태로 모두 되돌린다**.
   - 서버에는 아무 변화가 없으므로 폰과 서버가 어긋나지 않는다.
8. **저장 성공 시**:
   - 곧바로 "동기화 중"을 시작해 서버 변경(다른 기기 편집 포함)을 받아온다.
   - 알림과 위젯도 새로 예약·갱신한다.

### 로그인하지 않은 로컬 모드

계정 로그인이 없거나 서버와 아직 한 번도 맞추지 않은 폰은 지금처럼 동작한다. 편집이 로컬 폰에만 저장되고 서버와 상관없다.

### 특수 기능: '서버 내용으로 이 폰 다시 맞추기'

관리자 화면의 '기타 → 서버 연결'에서 이 버튼을 누르면:
- 사용자에게 "이 폰의 시간표·할 일·체크·보석 기록을 서버 내용으로 바꿔요. **아직 서버에 올라가지 않은 이 폰의 기록은 사라져요**."라고 안내한다.
- 확인 후, **동기화 표시를 초기화**하고 서버 기준으로 처음부터 동기화를 다시 한다.
- 이 때 **폰의 올라가지 않은 기록(체크, 보석 등)이 사라진다**.
- 빈 서버에서 (빈 폰 상태에서) 직접 이 버튼을 눌렀으면 **빈 서버 보호를 건너뛴다**(서버에 아직 데이터가 없어도 진행).

### 로그아웃 시 동기화 표시 초기화

로그아웃하면 "이 폰에서 로그아웃했어요"와 함께 저장소의 동기화 표시(어느 가족과 맞췄는지, 마지막 동기화 시각)를 **지운다**. 다음에 로그인하면 처음 동기화부터 다시 시작한다.

## 필요한 입력

- **관리자 PIN** 또는 설정 화면 접근 권한: 로그인 상태 확인과 '서버 내용으로 다시 맞추기' 실행
- **인터넷 연결**: 편집 저장과 동기화 실행
- **서버 계정**: 가족 가입 · 로그인(P6.4 완료)
- **로컬 데이터**: 편집 전에 폰에 시간표·할 일 등이 있어야 함(빈 폰은 자동 처리)

## 결과물

### 코드 구현
- **src/sync/adminEdit.ts**: 
  - `diffParentTables()`: 편집 전후 데이터를 비교해 upsert/delete 목록 생성.
  - `toServerRow()`: 로컬 행을 서버 형식으로 변환(시각 ISO 포맷, 요일 배열 등).
  - `applyParentDiff()`: Supabase에 upsert/delete 적용(참조 순서 맞춤).
  - `runAdminEdit<T>()`: 편집 전후 스냅샷 및 서버 저장을 감싼다. 실패 시 로컬 되돌림.
  - `OFFLINE_EDIT_MESSAGE`: 오프라인 편집 안내 문구.

- **src/sync/adminEditGate.ts**:
  - 화면 코드가 관리자 편집을 할 때 부르는 입구.
  - 로그인한 폰이면 `runAdminEdit()`를 통해 서버 저장을 거치고, 로그인 전이면 직접 편집을 실행.
  - 화면이 동기화 모듈을 직접 부르지 않도록 분리.

- **src/sync/syncMarkers.ts**:
  - `hasSyncedFamily()`: 이 폰이 어느 가족과 맞췄는지 확인.
  - `markSynced()`: 가족 id와 마지막 동기화 시각을 저장.
  - `clearSyncedFamily()`: 로그아웃 또는 '다시 맞추기' 선택 시 동기화 표시 초기화.

- **src/components/SyncPanel.tsx**:
  - 관리자 '기타 → 서버 연결' 패널.
  - '지금 서버와 맞추기' 버튼: 즉시 동기화.
  - '서버 내용으로 이 폰 다시 맞추기' 버튼: 사용자 확인 후 초기화 및 재동기화.

- **src/sync/syncRunner.ts의 `resyncFromServer()`**:
  - `clearSyncedFamily()` 호출해 표시 초기화.
  - `runSync(target, { forceServer: true })`로 서버 기준 첫 동기화 실행.

### 테스트
- **__tests__/sync-admin-edit.test.ts**:
  - ✅ 로그인해 서버와 맞춘 폰의 편집은 바뀐 행만 서버 저장, 로컬 id 유지, 곧 다시 맞춤.
  - ✅ 인터넷 없음: 서버 저장 실패 → 폰 편집 되돌림 → 안내 메시지.

  - ✅ 세트 복사 시 세트와 항목이 함께 저장, 참조 순서 유지.
  - ✅ 서버 행 변환: 옛 열 제외, 시각 ISO 포맷, 요일 배열 변환.
  - Jest 5개 테스트 통과.
