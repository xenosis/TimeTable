# P6.8 — 아빠 화면

## 기준 입력

- Schema version: 1.1
- SHA-256: 34d737010653c0eef51542eaa4d816b2e5b79f4da3c692bbc692b78821c6eec6
- 입력 크기: 442641 bytes
- 기준 시각: 2026-10-07T18:11:48.116Z
- 작업 상태: needs_info; owner codex; updated_at 2026-10-07T17:19:32.323Z

## 목적

아빠 계정으로 로그인한 기기에서 시간표와 할 일을 편집하고, 딸의 완료 현황·보석 정보·딸 폰의 마지막 동기화 시각을 확인하도록 한다.

## 쉬운 설명

아빠가 로그인하면 아빠 화면을 본다. 여기서 아이의 오늘 할 일 진행과 보석 정보를 보고, 딸 폰이 서버와 마지막으로 맞춘 때를 확인하며, 편집 화면으로 이동할 수 있다.

## 필요한 입력

- P6.6 동기화 기능: 완료. 서버 데이터를 로컬에 반영하고 오프라인 기록을 동기화한다.
- P6.7 Realtime·앱 복귀 동기화: 완료.
- P6.15 서버 우선 편집: 완료. 로그인 상태에서 편집은 서버에 먼저 저장된다.
- 가족의 child 구성원 및 `tt_devices.last_synced_at` 정보.
- 아빠 계정에 로그인할 수 있는 기기. 기준 입력 시점에는 실제 아빠 계정 기기 확인이 미완료다.
- 기존 행을 여러 기기에서 동시에 편집할 때의 정책에 대한 사용자 결정. 기준 입력에서는 미확정이다.

## 결과물

- 아빠 전용 홈과 편집 화면 진입점.
- 딸의 오늘 할 일 진행 및 작은·큰 보석 정보를 보여주는 현황 영역.
- 딸 폰의 마지막 동기화 시각 표시.
- 아빠 기기의 딸 일정 알람 차단 정책.
- 현황·역할별 동작을 검증하는 자동 테스트 및 기기 확인 기록.

## 선행 작업

- 직접 deps: P6.6 (`done`).
- 구현에 연관된 완료 작업: P6.7, P6.15.
- 실제 아빠 계정 기기 확인과 원격 지급·기기 알람 정책 검증은 자식 작업 P6.16에서 다룬다. P6.16은 기준 입력에서 `needs_info`다.

## 수행 순서

1. 아빠 로그인 역할에서 아빠 홈을 표시하고 편집 진입점을 연결한다.
2. 동기화된 딸 자료에서 오늘 할 일·보석 정보를 읽어 현황을 표시한다.
3. 딸 구성원 기기 정보를 조회해 마지막 동기화 시각을 표시하며 미동기화·오류·기록 없음도 구분한다.
4. 앱 복귀, 동기화 변경 및 수동 새로고침 뒤 현황을 갱신한다.
5. 아빠 기기 역할에 맞춰 딸 알람 예약을 차단하고, 역할 전환 때 정책을 갱신한다.
6. 현황 조회와 역할별 알람 동작의 테스트·전체 검사·독립 리뷰 근거를 확인한다.
7. 아빠 계정 기기에서 편집, 현황, 동기화 시각 및 관련 기기 정책을 확인한다.
8. 동시 편집 정책을 사용자 결정으로 기록한다. P6.16 검증과 미결정 사항이 끝나기 전에는 P6.8을 완료로 처리하지 않는다.

## done_when 확인 방법

백로그 조건은 “아빠 화면에서 편집·현황·동기화 시각이 모두 표시됨”이다.

- 아빠 화면에 시간표·할 일 편집 진입점이 있고 선택 시 편집 화면으로 이동하는지 확인한다.
- 딸의 오늘 할 일 진행 및 보석 현황이 표시되는지 확인한다.
- 딸 폰의 마지막 동기화 시각이 표시되는지 확인한다. 미동기화·기록 없음·조회 실패를 성공으로 오인하게 표시하지 않는지도 확인한다.
- 관련 자동 테스트, `npm run check`, 등록된 독립 리뷰 결과를 확인한다.
- 실제 아빠 계정 기기에서 위 화면 항목과 편집 진입을 확인한다.
- P6.16에 기록된 두 기기 검증과 동시 편집 정책 결정이 완료됐는지 확인한다. 검증 미완료 또는 리뷰 미실행은 완료 근거가 아니다.

## 현재 확인 기록 (기준 SHA 기준)

- P6.8은 `in_review`; 직접 의존 P6.6은 `done`이다. P6.7과 P6.15도 `done`이다.
- 로그에는 아빠 홈, 편집 진입, 딸의 할 일·보석 현황, 딸 기기 동기화 시각, 아빠 기기의 딸 알람 차단과 원격 보석 지급 처리가 구현됐다고 기록돼 있다.
- 최신 로그(1.54.6/145)는 전체 검사가 74 suites/451 tests 및 Android build에서 정상 종료됐다고 기록한다. 가족별 편집 시각 테스트 1건과 lint·길이 검사도 통과했다. 같은 가족 안 역할 전환·재로그인 중 이전 조회 결과를 폐기하고, 역할 저장소 조회 오류 때 기존 네이티브 예약을 보존하는 보완을 검증했다. 지정 ARM64 릴리즈의 버전 145와 기존 서명 일치를 확인했고 딸 폰 설치가 진행 중이다. 이 로그의 목적은 코드 보완 재리뷰이며, 아빠 계정 기기 검증이나 P6.16 완료를 뜻하지 않는다.
- P6.16은 `needs_info`다. 아빠 계정 로그인 기기에서 양방향 동기화·원격 지급·로그아웃/재시작 후 알람 정책을 확인해야 한다. 추가 딸 폰 알람 발생 시험은 사용자 지시에 따라 진행하지 않는다.
- 기존 행 동시 편집의 마지막 저장 우선 정책은 수용 여부가 미확정이다. 이를 승인된 결정으로 취급하지 않는다.
- 결론: P6.8은 `in_review`다. 기기 확인과 정책 결정이 남아 있으므로 완료 조건을 충족했다고 볼 수 없다.

## 확인 질문

- 여러 기기에서 같은 기존 항목을 동시에 편집할 때 현재 기록된 마지막 저장 우선 정책을 수용할지 결정이 필요하다.
- 딸 계정에 여러 기기가 등록될 경우 어느 기기의 동기화 시각을 대표로 보여야 하는지 백로그 입력은 명시하지 않았다. 현재 작업 로그는 최신 `last_synced_at` 기기를 선택한다고 설명한다. 별도 정책이 필요한지 확인한다.
- 마지막 동기화가 오래된 상태의 경고 기준·문구는 기준 입력에서 정하지 않았다. 현재 표시 방식 외의 경고가 필요한지 확인한다.

## 확인 한계

- P6.16은 `needs_info`이며 완료 조건에 아빠 편집→딸 반영, 딸 완료 체크→아빠 현황 반영, 원격 보석 지급 및 장부 수량 불변, 아빠 로그아웃·재시작 뒤 알람 차단과 딸 로그인 시 허용 확인이 있다. 해당 실기기 검증은 아직 근거로 제시되지 않았다.
- P6.16 gate인 아빠 계정 로그인 기기와 기존 행 동시 편집 정책이 해결되지 않았다. P6.15 로그에는 “마지막 저장 우선”이 현재 동작으로 기록되어 있지만, 사용자 수용 여부는 미확정이므로 승인된 결정처럼 취급하지 않는다.
- 사용자 지시에 따라 추가 딸 폰 알람 발생 시험은 진행하지 않는다. P6.12도 `needs_info`이고, 전체화면 알람 및 장기간 서버 장애 범위는 미확인이다.
- 최신 1.54.6/145: 전체 check 74 suites/451 tests와 Android build 정상 종료. 별도 가족별 편집 시각 1건·lint·길이 검사 통과. 같은 가족 역할 전환·재로그인 시 이전 동기화 폐기, 역할 조회 실패 시 기존 알람 예약 보존. ARM64 릴리즈 버전·서명 검증 완료. P6.16 gate는 미해결이며 done 판정 대상이 아니다.
- 현재 확인 범위는 입력된 로그의 기록에 한정한다. 최신 ARM64 설치 완료 결과와 최종 코드 재리뷰 결과는 기준 JSON에 아직 없다.

- 1.54.6 리뷰 종료 결과: backlog-explainer 정상 종료, critical-reviewer 480초 시간 초과. 이번 리뷰는 완료 근거가 아니며 P6.16 gate도 미해결이다.
