## 작업 목적

아빠 계정으로 로그인한 기기에서 딸의 오늘 할 일 진행, 작은·큰 보석 수, 딸 폰의 마지막 동기화 시각을 볼 수 있게 한다. 아빠가 시간표와 할 일을 편집할 수 있는 진입점도 제공한다.

## 쉬운 설명

아빠가 앱에 로그인하면 아빠 화면이 열린다. 이 화면에서 딸의 할 일 현황과 보석 수, 딸 폰이 서버와 마지막으로 정보를 맞춘 때를 확인하고, 시간표·할 일 편집 화면으로 이동한다. 아빠 폰에서는 딸의 알림과 알람이 울리지 않도록 한다.

## 필요한 입력

- P6.6 동기화 기반: 완료. 서버 데이터를 로컬에 반영하고 로그인 기기 역할을 식별하는 흐름이 있다.
- P6.15 서버 우선 편집: 완료. 로그인 상태의 관리자 편집은 서버에 저장하고 동기화한다.
- P6.7 Realtime 및 앱 복귀 동기화: 완료. 아빠 화면의 현황을 다시 읽는 신호로 활용할 수 있다.
- 가족 구성원과 기기 상태: `tt_family_members`의 child 역할 및 `tt_devices`의 `last_synced_at`, `app_version`을 조회한다.
- 아빠 기기 역할: 로그인 상태와 저장된 역할 캐시를 이용해 앱 시작·백그라운드 예약 시에도 아빠 폰에서 딸 알림·알람을 막는다.

## 수행 순서

1. 아빠 역할로 로그인했을 때 아이 화면 대신 `ParentHome`을 표시한다.
2. 아빠 홈에서 기존 관리자 설정으로 이동하는 편집 버튼을 연결한다. 편집은 P6.15의 서버 우선 저장 규칙을 따른다.
3. 로컬 동기화 데이터를 읽어 오늘 할 일 진행과 작은·큰 보석, 목표 현황을 표시한다.
4. 서버에서 딸 역할 구성원과 기기 동기화 시각·앱 버전을 조회하고, 오류·기록 없음 상태도 표시한다.
5. 앱 복귀, 동기화/위젯 체크 반영, 수동 새로고침에서 현황을 다시 읽는다.
6. 아빠 역할의 알림·알람 예약 차단을 앱 시작 및 역할 전환 흐름에 연결한다.
7. 현황 계산·기기 조회·역할별 예약 동작의 테스트를 확인하고 전체 검증 및 리뷰를 수행한다.
8. 아빠 계정이 연결된 실기기에서 화면과 편집 진입 동작을 확인한다.

## done_when 확인 방법

백로그 완료 조건은 “아빠 화면에서 편집·현황·동기화 시각이 모두 표시됨”이다. 다음 근거를 대조한다.

1. 아빠 화면에 시간표·할 일 편집 진입점이 있고, 편집 화면으로 이동한다.
2. 아빠 화면에 딸의 오늘 할 일 진행 현황과 보석 현황이 표시된다.
3. 아빠 화면에 딸 폰의 마지막 동기화 시각이 표시된다. 기록이 없거나 조회에 실패한 경우도 오해 없이 구분한다.
4. 관련 테스트가 현황 계산, 기기 상태 조회, 아빠·딸·로컬 역할별 알림 예약 동작을 검증한다.
5. `npm run check` 결과와 등록된 리뷰 결과를 확인한다.
6. 아빠 계정 실기기에서 위 현황과 편집 진입을 확인한다. 실기기 확인이 끝나기 전에는 해당 근거를 완료로 기록하지 않는다.

- P6.15 검토에서 여러 기기의 동시 편집이 충돌하면 거부 후 서버 내용으로 다시 맞추기로 정했다. 아빠 화면에서 충돌 안내 또는 다시 맞추기 진입을 별도로 제공할지 여부는 P6.8 요구사항에 정해져 있지 않다. 필요 여부를 결정해야 한다.
