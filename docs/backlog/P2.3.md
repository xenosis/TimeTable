# P2.3 — 교시 시간 설정 화면

## 기준 입력

- 기준 백로그 schema version: `1.1`
- 기준 백로그 SHA-256: `de2559bc8bf037d9a28276b9343e6500e8780551c21551f2a828052b22a761a6`
- 기준 백로그 항목: `P2.3`
- 백로그 개발 상태: `done`
- 선행 작업: `P2.2`
- 구현 기준 버전: `1.6.4` (`versionCode 17`)
- 문서 상태: 구현 근거를 반영한 설명 문서 작성 완료. 문서화 완료와 개발 작업 완료는 별도로 관리한다.

## 목적

교시마다 시작 시각과 종료 시각을 입력하고 저장·조회할 수 있는 설정 화면을 제공한다. 백로그의 완료 기준은 “교시별 시작·종료 시각을 저장·조회 가능”이다.

## 쉬운 설명

처음 화면을 열면 저장된 교시를 불러오는 동안 편집 동작이 비활성화된다. 조회에 실패하면 다시 시도하기 전까지 저장도 차단된다. 불러오기가 끝나면 목록이 비어 있거나 저장된 교시가 표시되며, 사용자가 필요한 교시를 추가한 뒤 각 교시의 시작·종료 시각을 입력한다. 저장 중에도 편집 동작이 차단된다. 저장하기 전에는 마지막으로 추가한 입력 행만 `마지막 교시 지우기`로 제거할 수 있다. 저장할 때 입력 형식을 확인하고 같은 가족 범위와 교시 번호에 해당하는 행을 UPSERT한다. 화면을 다시 열면 해당 가족 범위의 저장된 교시가 교시 번호 순서로 표시된다.

## 필요한 입력

- 교시 번호: 1 이상인 정수이며 목록 안에서 중복되지 않아야 한다.
- 초기 교시 목록: 빈 목록. 필요한 교시는 화면의 `교시 추가` 동작으로 추가한다.
- 각 교시의 시작 시각과 종료 시각: `HH:MM` 형식의 24시간 시각.
- 종료 시각은 시작 시각보다 늦어야 한다.
- 조회·저장 범위 식별자: `familyId`이며, 전달하지 않으면 `local-family`를 사용한다.
- 화면 입력 및 저장 대상 DB: `getDatabase()`가 제공하는 SQLite 데이터베이스.

  - 화면 안내 문구의 UTF-8 한글 표시
  - 초기 교시 조회 중 편집 동작 비활성화
  - 초기 조회 실패 후 재시도 전 저장 차단

  - `familyId` 조건의 교시 조회
  - 트랜잭션과 `(family_id, period_no)` 충돌 조건을 이용한 UPSERT 저장

## 수행 순서

1. `P2.2`에서 준비된 `periods` 테이블과 DB 연결을 사용한다.
2. 설정 화면이 저장된 교시를 불러오는 동안 입력·추가·삭제·저장 편집 동작을 비활성화한다.
3. 조회에 실패하면 재시도 전까지 저장을 차단하고, 다시 불러오기 동작을 안내한다.
4. 조회가 끝나면 빈 목록 또는 `familyId` 범위의 기존 교시를 교시 번호 순서로 표시한다.
5. 사용자가 필요한 교시를 추가한 뒤 교시 번호별 시작·종료 시각을 입력한다.
6. 저장하기 전 필요하면 마지막으로 추가한 입력 행만 지운다.
7. 저장 전에 교시 번호가 양의 정수이고 중복되지 않는지 확인한다.
8. 저장 전에 시작·종료 시각이 `HH:MM` 형식이며 종료 시각이 시작 시각보다 늦은지 확인한다. 형식·순서 오류는 해당 입력 안내로 표시한다.
9. 검증을 통과하면 편집 동작을 차단하고 `BEGIN IMMEDIATE`로 저장을 시작하며, 각 교시를 `(family_id, period_no)` 기준으로 UPSERT한다.
10. 모든 UPSERT가 성공하면 `COMMIT`하고 저장 결과를 알린다. DB 등 저장 과정의 오류는 입력 형식 오류와 구분해 저장 실패로 안내하고 롤백한다.
11. 화면을 다시 조회해 저장된 교시 목록을 확인하고, 참조된 시간표 항목의 외래 키가 유지되는지 저장 방식으로 보장한다.

## done_when 확인 방법

다음 근거로 백로그의 완료 기준을 대조한다.

- `PeriodSettings.tsx`에서 교시별 시작·종료 시각을 입력하고 저장할 수 있다.
- `periodRepository.ts`의 `savePeriods`가 교시별 시각을 `periods`에 저장한다.
- `periodRepository.ts`의 `getPeriods`가 `familyId` 조건으로 저장된 교시를 교시 번호 순서로 조회한다.
- 저장은 `(family_id, period_no)` 충돌 시 시작·종료 시각을 갱신하는 UPSERT를 하나의 트랜잭션으로 수행하며, 실패 시 롤백한다. 기존 행을 일괄 삭제하지 않으므로 참조된 시간표 항목의 외래 키를 깨지 않는다.
- 첫 화면은 빈 목록으로 시작하고, 필요한 교시만 추가할 수 있다.
- 저장하기 전 `마지막 교시 지우기`로 마지막으로 추가한 입력 행만 제거할 수 있다.
- 교시 번호와 `HH:MM` 시각·시각 순서 검증이 저장 전에 수행된다.
- 입력 형식·순서 오류 안내와 DB 저장 실패 안내가 서로 구분된다.
- 화면 안내 문구가 UTF-8 한글로 표시된다.
- 초기 교시 조회가 끝날 때까지 편집 동작이 비활성화된다.
- 초기 조회 실패 시 재시도 전까지 저장할 수 없다.
- 저장 중 편집 동작이 비활성화된다.
- 구현 기준 버전은 `1.6.4`, `versionCode 17`이다.
- 보완된 `1.6.4` (`versionCode 17`) 기준으로 최종 전체 품질 검사(`npm run check`)가 통과했다.

위 근거가 확인되면 “교시별 시작·종료 시각을 저장·조회 가능” 조건을 충족한 것으로 판단한다. 이 문서는 해당 판단을 기록하지만 백로그 상태를 변경하지 않는다.
