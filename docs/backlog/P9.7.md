## 수행 순서

1. 계획 문서의 폭·방향·글자 배율·데이터 조건을 준비한다: 360dp/393dp, 세로·가로, 배율 1.0/1.3, 평일 총 20개 일정, 저장 시간표 `평소`·`방학`·`2학기`, 긴 한글 제목·메모, 주말 일정, 반복/특정 날짜/완료 이력 할 일.

2. 기본 화면과 보조 화면을 펼친 상태에서 비교한다. 보조 화면은 교시·요일 복사·보상·PIN·관리자 권한 안내·진단을 포함한다.

3. PIN·백그라운드 재잠금·세트 분리·CRUD·반복 종료·요일 매핑·알림/위젯 및 아이 화면 회귀를 확인한다.

4. 계획 및 백로그에서 요구한 테스트, 전체 품질 검사, 등록된 병렬 리뷰, 화면 비교와 수동 절차 근거를 기록한다. 사용자 실기기 확인 전에는 그 항목을 완료로 기록하지 않는다.

## 완료 조건 및 확인 방법

백로그 done_when 원문:

> docs/admin-compact-plan.md 확인 기준 전부 대조. 기본 폭/글자에서 요일 한 줄·하루 목록4개·3개 세트행180dp 기준 충족, 확대 글자/키보드 조작 가능. PIN·세트분리·CRUD·반복종료·요일매핑·알림/위젯·아이화면 회귀와 npm run check 및 병렬 리뷰 근거 기록. 사용자 실기기 확인 전에는 해당 확인을 완료로 기록하지 않고 needs_info로 관리. 비교 스크린샷/수동 절차와 버전 동시 수정 확인.

확인 방법: 360dp와 393dp, 세로와 가로, 배율 1.0과 1.3에서 기본 화면을 캡처해 비교하고 교시·요일 복사·보상·PIN·관리자 권한 안내·진단을 각각 펼친 상태의 화면도 비교한다. 짧은 세트명 `평소`, `방학`, `2학기`로 세 행 합계 180dp 기준을 확인하고 긴 세트명은 별도 확인한다. 계획 문서의 나머지 화면·입력·기능 회귀 기준, 검사·리뷰 근거, 버전 동시 수정 및 수동 절차를 대조한다. 에뮬레이터와 실기기 근거를 구분하며 사용자 실기기 확인 전에는 완료로 표시하지 않는다. **현황: 에뮬레이터 기본 확인 완료. 360/393dp 직접 확인 및 세트 목록 펼친 상태는 미확인. 검증 작업 미착수.**
