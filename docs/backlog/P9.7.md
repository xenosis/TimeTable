# P9.7 — 관리자 화면 밀도와 입력·기능 회귀 검증

## 기준 입력 및 현재 상태

- 백로그 schema version: `1.1`
- 백로그 SHA-256: `1efc75d2e5a3536986545592fdc55ce541f68e04b24e3e290aacd03713655a06`
- 기준 항목: P9.7, 상태 `in_progress`
- 상위 작업: P9 관리자 화면 컴팩트화
- 선행 작업: P9.3, P9.5, P9.6 (모두 `done`)
- 수행 위치: `docs/manual-device-tests.md`, `docs/admin-compact-plan.md`, `__tests__/`
- 상세 기준: [관리자 화면 컴팩트화 작업안](../admin-compact-plan.md)

P9.7은 P9.2~P9.6의 구현 완료 여부를 다시 만드는 작업이 아니라, 관리자 화면의 실제 밀도·입력 흐름과 기존 기능 회귀를 계획 기준에 따라 확인하고 근거를 남기는 작업이다. 에뮬레이터 결과, S23 Ultra 결과, 지정 딸 폰(SM-A245N) 결과를 서로 구분한다.

## 목적

기본 폭과 글자 크기에서 관리자 화면이 짧고 한눈에 읽히는지, 키보드가 열린 상황에서도 입력·저장·취소가 가능한지 확인한다. 글자 배율 1.3은 수용된 사용자 결정에 따라 필수 완료 조건에서 제외한다. PIN 보호, 시간표·할 일 기능, 알림·위젯, 아이 화면이 관리자 화면 변경으로 깨지지 않았는지도 함께 회귀 확인한다.

## 쉬운 설명

관리자 화면을 작은 화면과 큰 화면, 세로와 가로에서 실제로 살펴본다. 평일 일정이 많고, 이름이 긴 시간표와 완료 이력이 있는 할 일을 넣어도 필요한 내용을 찾고 편집할 수 있는지 확인한다. PIN을 다시 요구하는지와 저장한 내용이 아이 화면·알림·위젯에 그대로 이어지는지도 확인한다. 화면을 본 기기가 에뮬레이터인지 어느 실기기인지 기록해 증거의 범위를 분명히 한다.

## 필요한 입력

- 계획 기준: `docs/admin-compact-plan.md`의 공통 크기·요일 선택·할 일·시간표 목록·세트 선택·편집 폼·회귀 확인 기준
- 수동 절차와 관련 회귀 항목: `docs/manual-device-tests.md`
- 선행 구현 및 테스트: P9.3 할 일 폼, P9.5 시간표 세트 선택, P9.6 시간표 편집 폼
- 화면 폭 360dp/393dp, 세로/가로, 글자 배율 1.0 확인 환경 (1.3은 사용자 결정으로 필수 검사에서 제외)
- 검증 데이터: 평일 20개 일정, 저장 세트 3개(짧은 이름과 긴 한글 이름), 긴 한글 제목·메모, 주말 일정, 반복·특정 날짜·완료 이력이 있는 할 일
- 비교 스크린샷과 화면별 입력·기능 확인 결과

기기 상태나 확인 방법이 명시되지 않은 항목은 확인 질문으로 남긴다. 계획에 없는 데이터 변경 정책은 추가하지 않는다.

## 결과물

- `docs/backlog/P9.7.md`의 확인 기록과 미확인 사항
- `docs/manual-device-tests.md`의 재현 가능한 실기기 수동 절차 및 결과 보강
- `docs/admin-compact-plan.md` 기준별 대조 결과와 비교 스크린샷 참조
- 관련 자동 검사 및 병렬 리뷰의 실제 실행 근거
- 구현 변경이 필요하면 관련 화면·테스트 수정과 버전 파일 동시 갱신 근거

화면 확인 결과는 기기/환경, 앱 버전, 화면 방향·폭·글자 배율, 준비 데이터, 수행 동작, 실제 결과를 묶어 기록한다. 확인하지 않은 항목은 통과로 간주하지 않는다.

## 수행 순서

1. `docs/admin-compact-plan.md`의 확인 기준을 항목별 체크리스트로 만들고, P9.3/P9.5/P9.6의 기존 결정과 완료 기록을 읽는다.
2. 안전한 검증 데이터를 준비한다: 평일 총 20개 일정, 3개 시간표 세트, 긴 한글 제목·메모, 주말 일정, 반복·특정 날짜·완료 이력 할 일. 테스트 항목은 식별 가능한 이름을 붙이고 검증 뒤 정리한다.
3. 계획서 기준에 따라 360dp와 393dp의 세로·가로 및 기본 글자 크기 1.0을 비교한다. 글자 배율 1.3은 수용된 사용자 결정에 따라 필수 완료 검사에서 제외한다. 기본 화면과 보조 화면(교시, 요일 복사, 보상, PIN/권한 안내, 진단·기기 테스트)을 펼친 화면을 캡처한다.
4. 기본 크기 기준을 대조한다: 요일 선택 한 줄, 하루 일정 목록 4개, 짧은 이름 세트 3행 합계 180dp 이내. 확대 글자와 키보드가 열린 상태에서 긴 한글 입력, 저장, 취소, 모달 닫기·전환이 가능한지 확인한다.
5. 회귀를 확인한다: PIN 진입·재잠금, 세트 간 데이터 분리와 적용 유지, 일정/할 일 CRUD와 반복 종료, 요일 매핑, 저장 후 알림·위젯 갱신, 아이 화면 반영. 기본 관리자 화면에서 기기 테스트 UI가 숨겨지고 기타 영역에서 PIN 보호 아래 접근되는지도 대조한다.
6. 자동 회귀·전체 검사와 등록된 critical-reviewer/backlog-explainer 결과를 확인한다. 코드 변경이 있었다면 검사와 리뷰를 변경 후 기준으로 다시 확인하고 버전 변경 여부를 확인한다.
7. 남은 확인을 기기별로 표시한다. 사용자 실기기 확인이 남아 있으면 `needs_info`로 관리하며, 사용자 딸 폰 확인을 다른 기기나 에뮬레이터 결과로 대체 기록하지 않는다.

## done_when 확인 방법

백로그 완료 조건:

> docs/admin-compact-plan.md 확인 기준 전부 대조. 기본 폭/글자에서 요일 한 줄·하루 목록4개·3개 세트행180dp 기준 충족, 확대 글자/키보드 조작 가능. PIN·세트분리·CRUD·반복종료·요일매핑·알림/위젯·아이화면 회귀와 npm run check 및 병렬 리뷰 근거 기록. 사용자 실기기 확인 전에는 해당 확인을 완료로 기록하지 않고 needs_info로 관리. 비교 스크린샷/수동 절차와 버전 동시 수정 확인.

대조 판정은 계획 문서의 각 확인 기준에 대해 `통과`, `실패`, `미확인` 중 하나와 근거를 기록한다. 기본 폭 기준은 360/393dp 및 기본 글자 크기 화면에서 재고, 세트 행 높이는 세 행 합계를 확인한다. 확대 글자·키보드 조작은 실제 폼에서 입력·저장·취소까지 수행한다. 기능 회귀는 해당 동작의 저장 결과와 앱 재진입 후 결과를 확인하고, 알림·위젯은 갱신 결과를 별도로 기록한다. 자동 검사와 병렬 리뷰는 실행 기록 자체를 확인하며 다른 P9 작업의 근거를 P9.7 실행 근거로 대신하지 않는다. 버전 확인은 변경이 있었을 때 `app.json`, `package.json`, 존재하는 Android `versionCode`/`versionName`의 동시 반영 여부를 대조한다.

## 현재 확인 기록

백로그 기준 입력에 기록된 이전 확인:

- 에뮬레이터: 관리자 영역 메뉴·편집 모달·할 일 폼 확인.
- 이전 전체 검사 기록: `npm run check` 268개 통과.
- 당시 미확인으로 기록된 항목: 360/393dp 및 가로 직접 확인, 보상·교시·요일 복사·진단 영역 밀도, 키보드 상태의 저장/취소, 지정 딸 폰 확인.

2026-10-04 최신 기기 기록(`docs/device-verification-2026-10-04.md`)에 따라 S23 Ultra에서 관리자 PIN 첫 탭 진입, 할 일 한글 입력, 버림 확인 뒤 계속 편집, 수정 저장과 목록 반영을 확인했다. 검증용 항목은 정리했고 원래 할 일·보석 장부는 보존했다. 요일 선택기 수정 뒤 이름 입력 직후 일요일을 한 번 탭해 선택 상태가 바뀌는 것도 확인했다.

이전 버전에서 관리자 루트의 KeyboardAvoidingView와 공개 API 헤더 높이 처리로 전체 검사 48 suites/313 tests, lint, typecheck, Android debug build가 통과했고, ARM64 오프라인 APK를 S23 Ultra에 재설치했다. 최신 후속 전체 검사와 PC 실기 절차 결과는 아래 보완 기록에 따로 적는다. 원래 기기 설정 font 0.8·density 560·회전값은 검증 뒤 복원했다. 요일 선택 후 저장/취소를 끝까지 실행한 최신 실기기 응답은 아직 확인되지 않았다. 앱에서 키보드가 버튼 영역을 가리는 문제가 관측된 이전 저장 시도는 성공 증거가 아니다.

mandatory dispatcher의 두 역할은 종료됐지만, 동시에 생성된 root APK 3개 변경 때문에 freeze 검증이 실패했다. 따라서 P9.7 병렬 리뷰 성공으로 기록하지 않는다. 실제폰 검증에 집중하라는 요청에 따라 다른 앱 입력/터치와의 간섭을 피하면서 추가 기기 응답을 기다린다. S23 Ultra 근거는 이 기기에 한정되고, 지정 딸 폰 SM-A245N과 전면 관리자 회귀는 확인되지 않았다.

기준 입력의 최신 로그(2026-10-04 11:41:32Z)는 S23 Ultra에서 관리자 PIN 해제 뒤 1.45.0/106의 실제 관리자 화면을 대상으로 시간표·할 일·보상·기타 영역, 밀도·입력·저장·취소·PIN 재잠금 회귀 확인을 시작했다고 기록한다. 테스트 데이터만 생성·정리하고 기기 원래 font 0.8·density 560·회전 설정을 보존하는 방침이다. 이 로그는 착수 기록이며 각 항목의 결과를 입증하지 않으므로 완료 근거로 세지 않는다.

따라서 현재 기록만으로는 P9.7 완료를 판정할 수 없다. 실기기에서 이미 확인한 S23 Ultra 근거는 해당 기기 범위로만 기록하고, 지정 딸 폰(SM-A245N) 확인 여부는 별도로 남긴다. 확인 질문: 최신 착수 기록에 적힌 각 영역·저장/취소·PIN 재잠금 검증의 관찰 결과와 비교 캡처 위치는 무엇인가? 딸 폰 확인은 아직 수행되지 않았는가? 답이 없는 항목은 미확인으로 둔다.
