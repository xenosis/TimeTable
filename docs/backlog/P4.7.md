# P4.7 — 스티커판 · 보상 화면

## 기준 입력

- 백로그 schema version: `1.1`
- 백로그 SHA-256: `ce397694b89b129a75857c86108452a0d162614ad59a9067d3f2fb9da6f384b8`
- 기준 입력 경로: `C:\Users\Lenovo\claudeProjects\TimeTable\backlog.json`
- 기준 입력 크기: `120456` bytes
- 기준 입력 수정 시각: `2026-09-19T01:22:05.390Z`
- 항목 상태: `in_review`
- 항목 담당: `codex`
- 항목 위치: `app/`

## 작업 목적

모은 스티커의 합계와 보상 목표까지 남은 개수를 아이가 이해하기 쉬운 화면에 표시한다. 화면은 현재 활성 테마의 독자적인 스티커 스타일을 사용한다.

## 쉬운 설명

아이가 모은 보석이 몇 개인지, 다음 보상까지 몇 개가 더 필요한지 한눈에 보는 스티커판이다. 테마를 바꾸면 스티커 모양과 꾸밈도 그 테마에 맞춰 보여야 한다.

## 필요한 입력

- P4.6의 스티커 원장·보상 계산 결과와 화면 연동 결과.
- P1.9의 테마 정의·레지스트리·스티커 토큰 및 의미 키 해석 계약.
- P4.1에서 확정한 보상 정책: 개별 할 일 보상 없음, 최초 전체 완료 1일과 7일 연속 완료에 일반 보석 각 1개, 이후 30일 연속 완료마다 큰 보석 1개.
- 활성 테마의 스티커 스타일과 보상 목표를 표시하는 앱 화면 구현 결과.

백로그에 없는 보상 종류, 추가 목표, 표시 문구, 애니메이션 동작은 임의로 추가하지 않는다.

## 결과물

- `app/` 범위의 스티커판·보상 화면.
- 스티커 합계가 원장/계산 결과와 일치하여 표시됨.
- 현재 보상 목표와 목표까지 남은 개수가 표시됨.
- 활성 테마의 독자 스티커 스타일이 화면에 적용됨.
- 구현 및 검증 근거를 이 문서에 기록함.

## 선행 작업

- `P4.6` 스티커 적립: 기준 입력상 `needs_info`. 구현·원장 재계산·자동 검사는 완료되었으나 사용자 실기기 확인이 남아 있다.
- `P1.9` 테마 계약·레지스트리: 기준 입력상 `done`. 테마 정의와 독립적인 스티커/장식 토큰을 사용할 수 있는 상태다.

P4.6의 실기기 확인 결과가 P4.7 완료 전이의 의존성 조건에 영향을 줄 수 있음을 함께 확인한다.

## 수행 순서

1. 지정된 schema version과 SHA-256의 P4.7 항목 및 선행 작업 상태를 확인한다.
2. P4.6의 스티커 합계·보상 목표 계산 결과와 P1.9의 활성 테마 토큰을 연결한다.
3. 스티커 합계와 보상까지 남은 개수를 `app/` 화면에 표시한다.
4. 활성 테마를 바꾸었을 때 독자 스티커 스타일이 렌더링되는지 확인한다.
5. 보상 목표가 없거나 계산 결과를 읽지 못하는 경우는 요구사항에 없는 값을 만들지 말고 확인 질문으로 남긴다.
6. 구현 검사와 등록된 검토 결과를 확인하고 현재 기록을 갱신한다.

## done_when 확인 방법

다음을 기준 입력의 `done_when`과 직접 대조한다.

1. 스티커 합계가 실제 원장/계산 결과와 같은지 확인한다.
2. 보상 목표까지 남은 개수가 목표 및 현재 합계에 맞게 표시되는지 확인한다.
3. 활성 테마의 독자 스티커 스타일이 화면에 적용되는지 확인한다.

확인한 코드·테스트·사용자 확인의 근거와 미확인 사항을 기록하며, 기준 `done_when`에 없는 추가 완료 조건은 만들지 않는다.
