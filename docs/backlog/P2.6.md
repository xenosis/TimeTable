# P2.6 — 항목 편집: 추가 · 수정 · 삭제

## 기준 입력

- 기준 백로그 schema version: `1.1`
- 기준 백로그 SHA-256: `de2559bc8bf037d9a28276b9343e6500e8780551c21551f2a828052b22a761a6`
- 기준 백로그 항목: `P2.6`
- 백로그 개발 상태: `done`
- 선행 작업: `P2.2`, `P1.9`
- 문서 상태: 구현 및 검사 근거를 반영한 설명 문서 작성 완료. 문서화 완료와 개발 작업 완료는 별도로 관리한다.

## 목적

시간표 항목을 추가·수정·삭제할 수 있는 편집 UI와 저장소를 제공한다. 요일을 하나 이상 선택하고, 교시 또는 유효한 직접 입력 시간, 과목명, 일정 종류(category), 테마 독립 의미 색·아이콘 키, 알림 방식과 미리 알림 시간을 저장한다. 백로그의 완료 기준은 “시간표 항목 CRUD가 모두 동작하고 색·아이콘은 테마 독립적인 의미 키로 저장됨”이다.

## 쉬운 설명

사용자는 새 항목 입력을 시작할 때 빈 초안으로 초기화된 과목명·일정 종류·요일·시간·색·아이콘·알림 값을 입력한다. 교시를 선택하거나 시작·종료 시각을 직접 입력하고, 종료 시각이 시작 시각보다 늦은지 확인한 뒤 저장한다. 기존 항목을 목록에서 고르면 저장된 category와 나머지 내용을 유지한 채 한 요일의 항목을 수정하거나 삭제할 수 있다. 여러 요일을 한 번에 추가하면 선택한 요일마다 항목이 만들어진다. 저장하거나 삭제하면 편집기 목록과 오늘 화면이 다시 조회되며, 이전 조회 결과가 늦게 도착해 최신 오늘 화면을 덮어쓰지 않도록 처리하고 재조회 실패는 오류로 안내한다.

## 필요한 입력

- SQLite DB 연결: `getDatabase()`가 제공하는 DB.
- 항목 제목과 하나 이상의 요일(0~6).
- 일정 종류: `school`, `academy`, `life` 중 하나.
- 시간 방식: 양의 교시 번호 또는 `HH:MM` 형식의 시작·종료 시각. 직접 입력 방식은 종료 시각이 시작 시각보다 늦어야 한다.
- 테마 독립 의미 키: `colorKey`, `iconKey`.
- 알림 방식: `none`, `notify`, `alarm` 중 하나.
- 미리 알림 분: 0 이상의 정수.
- 수정·삭제 시 양의 항목 ID와 기본 `familyId`인 `local-family`.

## 수행 순서

1. 선행 작업 `P2.2`의 `timetable_items` 구조와 `P1.9`의 의미 색·아이콘 키 계약을 사용한다.
2. 새 항목 입력 동작은 빈 초안으로 명시적으로 초기화한다.
3. DB에서 현재 가족 범위의 편집 가능한 항목을 조회하고 목록에 표시한다.
4. 새 항목에 제목, 일정 종류, 하나 이상의 요일, 교시 또는 직접 시간, 의미 색·아이콘, 알림 설정을 입력한다.
5. 입력값을 검증한 뒤 선택한 각 요일에 항목을 생성하고, 복수 생성은 하나의 트랜잭션으로 커밋하거나 실패 시 롤백한다.
6. 기존 항목을 선택하면 해당 항목의 category를 포함한 저장값을 불러오고, 한 요일만 수정해 같은 가족 범위와 ID로 저장한다. 삭제 동작은 같은 범위의 항목만 삭제한다.
7. 교시 방식과 직접 시간 방식의 상호 배타성, `HH:MM` 형식과 종료 시각의 순서, 제목·요일·category·알림 값 검증 결과를 안내한다.
8. 저장·삭제 후 편집기 목록을 다시 조회하고 새로고침 신호를 전달해 오늘 화면도 최신 내용을 반영한다. 이전 요청의 늦은 응답은 무시하고 재조회 실패는 오류 문구로 표시한다.
9. 관련 단위 테스트와 최신 `npm run check`를 실행한다.

## done_when 확인 방법

다음 근거로 백로그의 완료 기준을 대조한다.

- `TimetableEditor`에서 항목 목록 조회, 새 항목 추가, 기존 항목 선택 후 수정, 삭제가 가능한지 확인한다.
- 여러 요일을 선택한 추가 요청이 선택한 요일별 항목을 트랜잭션으로 생성하는지 확인한다.
- 기존 항목 수정은 한 요일만 대상으로 하며 저장된 category가 수정 후에도 보존되는지 확인한다.
- 새 항목 입력 동작이 기존 항목의 값이 남지 않는 빈 초안으로 초기화되는지 확인한다.
- 교시 방식 또는 직접 시간 방식이 저장되고, 두 방식을 동시에 사용하지 못하며 직접 입력의 종료 시각이 시작 시각보다 늦어야 하는지 입력 검증을 확인한다.
- 제목, 요일, category, 시각, 알림 방식, 미리 알림 분의 필수·범위 검증이 적용되는지 확인한다.
- 수정·삭제가 `familyId`와 항목 ID 범위 안에서 실행되는지 확인한다.
- `color_key`, `icon_key`가 테마의 실제 색상·glyph가 아닌 의미 키로 저장되고, 편집 UI가 활성 테마 해석값을 보여 주는지 확인한다.
- 저장·삭제 후 편집기 목록과 오늘 화면이 다시 조회되어 최신 내용을 표시하는지 확인한다.
- 이전 오늘 화면 조회 결과가 늦게 도착해 최신 결과를 덮어쓰지 않으며, 재조회 실패 시 오류 문구가 표시되는지 확인한다.
- 최종 전체 품질 검사 `npm run check`가 통과했다: 지침 동기화, 파일 길이, lint, typecheck, Jest 31개, Android x86_64 debug build.
- 최종 확인 결과, `done_when` 조건과 선행 작업·검증 근거가 모두 확인되어 백로그 개발 상태가 `done`으로 기록되었다.
