# P7 마무리 · 배포

- schema version: `1.1`
- 기준 입력 SHA-256: `9fd62d6123685111ae43be0ee903cae351175ba1735d0ec1e48a281ba459a702`
- 입력 수정 시각: `2026-10-12T11:18:12.974Z`
- 기준 상태: `done`

## 목적

양쪽 기기에 정식 릴리즈 앱을 설치하고, 이후 같은 서명으로 업데이트할 절차를 확립한다. 완료 판단에는 설치 및 업데이트 문서와 회귀 확인 기록을 사용하며, 직접 시험한 결과와 사용자가 수용한 검증 범위를 구별한다.

## 쉬운 설명

딸 폰과 아빠 폰에 배포용 앱이 설치되어 있는지 확인하고, 다음 버전으로 안전하게 업데이트하는 방법을 문서로 남기는 단계다. 확인하지 않은 항목은 확인한 것처럼 쓰지 않고, 사용자가 패스로 수용한 범위는 그 결정으로 기록한다.

## 필요한 입력

- P6 완료 상태
- P7.1~P7.6의 상태, 로그, evidence
- 양쪽 폰의 릴리즈 APK 설치 기록과 패키지·ABI·서명 비교 결과
- `docs/build-commands.md`의 빌드 및 업데이트 절차
- 회귀 및 테마 확인 기록과 사용자의 검증 수용·취소 결정
- 부모 완료 조건과 하위 작업 근거를 대조한 등록 리뷰

## 결과물

- 두 기기의 릴리즈 설치 근거
- 같은 서명과 앱 데이터 보존을 다루는 업데이트 절차 문서
- 회귀·테마 검증의 직접 확인, 자동 검사, 사용자 수용 및 미실시 범위 기록
- 부모 완료 조건과 하위 작업을 대조한 리뷰 가능한 근거

## 선행 작업

- P6 서버 연동: `done`
- P7.1 앱 꾸미기: `done`
- P7.2 양쪽 기기 설치: `done`
- P7.3 빌드·업데이트 절차 문서화: `done`
- P7.4 회귀 테스트: `done` (일부 항목은 사용자 수용으로 통과 처리)
- P7.5 테마 회귀 확인: `done`
- P7.6 서명 키 외부 백업: `cancelled` (사용자가 PC 밖 백업을 하지 않기로 결정)

## 수행 순서

1. P6와 P7.1의 완료 상태 및 관련 근거를 확인한다.
2. P7.2에서 아빠·딸 폰의 릴리즈 설치 버전과 성공 기록, 패키지·ABI 및 서명 일치 여부를 확인한다. 아빠 폰의 최신 버전 업데이트는 사용자가 보류했으므로 추가 완료 조건으로 취급하지 않는다.
3. P7.3의 `docs/build-commands.md`에서 빌드 대상 구분, 릴리즈 서명 재사용, 업데이트 절차를 확인하고 P7.6 취소 결정을 함께 기록한다.
4. P7.4의 회귀 근거와 P7.5의 테마 근거를 살핀다. 직접 확인, 자동 검사, 사용자 수용, 미실시를 구분하고 사용자 수용을 실측 PASS로 표현하지 않는다.
5. P7.4 기록에 포함된 임시 데이터 정리, 딸 폰 동기화 완료, 할 일 없음 및 알림·알람 예약 0건 근거를 대조한다.
6. P6 선행 조건, P7.1~P7.6 상태, 부모의 `done_when`을 함께 검토하고 등록 리뷰 결과를 확인한다.

## done_when 확인 방법

“정식 설치, 업데이트 절차 확립”은 다음 근거로 확인한다.

- 아빠 폰과 딸 폰에 릴리즈 APK 설치 성공 기록이 있다.
- 두 APK의 패키지명과 ABI가 맞고 서명 인증서가 동일하다는 대조 기록이 있다.
- `docs/build-commands.md`에 빌드 및 업데이트 절차가 기록되어 있다.
- P6가 `done`, 필수 하위 P7.1~P7.5가 `done`이며, P7.6은 사용자 결정에 따른 `cancelled`로 확인된다.
- P7.4·P7.5 근거에서 미실시 시험과 사용자 수용 범위를 실제 통과 결과와 구별한다.
- 부모 등록 리뷰 결과를 확인한다. 이 설명 문서는 리뷰 완료나 상태 변경 자체를 증명하지 않는다.

## 현재 확인 기록

- 기준 입력에서 P6은 `done`, P7 부모는 `done`다.
- P7.1~P7.5는 `done`; P7.6은 외부 백업을 하지 않겠다는 사용자 결정으로 `cancelled`다.
- P7.2: 아빠 폰 1.63.2/182 및 딸 폰 1.63.5/185의 릴리즈 설치 성공이 기록됐다. 양쪽 APK는 `com.chaea.timetable`, ARM64이며 서명 인증서 SHA-256이 일치한다. 아빠 폰 최신 업데이트는 사용자 보류 상태다.
- P7.3: `docs/build-commands.md`에 빌드·업데이트 절차가 기록되어 있다. 외부 백업 위치 기록은 P7.6 범위였고 해당 작업은 취소됐다.
- P7.4: 사용자가 업데이트 중 이상이 없었다고 알리고 회귀 항목을 패스로 수용했다. 1.63.5 자동 검사(93개 묶음, 테스트 557개, Android 빌드, 푸시 테스트 13건)와 기존 실기기 근거가 재사용됐다. 알람 재시험, 실제 알림 탭 6개 조합 및 원래 전체 수동 절차는 이번에 실행하지 않았으며 실측 PASS가 아니다.
- P7.4 기록에는 임시 서버 데이터 정리와 재연결 후 딸 폰의 동기화 종료, 할 일 없음, 활성 시간표·할 일 알림/알람 예약 0건을 직접 확인한 근거가 있다.
- P7.5 지원 테마 회귀 결과는 완료 근거에 기록됐다.
- 부모 작업은 `done`이다. 등록 리뷰 두 역할이 정상 종료했고 Critical/High 지적이 없었다고 완료 로그와 evidence에 기록되어 있다. P7.4 사용자 수용과 실제 PASS의 차이, P7.6 취소가 완료 근거에 명시되어 있다.

## 확인 질문

- 없음. 기록되지 않은 실측 결과를 추가로 주장하지 않는다.
