# P3.2 — 알림 채널: 일반 알림용 · 알람용

## 기준

- 백로그 schema: 1.1
- 백로그 schema version: `1.1`
- 백로그 SHA-256: `5b0e5d95fcf9ccc7f631c2a2524419fb60a065176d16be52e41770fcbdacf190`
- 기준 항목: `P3.2`
- 상태(기준 입력): `in_review`
- 원본 `backlog.json`과 프로그램 코드는 이 문서 갱신의 대상이 아님

## 작업 목적

Android 8 이상에서 사용할 알림 채널을 일반 알림용과 전용 알람용으로 분리하고, 앱 시작 시 두 채널이 생성되도록 연결한다. P3.2의 완료 조건은 “일반/알람 채널이 앱 시작 시 생성됨”이다.

## 쉬운 설명

알림을 한 종류로 섞지 않고, 평소 알림과 크게 울리는 알람을 각각 별도 통로에 등록한다. 앱을 켤 때 두 통로를 미리 만들어 두면 이후 알림이나 알람을 예약할 때 Android가 올바른 채널을 사용할 수 있다.

## 필요한 입력

- P3.2 백로그 항목의 `summary`, `deps`, `done_when`, `where`.
- 선행 작업 P3.1의 권한 안내·재안내 구현 및 검토 결과.
- 기존 일반 알림과 전용 Kotlin 알람 경로의 채널 생성 연결 지점.
- Android 8+ 알림 채널 요구사항과 프로젝트의 알림·알람 설계 기준.
- 세부 채널 ID, 이름, 중요도 등 백로그에 명시되지 않은 값은 요구사항 확인 없이 임의로 확정하지 않는다.

## 결과물

- 앱 시작 시 일반 알림 채널이 생성되는 연결.
- 앱 시작 시 전용 알람 채널이 생성되는 연결.
- 두 채널이 구분되어 예약 경로에서 사용되는 구현 확인 기록.
- 완료 조건과 실제 검증 결과를 대조한 이 문서.

## 선행 작업

- 직접 선행 작업: `P3.1` — 권한 안내 화면.
- P3.1의 현재 구현·검토 결과를 확인한 뒤 P3.2를 최종 검토한다.
- P3.2의 상위 작업은 `P3`이며, 직접 의존성은 `P3.1`이다.

## 수행 순서

1. 기준 입력의 P3.2 범위와 `done_when`을 확인한다.
2. P3.1 선행 결과와 기존 일반 알림·전용 알람 경로를 확인한다.
3. 두 채널을 앱 시작 시 생성하도록 연결한다.
4. 일반 알림과 알람이 각각 의도한 채널을 사용하는지 대조한다.
5. 앱 시작 시 두 채널 생성 여부와 미확인 사항을 기록한다.
6. 검토·검증 결과를 완료 근거로 정리하되 추가 확인 사항은 질문으로 남긴다.

## done_when 확인 방법

다음 두 조건을 모두 확인한다.

- 일반 알림용 채널이 앱 시작 시 생성된다.
- 전용 알람용 채널이 앱 시작 시 생성된다.

앱 시작 경로의 채널 생성 호출, 각 예약 경로의 채널 참조, Android 8+ 등록 결과를 구현·검증 기록으로 대조한다. 백로그에 없는 별도 완료 조건은 추가하지 않는다.
