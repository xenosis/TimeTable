## 목적

사용자 결정(2026-09-30): 방학 돌봄은 학교도 학원도 생활도 아니므로 일정 종류에 '돌봄'을 별도로 추가한다. 돌봄을 학교로 잘못 입력하면 위젯에서 사라지는 위험도 없앤다. timetable_items.category의 CHECK 제약(school·academy·life)은 SQLite에서 바로 고칠 수 없으므로 테이블을 다시 만들어 데이터를 옮기는 마이그레이션(V10)이 필요하다. 타입(TimetableCategory)에 care를 추가하고 편집기 종류 버튼을 학교·학원·돌봄·생활 순으로 보인다. 위젯은 학교만 빼므로 돌봄은 그대로 보인다. 색·아이콘 체계(colorKey·iconKey)는 별개라 바뀌지 않는다.

## 완료 조건

마이그레이션이 기존 항목(모든 컬럼, set_id, 인덱스 포함)을 그대로 보존하며 category에 care를 허용함(실제 SQLite 테스트: 옛 스키마 데이터 이전, 새 종류 저장, 잘못된 종류 거절). 편집기 종류 버튼에 돌봄이 나오고 저장·수정·복사(세트 복제, 요일 복사)에서 유지됨. 위젯 데이터에 돌봄 항목이 포함됨(테스트). npm run check 통과, 에뮬레이터 확인

## 근거

마이그레이션 V10: 실제 SQLite 테스트 8개 통과(V8·V9 옛 스키마의 모든 컬럼·set_id·인덱스 4개 보존, care 저장, 잘못된 종류 거절, 요일 복사·세트 복제에서 care 유지, 위젯 데이터에 care 포함·school만 제외). 딸 폰(SM-A245N)에서 v1.31.1→1.38.0 덮어 설치 시 실제 DB가 V10으로 올라가 기존 항목('국어')이 보존되고 크래시 없음, 편집기 일정 종류에 학교/학원/돌봄/생활 버튼 표시. · 검증: npm run check 통과(lint, typecheck, Jest, Android build), critical-reviewer 검토 반영. 한계: 에뮬레이터 확인은 못 했고(메모리 부족) 실기기에서 돌봄 종류 항목을 저장해 위젯에 표시되는지는 확인하지 않았다(위젯 표시는 Jest로만 검증)
