## 목적

할 일별 알림을 시간표 알림과 함께 롤링 예약하고, 미완료 할 일에 대해 30분 재알림을 생성한다. P4.8은 할 일 데이터 조회와 30분 재알림 계산만 담당하며, 네이티브 교체 경계(`tasks` owner)와 전체 세대 관리는 P3.4의 공통 메커니즘을 사용한다.

P4.8의 책임:
1. SQLite의 할 일 테이블에서 오늘 미완료 항목을 조회한다.
2. 각 할 일의 알림 시각과 방식(notify/alarm)을 읽어 첫 알림과 30분 뒤 재알림을 계산한다.
3. 이 목록을 P3.4의 공통 네이티브 교체 경계에 `tasks` owner로 전달한다.
4. 할 일 추가·수정·삭제·완료 시 별도의 재예약 요청 경로를 제공한다.

P3.4는 시간표의 실제 데이터와 owner 전체의 교체·복구 메커니즘을 담당하므로, P4.8은 tasks owner 실제 할 일 데이터 검증만 수행한다.

## 쉬운 설명

예를 들어 저녁 7시에 "숙제했니?"를 알리고, 아직 체크하지 않았다면 30분 뒤 다시 알려준다. 완료하면 남은 알림을 다시 계산해서 예약 목록에서 빼낸다. 시간표 알림도 같은 방식으로 처리되는데, 할 일과 함께 한 세대의 예약으로 관리되어 중복을 막는다.

## 필요한 입력

- 할 일별 알림 시각(`remind_time`), 알림 방식(`alert_mode`: `none`/`notify`/`alarm`), 반복 요일(`repeat_weekdays`)
- 각 할 일의 현재 날짜별 완료 여부(`task_completions` 테이블)
- 할 일 추가·수정·삭제·완료 체크 뒤 재예약을 요청할 수 있는 기존 연결

P4.2와 P3.3은 백로그에서 `done`으로 기록되어 있다.
