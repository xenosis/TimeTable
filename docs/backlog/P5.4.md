# P5.4 — 위젯 자동 갱신

**기준:** schema 1.1 · SHA-256 `f32b10b32c4cc7b63963247285cec1167cd2c1fa0b1488f7a92c3e89ab6c9131`  
**상태:** needs_info  
**담당:** claude

---

## 목적

시간표의 다음 교시가 시작될 때 홈 화면 위젯이 표시하는 현재 교시와 다음 일정을 자동으로 다시 계산하고 갱신합니다.

---

## 쉬운 설명

앱을 매번 열지 않아도 위젯이 시간표를 읽고, 교시가 바뀌면 현재 교시를 새 내용으로 보여주는 작업입니다. 날짜가 바뀌거나 기기가 재부팅된 뒤에도 위젯 갱신 예약을 이어갈 수 있어야 합니다.

---

## 필요한 입력

- P5.4의 기준 백로그 레코드와 `deps`에 기록된 선행 작업 결과
- P5.2에서 정의한 위젯 데이터 브릿지
- 시간표의 교시 시작·종료 시각과 위젯에 표시할 일정 데이터
- 사용자 결정(2026-10-05): "'교시 전환'은 위젯에 보이는 일정(정규 수업 제외)의 시작·종료 시각 전환으로 해석"

---

## 결과물

- 교시 시작·종료 시각과 다음 날짜 경계에 맞춰 위젯 갱신을 예약하는 동작
- 갱신 시점에 저장된 시간표를 다시 읽어 현재 교시·다음 일정을 계산하는 동작
- 날짜가 바뀌었거나 재부팅된 뒤에도 위젯 갱신 예약을 복구하는 동작
- 위젯 자동 갱신을 사람이 확인할 수 있는 수동 테스트 절차

---

## 선행 작업

- `P5.2` 데이터 브릿지 완료 결과
- `P5.9` 위젯 데이터 파일 v2 (재구현)
- 백로그에 기록된 P5.4의 `deps`와 상위 작업 상태

---

## 수행 순서

1. 기준 schema version, SHA-256, P5.4의 `deps`와 `done_when`을 확인한다.
2. P5.9의 재구현된 위젯 데이터가 현재 교시·다음 일정·시간표 목록을 전달하는지 확인한다.
3. 시간표 경계 시각과 다음 날짜 경계에 맞춰 Android 갱신 예약을 연결한다.
4. 갱신 수신 시 최신 저장 데이터를 읽어 위젯 표시를 다시 계산하고, 다음 갱신 예약을 이어간다.
5. 앱의 날짜 변경과 기기 재부팅 뒤 예약 복구 경로를 확인한다.
6. `npm run check` 전체 검사를 실행하고 결과를 기록한다.
7. 등록된 `critical-reviewer`와 `backlog-explainer`의 검토 결과를 확인한다.
8. 아래 수동 테스트 항목을 구분해 진행한다:
   - 교시 종료·시작 경계 전환(에뮬레이터·실기기 일부 확인)
   - 화면 잠금·절전·재부팅·자정(사용자 결정으로 P5.6 실사용 때 확인)
9. 개발 구현 완료, 자동 검사 완료, 실기기 확인, 문서화 완료를 각각 구분해 백로그 상태와 문서에 반영한다.
