# P5.4 — 위젯 자동 갱신

## 기준

- 백로그 schema version: `1.1`
- 기준 CLI 조회 스냅샷 SHA-256: `22c22a2b7efdff1ee77f2255135d84fd2cd5fa27f126499f1c7d4ace086adb9c`
- 개발 상태: `in_review`
- 문서화 상태: 작성됨

이 문서는 위 기준 스냅샷의 P5.4 레코드만 설명한다. 원본 `backlog.json`은 수정하지 않는다.

## 작업 목적

시간표의 다음 교시가 시작될 때 홈 화면 위젯이 표시하는 현재 교시와 다음 일정을 자동으로 다시 계산하고 갱신한다.

## 쉬운 설명

앱을 매번 열지 않아도 위젯이 시간표를 읽고, 교시가 바뀌면 현재 교시를 새 내용으로 보여주는 작업이다. 날짜가 바뀌거나 기기가 재부팅된 뒤에도 위젯 갱신 예약을 이어갈 수 있어야 한다.

## 필요한 입력

- P5.4의 기준 백로그 레코드와 `deps`에 기록된 선행 작업 결과
- P5.2에서 정의한 위젯 데이터 브릿지
- 시간표의 교시 시작·종료 시각과 위젯에 표시할 일정 데이터
- 위젯이 갱신될 수 있는 개발 빌드와 사용자가 확인할 Android 기기

백로그 레코드에 없는 표시 문구, 허용 지연 시간, 운영 정책은 이 문서에서 결정하지 않는다.

## 결과물

- 교시 시작·종료 시각과 다음 날짜 경계에 맞춰 위젯 갱신을 예약하는 동작
- 갱신 시점에 저장된 시간표를 다시 읽어 현재 교시·다음 일정을 계산하는 동작
- 날짜가 바뀌었거나 재부팅된 뒤에도 위젯 갱신 예약을 복구하는 동작
- 위젯 자동 갱신을 사람이 확인할 수 있는 수동 테스트 절차

## 선행 작업

- `P5.2` 데이터 브릿지 완료 결과
- 백로그에 기록된 P5.4의 `deps`와 상위 작업 상태

## 수행 순서

1. 기준 schema version, SHA-256, P5.4의 `deps`와 `done_when`을 확인한다.
2. P5.2의 파일 기반 위젯 데이터가 현재 교시·다음 일정·시간표 목록을 전달하는지 확인한다.
3. 시간표 경계 시각과 다음 날짜 경계에 맞춰 Android 갱신 예약을 연결한다.
4. 갱신 수신 시 최신 저장 데이터를 읽어 위젯 표시를 다시 계산하고, 다음 갱신 예약을 이어간다.
5. 앱의 날짜 변경과 기기 재부팅 뒤 예약 복구 경로를 확인한다.
6. `npm run check` 전체 검사를 실행하고 결과를 기록한다.
7. 등록된 `critical-reviewer`와 `backlog-explainer`의 검토 결과를 확인한다.
8. 아래 수동 테스트를 사용자 실기기에서 수행한 뒤 관찰 결과를 기록한다.
9. 개발 구현 완료, 자동 검사 완료, 실기기 확인, 문서화 완료를 각각 구분해 백로그 상태와 문서에 반영한다.

## done_when 확인 방법

`교시 전환 시 위젯이 자동으로 갱신됨`을 다음 근거와 대조한다.

- 구현 근거: 교시 경계와 날짜 경계에 대한 갱신 예약, 갱신 수신 시 최신 데이터 재계산, 재부팅 후 예약 복구가 코드에 연결되어 있는지 확인한다.
- 자동 검증 근거: `npm run check`가 지침 동기화, 코드 길이, lint, typecheck, 테스트 12개 suite/42개 test, Android debug build를 모두 통과해야 한다.
- 사람 확인 근거: 아래 실기기 테스트에서 화면을 켜거나 앱을 다시 열지 않은 상태에서도 위젯 내용이 교시 전환에 맞춰 바뀌는지 확인하고 결과를 기록한다.

## 사용자 실기기 수동 테스트

각 항목에서 테스트 시작 시각, 예정된 교시 시각, 실제 위젯이 바뀐 시각, 화면 잠금 상태, 결과를 기록한다. 시간표 데이터가 위젯에 보이는지 먼저 확인하고 테스트한다.

### 1. 교시 전환

1. 시작까지 3~5분 남은 교시와 그 다음 교시가 보이도록 시간표를 준비한다.
2. 홈 화면에 4 x 2 위젯을 배치하고 앱을 종료하거나 백그라운드로 보낸다.
3. 화면을 잠근 상태로 교시 시작 시각을 지난다. 화면을 켜서 잠금 화면을 통과하기 전까지 위젯이 임의로 바뀌었는지 여부도 기록한다.
4. 홈 화면에서 위젯을 확인한다. 이전 교시가 남아 있지 않고 현재 교시가 표시되는지, 다음 일정 표시가 맞는지 확인한다.
5. 교시 종료 시각 뒤에도 같은 방법으로 확인하여 현재 교시가 사라지고 다음 일정 또는 휴식 문구로 바뀌는지 기록한다.

### 2. 화면 잠금

1. 다음 교시가 가까운 시간표를 준비하고 위젯이 정상 표시되는지 확인한다.
2. 화면을 잠근 뒤 교시 전환 시각을 지난다. 잠금 중에는 위젯 자체를 볼 수 없으므로, 잠금 상태에서 앱 알림이나 이상 동작이 있었는지는 별도로 기록한다.
3. 잠금을 해제하고 홈 화면으로 이동해 위젯을 확인한다. 앱을 직접 열지 않아도 최신 교시가 표시되는지 확인한다.
4. 잠금 해제 직후에만 갱신되었는지, 이미 잠금 중 갱신된 상태였는지 관찰 내용을 구분해 기록한다.

### 3. 재부팅

1. 다음 교시가 가까운 시간표와 위젯 표시를 준비한다.
2. 기기를 재부팅하고 부팅이 끝난 뒤 앱을 직접 열지 않는다.
3. 홈 화면에서 위젯이 표시되는지 확인하고, 다음 교시 시각이 지난 뒤 위젯 내용이 자동으로 갱신되는지 확인한다.
4. 재부팅 전 시간표의 이전 교시가 계속 남는지, 최신 교시로 바뀌는지, 갱신 예약이 복구되지 않은 표시가 있는지 기록한다.

## 확인 질문

- 실기기에서 교시 전환 후 위젯이 갱신되기까지 허용할 지연 시간은 백로그에 정의되어 있지 않다. 실제 관찰값을 먼저 기록한 뒤 제품 기준을 정할 필요가 있다.
- Android 제조사 배터리 최적화 정책이 잠금·절전 중 위젯 갱신 시각에 미치는 영향은 실기기 결과로 확인해야 한다.
