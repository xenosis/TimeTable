## 목적

주간 시간표를 아이가 스크롤 없이 확인할 수 있게 보여 준다. 기본은 오늘 요일이 선택된 요일 탭 + 하루 전체 일정 목록이고, `주간 한눈에 보기`를 누르면 요일×교시 조건부 그리드로 전환된다. 일정이 있는 칸/행에는 활성 테마의 의미 색과 아이콘을 적용한다. 백로그의 완료 기준은 “요일 탭 기본 보기와 주간 한눈에 보기 토글로 주간 시간표를 확인할 수 있고, 두 보기 모두 활성 테마의 의미 색·아이콘이 적용됨”이다.

## 쉬운 설명

시간표 탭을 열면 오늘 요일이 미리 선택된 요일 탭(일~토)과 그날 하루 전체 일정 목록이 나온다. 지난 시간은 흐리게, 지금 시간에는 "지금" 표시가 붙는다. 화면 위쪽의 `주간 한눈에 보기` 버튼을 누르면 요일×교시 격자로 바뀌는데, 칸 너비를 화면 가로 폭에 맞춰 계산하기 때문에 좌우로 스크롤할 필요가 없다(칸에는 과목 아이콘·색만 압축 표시하고, 칸이나 요일 머리글을 누르면 그 요일의 하루 전체 목록으로 돌아간다). 일정 저장 뒤 새로고침 신호가 전달되면 두 보기 모두 DB를 다시 조회해 최신 내용을 반영한다.

> 이전 버전(가로 스크롤 격자, 칸마다 제목 텍스트 표시)은 세로 화면에서 계속 옆으로 밀어야 하는 문제가 있어 사용자 피드백에 따라 위 구조로 교체했다. `src/components/WeeklyTimetable.tsx`는 삭제됐고, 셀 배치 계산 유틸(`src/utils/weeklyTimetable.ts`)과 그 테스트만 새 그리드 컴포넌트가 그대로 재사용한다.

## 필요한 입력

- SQLite DB 연결: `getDatabase()`가 제공하는 DB.
- `periods`의 `periodNo`, 시작 시각, 종료 시각.
- `timetable_items`의 요일, 교시 번호, 제목, `color_key`, `icon_key`.
- 교시 번호가 없는 시간 지정 일정의 시작·종료 시각.
- 조회 범위: 기본 `familyId`인 `local-family`.
- 활성 테마: `ThemeDefinition`과 의미 색·아이콘 해석 함수.

## 수행 순서 (2026-09-17 최초 구현, 가로 스크롤 격자 기준 — 현재는 아래 재설계 참고)

1. 선행 작업 `P2.2`의 교시·일정 DB 구조와 `P1.9`의 테마 의미 키 해석을 사용한다.
2. DB에서 저장된 교시 목록을 조회하고 일~토 각 요일의 일정을 조회한다.
3. 교시 번호를 기준으로 요일별 복수 일정을 해당 격자 셀에 배치하고, 교시 번호가 없는 일정은 시간 지정 행에 배치한다.
4. 왼쪽 기준 열에 교시 번호와 시작·종료 시각을 표시하고, 일~토 열과 시간 지정 행을 구성한다.

6. 일정이 없는 셀은 빈 상태로 표시하고, 교시가 없거나 조회에 실패하면 안내 문구를 표시한다.
7. 일정 저장 후 `refreshKey`가 바뀌면 교시와 일정을 다시 조회해 최신 내용을 표시한다. 재조회에 실패하면 오류 문구를 표시한다.
8. 주간 격자 배치 단위 테스트와 프로젝트 전체 품질 검사를 실행한다.

### 2026-09-29 재설계

1. `src/components/WeeklyTimetable.tsx`를 삭제하고 `app/(tabs)/timetable.tsx`에서 요일 탭 기본 보기/주간 한눈에 보기 토글 상태를 관리한다.
2. `WeekdayTabs`로 오늘 요일이 기본 선택된 요일 탭을 만들고, `DailyScheduleList`로 선택 요일의 하루 전체 일정을 지난/지금/예정 구분해 표시한다.
3. `WeekOverviewGrid`는 `useWindowDimensions`로 카드 폭을 읽어 `열 너비 = (카드 폭 − 교시 라벨 폭) / 7`을 계산해 화면 폭에 맞는 칸을 그리므로 가로 스크롤이 없다. 셀 탭 시 해당 요일 하루 보기로 이동한다.
4. 셀 배치 데이터는 기존 `src/utils/weeklyTimetable.ts`(`makeWeeklyTimetable`)를 그대로 재사용한다.
5. `npm run check` 전체 통과 후 에뮬레이터로 두 보기 전환과 칸 너비 무스크롤을 시각 확인한다.

## done_when 확인 방법

다음 근거로 백로그의 완료 기준을 대조한다.

- `WeekdayTabs`가 오늘 요일을 기본 선택하고, `DailyScheduleList`가 해당 요일의 하루 전체 일정을 지난/지금/예정 상태로 표시하는지 확인한다.
- `주간 한눈에 보기` 토글 시 `WeekOverviewGrid`가 요일×교시 격자를 렌더링하고, 칸 너비가 `useWindowDimensions` 기반으로 화면 폭에 맞춰 계산되어 가로 스크롤 없이 전체 열이 보이는지 확인한다.
- `getPeriods`와 `getTimetableItemsForWeekday` 결과가 두 보기 모두에서 정확히 대응하는지 확인한다.
- 그리드 셀·요일 머리글 탭 시 해당 요일의 하루 보기로 이동하는지 확인한다.
- 두 보기 모두에서 일정에 `resolveThemeColor`, `resolveThemeIcon`으로 해석한 활성 테마의 의미 색·아이콘이 적용되는지 확인한다.

- `__tests__/weekly-timetable.test.ts`의 셀 배치 테스트가 여전히 통과한다(`WeekOverviewGrid`가 같은 유틸을 재사용하므로 유효).
