# P2.5 — 주간 화면

## 기준 입력

- 기준 백로그 schema version: `1.1`
- 기준 백로그 SHA-256: `b6c9670cebdd082363859b6077e8ea4b440c56e35d99eab6201a6cb0252ce04b`
- 기준 백로그 항목: `P2.5`
- 백로그 개발 상태: `done`
- 선행 작업: `P2.2`, `P1.9`
- 문서 상태: 구현 및 검사 근거를 반영한 설명 문서 작성 완료. 문서화 완료와 개발 작업 완료는 별도로 관리한다.

## 목적

요일과 교시를 교차하는 격자로 주간 시간표를 보여 준다. 교시별 시각과 요일별 일정이 같은 표에서 대응되며, 일정이 있는 칸에는 활성 테마의 의미 색과 아이콘을 적용한다. 백로그의 완료 기준은 “요일×교시 격자 화면이 데이터를 정확히 표시하고 활성 테마의 의미 색·아이콘이 적용됨”이다.

## 쉬운 설명

주간 화면에는 왼쪽에 교시와 시작·종료 시각을 표시하고, 오른쪽에 일요일부터 토요일까지 열을 만든다. 한 칸에 일정이 여러 개면 모두 표시하고, 교시가 아니라 시작·종료 시각을 직접 가진 일정은 표의 별도 `시간 지정` 행에 표시한다. 일정이 있는 칸에는 과목 이름과 아이콘을 보여 주고 과목 의미에 맞는 테마 색을 사용한다. 일정이 없는 칸은 빈 칸으로 표시한다. 화면 가로 폭이 좁으면 표를 좌우로 움직여 볼 수 있다. 일정 저장 뒤 새로고침 신호가 전달되면 DB를 다시 조회해 최신 내용을 반영하고, 재조회에 실패하면 오류 문구를 표시한다.

## 필요한 입력

- SQLite DB 연결: `getDatabase()`가 제공하는 DB.
- `periods`의 `periodNo`, 시작 시각, 종료 시각.
- `timetable_items`의 요일, 교시 번호, 제목, `color_key`, `icon_key`.
- 교시 번호가 없는 시간 지정 일정의 시작·종료 시각.
- 조회 범위: 기본 `familyId`인 `local-family`.
- 활성 테마: `ThemeDefinition`과 의미 색·아이콘 해석 함수.

  - 일정 제목과 활성 테마의 의미 색·아이콘 표시

## 수행 순서

1. 선행 작업 `P2.2`의 교시·일정 DB 구조와 `P1.9`의 테마 의미 키 해석을 사용한다.
2. DB에서 저장된 교시 목록을 조회하고 일~토 각 요일의 일정을 조회한다.
3. 교시 번호를 기준으로 요일별 복수 일정을 해당 격자 셀에 배치하고, 교시 번호가 없는 일정은 시간 지정 행에 배치한다.
4. 왼쪽 기준 열에 교시 번호와 시작·종료 시각을 표시하고, 일~토 열과 시간 지정 행을 구성한다.
5. 일정이 있는 셀에서 `colorKey`와 `iconKey`를 활성 테마의 색·아이콘으로 해석해 적용한다.
6. 일정이 없는 셀은 빈 상태로 표시하고, 교시가 없거나 조회에 실패하면 안내 문구를 표시한다.
7. 일정 저장 후 `refreshKey`가 바뀌면 교시와 일정을 다시 조회해 최신 내용을 표시한다. 재조회에 실패하면 오류 문구를 표시한다.
8. 주간 격자 배치 단위 테스트와 프로젝트 전체 품질 검사를 실행한다.

## done_when 확인 방법

다음 근거로 백로그의 완료 기준을 대조한다.

- `WeeklyTimetable`이 일~토와 교시 번호를 교차하는 격자를 렌더링하는지 확인한다.
- `getPeriods`와 `getTimetableItemsForWeekday` 결과가 화면의 교시·요일 셀에 정확히 대응하는지 확인한다.
- 같은 교시·요일의 복수 일정이 모두 표시되는지 확인한다.
- 교시 번호가 있는 일정은 해당 교시 셀에, 교시 번호가 없는 시간 지정 일정은 시간 지정 행에 표시되는지 `makeWeeklyTimetable`과 단위 테스트로 확인한다.
- 일정 셀에 제목과 함께 `resolveThemeColor`, `resolveThemeIcon`으로 해석한 활성 테마의 의미 색·아이콘이 적용되는지 확인한다.
- 저장 후 새로고침 신호가 바뀌면 DB를 다시 조회해 최신 시간표를 표시하는지 확인한다.
- 교시 번호가 없는 시간 지정 일정이 표의 `시간 지정` 행에 표시되는지 확인한다.
- 저장 후 재조회에 실패하면 주간 시간표 오류 문구가 표시되는지 확인한다.
- `__tests__/weekly-timetable.test.ts`의 일~토 배치, 복수 일정, 시간 지정 일정 테스트가 통과했다.
- 마지막 `npm run check`가 통과했다: 지침 동기화, 파일 길이, lint, typecheck, Jest 30개, Android x86_64 debug build.
- 최종 확인 결과, `done_when` 조건과 선행 작업·검증 근거가 모두 확인되어 백로그 개발 상태가 `done`으로 기록되었다.
