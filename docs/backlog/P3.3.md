# P3.3 — 롤링 예약 계산 (순수 함수 + 테스트)

## 기준 입력

- 기준 백로그 schema version: `1.1`
- 기준 백로그 SHA-256: `cf3f4a94d5d2e28ad9dc9bd91e0e506de357f475137a99a3fd9579c2f7e42604`
- 기준 백로그 항목: `P3.3`
- 백로그 개발 상태: `in_review`
- 선행 작업: `P2.2`
- 문서 상태: 7일 롤링 계산과 테스트·전체 검사 근거를 반영했다. 문서화 완료와 개발 작업 완료는 별도로 관리한다.

## 목적

현재 시각부터 정확히 7×24시간인 구간 `[now, now + 7일)`에 발생할 알림 목록을 순수 함수로 계산한다. 공휴일·방학 예외, 미리 알림 시간, 알림 방식별 분기, 과거 트리거 제외를 계산에 반영하며, 다음 주 이른 일정의 미리 알림이 구간 안에 들어오면 일정 날짜가 구간 밖이어도 포함한다. 백로그의 완료 기준은 “7일치 알림 목록 계산 함수와 단위 테스트가 통과함”이다.

## 쉬운 설명

현재 시각부터 정확히 7일 동안 요일에 맞는 시간표 항목을 찾는다. 알림 없음 항목은 제외하고, 학교 일정이 공휴일·방학 범위에 걸리면 제외한다. 시작 시각에서 미리 알림 분을 뺀 시각을 예약 시각으로 만들고, 이미 지난 예약과 7일 구간 끝 시각 이상인 예약은 제외한다. 다만 다음 주 월요일처럼 일정 시작이 7일 뒤여도 전날 밤 미리 알림이 구간 안에 들어오면 그 예약은 포함한다. 남은 예약은 `notify` 또는 `alarm` 방식과 함께 시간순으로 반환한다.

## 필요한 입력

- 일정 ID, 요일, 시작 시각, 제목, category, alert mode, 미리 알림 분.
- 공휴일·방학 예외의 시작일과 종료일 범위.
- 기준 현재 시각 `now`.
- 계산 기간 일수(기본 7일, 양의 정수).

## 결과물 및 구현

- `src/utils/rollingNotifications.ts`
  - `buildRollingNotifications` 순수 함수
  - 기본 7일 날짜 범위 생성과 요일 매칭
  - 학교 일정의 예외 날짜 제외
  - `none` 제외와 `notify`·`alarm` 예약 결과 분기
  - 미리 알림 분을 반영한 트리거 시각 계산
  - 정확한 `[now, now + 7일)` trigger 구간 적용
  - 다음 주 이른 일정의 전날 미리 알림을 포함하기 위한 날짜 탐색
  - 현재 시각 이전 트리거 제외 및 트리거 시각·항목 ID 정렬
  - 항목 ID와 날짜 기반 예약 ID 생성
- `__tests__/rolling-notifications.test.ts`
  - 7일 범위, 미리 알림, 방식 분기
  - 공휴일·방학 중 학교 일정 제외와 비학교 일정 유지
  - 과거 예약 제외와 잘못된 일수 거부

## 수행 순서

1. `P2.2`의 요일·일정 데이터와 알림 설정을 입력 계약으로 사용한다.
2. `now`부터 정확히 `days * 24시간` 뒤를 `windowEnd`로 정하고, trigger가 `[now, windowEnd)`에 들어오는지 판정한다.
3. 각 날짜의 요일과 일정 요일을 비교하고, 알림 없음 항목을 제외한다.
4. 학교 category가 예외 날짜 범위에 포함되면 제외하고, 학원·생활 일정은 유지한다.
5. 시작 시각에서 `alertBeforeMin`을 빼 트리거 시각을 계산한다.
6. 다음 주 이른 일정의 전날 미리 알림을 놓치지 않도록 최대 미리 알림 분만큼 날짜 탐색 범위를 연장한다.
7. 트리거 시각이 `now`보다 과거이거나 `windowEnd` 이상이면 제외하고, 나머지를 방식과 함께 결과에 담는다.
8. 트리거 시각과 항목 ID 순으로 결과를 정렬하고, 각 결과에 항목·날짜 식별자를 부여한다.
9. 단위 테스트와 전체 `npm run check`를 실행한다.

## done_when 확인 방법

다음 근거로 백로그의 완료 기준을 대조한다.

- `buildRollingNotifications`가 기본 7일의 각 날짜에서 요일에 맞는 알림을 계산하는지 확인한다.
- 미리 알림 분이 시작 시각에서 정확히 차감되는지 확인한다.
- `notify`와 `alarm` 방식이 결과에 보존되고, `none`은 제외되는지 확인한다.
- 공휴일·방학 예외 범위에서는 학교 알림이 제외되고 다른 category 알림은 유지되는지 확인한다.
- 현재 시각보다 과거인 트리거가 제외되고 결과가 시간순으로 정렬되는지 확인한다.
- trigger가 정확히 `[now, now + 7일)` 구간에만 포함되는지 확인한다.
- 다음 주 이른 일정의 미리 알림 시각이 7일 구간 안이면 전날 예약으로 포함되는지 확인한다.
- 계산 일수가 양의 정수가 아니면 오류가 발생하는지 확인한다.
- `__tests__/rolling-notifications.test.ts`의 7일 계산, 예외·방식 분기, 과거·경계 검증이 통과했다.
- 최종 전체 `npm run check`가 통과했다: 지침 동기화, 파일 길이, lint, typecheck, Jest 38개, Android x86_64 debug build.
- 현재 백로그 개발 상태는 `in_review`이며, 문서화 완료를 개발 작업의 `done` 상태와 혼동하지 않는다.
