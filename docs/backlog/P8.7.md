# P8.7 — 학교 시간표 자동 갱신

## 기준

- 백로그 schema version: `1.1`
- 백로그 SHA-256: `094d32156c4af4a7141a9c993f8f83a9d8472005029e0a3e59900465c35905fc`
- 기준 작업 상태: `in_review`
- 상위 작업: `P8`

## 목적

학교 시간표는 매주 바뀌므로, 저장해 둔 학교·학년·반으로 앱이 스스로 정해진 간격(6시간)으로 이번 주(주말에는 다음 주) 나이스 시간표를 확인하여, 내용이 바뀌었으면 '학교' 분류 일정만 자동 반영한다. 매주 사람이 "가져오기" 버튼을 누르지 않아도 된다.

## 쉬운 설명

앱을 켜거나 백그라운드에서 돌아올 때 자동으로 나이스 시간표를 확인한다. 내용이 달라졌으면 학교 일정만 시간표에 반영하고, 같으면 무시한다(빈 주·공휴일은 안전하게 처리). 딸 폰(딸 계정·로컬 모드)에서만 작동하며, 같은 주는 최소 6시간 간격으로 확인한다. 관리자 화면에 "자동 갱신: 언제 확인 — 상태" 메시지가 표시된다.

## 필요한 입력

- P8.1에서 저장한 학교·학년·반 정보: 자동 갱신 때 이 정보로 나이스를 조회한다.
- 교시 시간: 교시 번호만 있는 나이스 응답을 앱의 교시 시간 설정과 합쳐야 한다.
- 나이스 인증키: P8.1에서 사용한 것과 동일(`.env` 파일의 `EXPO_PUBLIC_NEIS_API_KEY`).

## 결과물 및 구현 범위

### UI 및 정보 표시
- 관리자 화면 → "시간표" → "학교 시간표 가져오기(나이스)" 항목 아래에 자동 갱신 상태 표시
  - 처음: "자동 갱신: 앱을 켤 때마다(6시간 간격) 이번 주 시간표를 확인해 바뀌면 학교 일정만 바꿔요."
  - 확인 후: "자동 갱신: 2026-10-09 08:13 확인 — 10/5 주 나이스 시간표로 학교 일정을 바꿨어요." (메시지는 결과에 따라 다름)
  - 같은 내용: "자동 갱신: 2026-10-09 08:14 확인 — 나이스 시간표와 지금 시간표가 같아요."
  - 오류: "자동 갱신: 2026-10-09 08:15 확인 — 학교 시간표를 확인하지 못했어요. 다음에 다시 확인해요."
- "지금 나이스 확인" 버튼으로 즉시 확인 가능 (간격 조건 무시)

### 동작
- 앱 시작: 5초 뒤에 한 번 확인
- 앱 복귀 (AppState 'active' 신호): 즉시 확인
- 백그라운드 작업: timetable-rolling-refresh(최소 15분 간격)에서도 자동 갱신 호출. 단 앱 프로세스가 완전히 꺼져 화면 없이 깨어난 경우, 계정 확인 전이거나 '서버 먼저 저장' 경로가 없으면 건너뜀(서버를 거치지 않는 로컬 변경 방지)
- 같은 주: 마지막 확인 이후 6시간 이내면 재확인하지 않음
- 주 변경: 새 주(월요일 기준)에는 즉시 확인
- 실패: 30분 뒤 재시도 (성공·같음은 6시간 뒤 재확인)
- 결과:
  - 'updated': 나이스 시간표가 달라 학교 일정을 업데이트
  - 'same': 나이스 시간표와 현재 시간표가 같음
  - 'empty': 이번 주 나이스에 과목이 없음 (방학 또는 학교 미입력)
  - 'missing-periods': 필요한 교시 시간이 설정되지 않음
  - 'error': 네트워크 실패 등

### 데이터 처리
- 빈 요일(공휴일이거나 학교가 아직 입력하지 않은 날): 매주 반복 시간표를 그대로 둔다. 공휴일·휴업일은 P8.8이 날짜별 휴일로 그날만 숨긴다(1.61.0부터. 1.59.x에서는 공휴일 요일의 학교 일정을 반복 시간표에서 비웠다)
- 같은 교시·과목의 알림·메모 유지: 시간표 내용이 같으면 알림과 메모는 그대로 보존
- 시간으로 입력한 학교 일정 유지: 사용자가 직접 추가한 시간 단위 항목은 건드리지 않음
- 학원·돌봄·방과후 등 다른 분류의 일정은 유지
- 같은 내용은 다시 쓰지 않음 (데이터베이스 불필요한 갱신 방지)
- 오류 시 기존 시간표는 건드리지 않음

### 기기 제약
- 아빠 폰(관리자 역할)은 자동 갱신하지 않음 (P8.1과 동일)
- 딸 계정이 서버와 한 번 맞춘 뒤에만 활성화 (로컬 모드와 서버 로그인 모두 지원, 하지만 로컬 모드는 앱 시작·복귀만, 서버 모드는 동기화 이후도 처리)
