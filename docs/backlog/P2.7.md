# P2.7 — 요일 복사

## 기준 입력

- 기준 백로그 schema version: `1.1`
- 기준 백로그 SHA-256: `de2559bc8bf037d9a28276b9343e6500e8780551c21551f2a828052b22a761a6`
- 기준 백로그 항목: `P2.7`
- 백로그 개발 상태: `done`
- 선행 작업: `P2.6`
- 문서 상태: 구현 및 검사 근거를 반영한 설명 문서 작성 완료. 문서화 완료와 개발 작업 완료는 별도로 관리한다.

## 목적

원본 요일의 시간표 항목을 대상 요일로 복사하는 기능을 제공한다. 대상 요일의 기존 항목은 원본의 현재 상태로 교체하며, 복사 과정 전체가 하나의 DB 트랜잭션으로 처리되어야 한다. 백로그의 완료 기준은 “요일 간 복사가 정확히 동작함”이다.

## 쉬운 설명

사용자가 일요일부터 토요일까지 원본 요일과 대상 요일을 각각 고른다. 원본 요일에 항목이 있어야 복사가 실행되며, 원본이 비어 있으면 대상 요일을 지우지 않고 오류 안내를 표시한다. 원본 항목이 있으면 `시간표 복사`를 눌러 대상 요일의 기존 시간표를 지우고 원본 요일의 항목을 그대로 복제한다. 복사할 때 과목명, 요일 외 시간 정보, 일정 종류, 색·아이콘 의미 키, 알림 설정을 함께 복사한다. 원본과 대상이 같으면 복사하지 않는다.

## 필요한 입력

- SQLite DB 연결: `getDatabase()`가 제공하는 DB.
- 원본 요일과 대상 요일: 각각 0~6이며 서로 달라야 한다.
- 복사 범위: 기본 `familyId`인 `local-family`.
- 원본 요일의 `timetable_items` 저장 필드 전체.
- 활성 테마: 복사된 의미 키를 화면에 표시할 때 사용하는 테마.

## 결과물

- `src/db/timetableRepository.ts`
  - 원본·대상 요일 범위와 동일 요일 여부 검증
  - 복사 트랜잭션 내부에서 원본 요일 항목 수 확인
  - 원본이 비어 있으면 대상 교체 전에 복사 거부
  - 대상 요일 기존 항목 삭제
  - 원본 요일 항목의 저장 필드를 대상 요일로 INSERT
  - 삭제와 복제를 `BEGIN IMMEDIATE`부터 `COMMIT` 또는 실패 시 `ROLLBACK`까지 하나의 원자적 트랜잭션으로 처리
  - `familyId` 범위 유지
- `src/components/WeekdayCopy.tsx`
  - 일~토 원본·대상 요일 선택 UI
  - 원본과 대상 선택 전 복사 버튼 비활성화
  - 복사 중 입력 차단과 성공·실패 안내
  - 복사 성공 후 `onCopied` 콜백으로 관련 화면 갱신
- `__tests__/database.test.ts`
  - 대상 교체, 원본 필드 복제, 동일 요일 거부와 트랜잭션 동작 검증

## 수행 순서

1. 선행 작업 `P2.6`에서 사용한 `timetable_items` 구조와 저장 필드를 사용한다.
2. 사용자가 원본 요일과 대상 요일을 각각 선택한다.
3. 원본과 대상이 모두 선택되었고 서로 다른지 확인한다.
4. `BEGIN IMMEDIATE`로 복사 트랜잭션을 시작한다.
5. 트랜잭션 내부에서 원본 요일의 항목 수를 확인하고, 0개면 대상 요일을 변경하지 않고 오류를 표시한 뒤 롤백한다.
6. 원본이 비어 있지 않을 때만 같은 `familyId`의 대상 요일 항목을 삭제한다.
7. 같은 `familyId`의 원본 요일 항목을 읽어 대상 요일로 복제하고, ID는 새로 생성되도록 한다.
8. 모든 복제가 성공하면 `COMMIT`하고 성공 메시지와 갱신 콜백을 실행한다. 중간에 실패하면 `ROLLBACK`하고 오류 메시지를 표시한다.
9. 복사 후 주간 화면과 오늘 화면 등 연결된 조회 화면이 최신 DB 상태를 반영하는지 확인한다.

## done_when 확인 방법

다음 근거로 백로그의 완료 기준을 대조한다.

- `WeekdayCopy`에서 일~토 원본·대상 요일을 선택하고 복사할 수 있는지 확인한다.
- 원본 또는 대상이 빠졌거나 두 요일이 같으면 복사가 실행되지 않는지 확인한다.
- 원본 요일 항목 수를 복사 트랜잭션 내부에서 대상 삭제 전에 확인하고, 비어 있으면 대상 요일을 삭제하거나 변경하지 않고 복사 실패 오류를 표시하는지 확인한다.
- 대상 요일의 기존 항목이 삭제되고 원본 요일의 모든 항목이 대상 요일에 동일한 저장 필드로 복제되는지 확인한다.
- `category`, `period_no` 또는 직접 시간, `color_key`, `icon_key`, `alert_mode`, `alert_before_min`이 복사되는지 확인한다.
- 대상 삭제와 원본 복제가 하나의 트랜잭션으로 처리되고 실패 시 롤백되는지 확인한다.
- `familyId`가 다른 항목을 삭제하거나 복사 대상에 포함하지 않는지 확인한다.
- `__tests__/database.test.ts`에서 대상 교체, 원본 필드 복제, 동일 요일 거부와 트랜잭션 호출을 검증한다.
- 최종 전체 품질 검사 `npm run check`가 통과했다: 지침 동기화, 파일 길이, lint, typecheck, Jest 32개, Android x86_64 debug build.
- 최종 확인 결과, `done_when` 조건과 선행 작업·검증 근거가 모두 확인되어 백로그 개발 상태가 `done`으로 기록되었다.
