# P6.9 — 변경 푸시

## 기준 입력

- Schema version: `1.1`
- SHA-256: `854053d825e5f6199d0a23bf0c656116ab907f332f0d48b637c1871be4d5cf81`
- 입력 크기: `495195 bytes`
- 기준 시각: `2026-10-11T00:22:17.962Z`
- 기준 상태: `in_progress` (2026-10-11)

## 목적과 쉬운 설명

아빠가 서버에 시간표나 할 일 변경을 저장하면 딸 폰에 “시간표가 바뀌었어요”라는 푸시 알림을 보내 변경 사실을 알린다. 알림을 탭하면 앱이 가족의 최신 내용을 동기화한다. 앱 복귀와 Realtime 동기화도 함께 사용하며, OS 강제 종료나 네트워크 단절 중 푸시 수신까지 보장하는 요구사항은 아니다.

## 필요한 입력

- 서버 변경을 감지하고 가족별 발송 대상을 확인하는 Supabase 함수와 서버 데이터
- 딸 기기의 설치본 식별·푸시 토큰 등록 정보 및 Android 네이티브 수신 경로
- Firebase 앱/FCM 자격과 Expo 푸시 발송 설정
- 발송 대기열·작업자·영수증(receipt) 조회를 위한 운영 서버 설정
- Doro의 푸시 설정 가이드에서 재사용할 수 있는 절차

## 결과물

- 인증 및 가족 경계가 적용된 변경 푸시 요청·발송·재시도·receipt 처리 경로
- 딸 기기에서 가족/역할을 확인해 표시하는 알림과 탭 후 동기화 경로
- Firebase·Expo·FCM 및 서버 배포·운영 확인 기록
- 서버 변경부터 딸 폰의 실제 알림 도착까지 확인한 근거

## 선행 작업

- `P6.6` — 서버↔SQLite 동기화와 온·오프라인 정합성
- 외부 설정 및 운영 배포/실기기 수신 세부 확인: 하위 `P6.17`
- 종료 상태 알림 탭 후 최신 내용 반영 및 기기 동기화 시각 확인: 하위 `P6.18`

## 수행 순서

1. 서버 변경 이벤트와 설치본·토큰 등록 경로가 가족 및 역할 경계를 지키는지 구현한다.
2. Expo 발송 함수, 실패 재시도, receipt 조회 경로를 연결한다. 발송 실패가 이미 저장된 편집을 취소하지 않도록 한다.
3. Android에서 현재 딸 가족의 알림만 표시하고, 알림 탭 뒤 최신 내용을 동기화한다.
4. Firebase·Expo·FCM 및 서버 작업자 설정을 적용하고 운영 상태를 확인한다.
5. 아빠 기기의 실제 저장에서 딸 폰의 실제 표시까지 확인하고, 구현·검사·리뷰·실기기 근거를 대조한다.

## 완료 조건과 확인 방법

백로그의 완료 조건은 “서버 변경 시 딸 폰에 푸시가 도착함”이다. 서버 변경을 실제로 저장하고 딸 폰에서 알림이 보이는지 기기 기록으로 확인한다. Expo ticket 접수나 receipt만으로 기기 도착을 대신 판정하지 않는다. P6.17에는 실제 서버 변경→딸 폰 알림 및 탭 후 최신 내용 적용 근거가 있고, P6.18에는 종료 상태 탭 후 최신 내용과 기기 동기화 시각 확인 근거가 기록되어 있다. 최종 완료 판정에는 등록된 리뷰와 해당 실행의 전체 검사 결과도 함께 대조한다.

## 현재 확인 기록 (기준 SHA 기준)

- 선행 `P6.6`은 완료 상태다.
- 입력 로그에는 실제 자동 발송, receipt 처리, 두 기기의 알림·탭·최신 내용 확인 및 전체 검사 통과가 기록되어 있다. 하위 `P6.17`과 `P6.18`도 완료 상태다.
- P6.9는 아직 `in_progress`다. 2026-10-11 00:20:18Z 기록에 최종 리뷰에서 확인된 로그아웃 시 재활성화 및 설치본 이전 요청 역전 경로 보완에 착수했고, 보완을 묶어 추가 설치하기로 적혀 있다. 따라서 기존 실제 수신 근거는 유지하되, 이번 보완·검사·리뷰·필요한 실기기 확인이 끝났다고 추정하지 않는다.
