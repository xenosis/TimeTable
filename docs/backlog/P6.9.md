# P6.9 — 변경 푸시

## 기준 입력

- Schema version: `1.1`
- SHA-256: `367fa78db141618420371941d4949afcc124c7c8b8c6307d118ae6fad2ebae96`
- 입력 크기: `443385` bytes
- 기준 시각: `2026-10-07T18:42:04.031Z`
- 기준 상태: `in_progress` (owner: `codex`, updated_at: `2026-10-07T18:42:04.009Z`)

## 목적

아빠가 가족 시간표나 할 일을 서버에 저장하면, 딸 폰에 변경을 알리는 보이는 푸시 알림을 전달한다. 알림을 누르면 딸 폰이 현재 가족의 서버 데이터를 다시 동기화한다.

## 쉬운 설명

아빠가 바꾼 내용이 서버에 저장되면 딸 폰에 “시간표가 바뀌었어요”라고 알려준다. 딸이 알림을 누르면 앱이 최신 내용을 받아온다. 서버 저장 성공과 푸시 도착은 별개이며, 푸시를 받지 못해도 앱 복귀와 Realtime 동기화가 보완 경로로 남는다.

## 필요한 입력

- 기준 작업: P6.9. 직접 선행 작업 P6.6(동기화)은 기준 입력에서 `done`이다.
- 요구사항: `docs/research.md`의 원격 푸시 흐름(특히 푸시 탭 후 동기화와 보이는 푸시 원칙).
- 구현 설정 안내: `docs/push-notification-setup.md`.
- 실제 푸시를 구성·확인하려면 현재 앱의 Android 패키지명, 해당 패키지로 등록한 Firebase Android 앱과 `google-services.json`, Expo 프로젝트 ID 및 FCM v1 자격 증명이 필요하다. 기준 입력의 기록에는 Firebase/Expo 설정, 함수 배포, 실제 수신 확인이 아직 완료되지 않았다고 되어 있다.

## 결과물

- 인증된 가족 변경 요청을 처리하는 Supabase Edge Function.
- 딸 기기의 푸시 토큰 등록·가족 역할 확인·로그아웃 시 수신 해제 경로.
- Android에서 현재 가족에 해당하는 보이는 알림과, 탭 시 동기화 경로.
- 설정 및 확인 절차와 완료 조건에 대한 근거 기록.

구현 기록상 1.55.0/146에서 코드와 자동 검사는 완료됐으나, Firebase/Expo 자격 설정·함수 배포·딸 폰 실제 푸시 도착은 미완료다. 따라서 코드 구현 완료만으로 `done_when` 충족을 간주하지 않는다.

## 선행 작업

- P6.6 — 완료. P6.9의 직접 의존성이다.
- P6.8은 기준 입력에서 `needs_info`이고, P6.9의 직접 의존성으로 지정되지는 않았다.
- P6.16은 아빠 원격 관리의 추가 실기기 검증 항목이며 P6.9의 직접 의존성은 아니다.

## 수행 순서

1. `docs/research.md`의 흐름과 P6.9 구현 기록을 대조해 서버 저장, 가족별 전송, 딸 기기의 알림 표시, 탭 후 동기화 경계를 확인한다.
2. `docs/push-notification-setup.md`를 따라 현재 패키지의 Firebase 앱, Expo 프로젝트 ID 및 FCM 자격 구성을 준비한다. 패키지명 변경은 P7에서 진행하기로 기록되어 있으므로, 현재 패키지로 설정할지 이름 변경 뒤 새 Firebase 앱으로 설정할지 결정이 필요하다.
3. 필요한 사용자 자격 증명과 설정이 준비되면 Edge Function을 배포하고 딸 계정 기기에 토큰을 등록한다. 비밀 키는 앱이나 저장소에 넣지 않는다.
4. 서버 변경을 저장해 딸 폰에 실제 보이는 푸시가 도착하는지 확인하고, 알림 탭 뒤 최신 내용이 동기화되는지 확인한다.
5. 다른 가족·아빠 기기·로그아웃 상태에는 알림을 표시하지 않는 경계도 확인하고, 실제 관찰과 코드/자동 검사 근거를 구별해 기록한다.

## done_when 확인 방법

기준 문구는 **“서버 변경 시 딸 폰에 푸시가 도착함”**이다. 서버 변경을 발생시킨 뒤 딸 폰에서 보이는 알림의 실제 도착을 관찰해 기록해야 한다. Expo 전송 접수, 함수 성공 응답, 토큰 등록, 자동 테스트만으로 도착을 판정하지 않는다. 가능한 경우 알림 탭 후 동기화도 확인하되, 기준 문구를 넘어서는 동작은 별도 근거로 표시한다.

## 현재 확인 기록

- 구현 기록: 아빠의 서버 저장 성공 뒤 `tt-notify-change` 호출, 딸 토큰 등록, Android 네이티브 가족 필터 후 보이는 알림, 탭 시 동기화, 로그아웃 기기의 수신 해제가 연결됐다고 기록되어 있다.
- 자동 확인: 1.55.0/146에서 78 suites/462 tests와 Android build 통과, Edge Function 인증·가족 분리 테스트 5건 및 Kotlin 가족 필터 테스트 2건 통과로 기록되어 있다.
- 기기 빌드: ARM64 릴리즈 버전 146과 기존 서명이 일치한다고 기록되어 있다.
- 미확인: Firebase 앱 및 `google-services.json`, Expo projectId/FCM 자격, 함수 배포, 딸 폰 실제 푸시 도착. 기준 입력 시 딸 폰 업데이트도 진행 중으로 기록되어 있다.
- 현 판정: `in_progress`. 등록된 리뷰의 인증 재시도 누락, 발송 유실, 토큰 정리 문제를 보완 중이다. `done_when`의 실제 푸시 도착 근거가 아직 없어 완료 조건 충족은 확인되지 않았다.
- 1.55.1/147: 인증 통신 실패 후 재등록과 계정 전환 중 이전 요청 차단을 검증했다. 발송 큐는 임시 가족의 롤백 SQL 시험에서 생성·병합·중복 임대 차단·새 변경 보존·권한 거절·삭제를 확인했다. 운영 migration 적용·자동 작업자·receipt·설치본 토큰 이전은 아직 미완료다.

## 확인 질문

- 패키지명 변경은 P7로 예정되어 있다. Firebase 앱과 푸시 설정을 현재 패키지 `com.sewoong.kidtimetable`로 먼저 만들지, 변경 후 목표 패키지 `com.chaea.timetable`에 맞춰 새로 등록할지 결정이 필요하다.
- 함수 배포와 Firebase/Expo 비밀 자격 설정을 진행할 계정·자격 준비 시점은 기준 입력에 정해져 있지 않다. 실제 설정 단계에서 사용자 제공 또는 직접 설정이 필요하다.
