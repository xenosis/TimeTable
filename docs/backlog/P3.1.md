# P3.1 — 권한 안내 화면

## 기준 입력 및 현재 상태

- 백로그 schema version: `1.1`
- 기준 백로그 SHA-256: `fc86040c04013d98bdd74a54fc1b773d5a3ab94e8d7285409ce6d6a2f8b7cf12`
- 기준 입력 schema version: `1.1` (source bytes: `143777`, modifiedAt: `2026-09-26T10:00:08.098Z`)
- 기준 항목: `P3.1` / `needs_info`
- 제목: 권한 안내 화면
- 백로그 의존성: `P0.4`, `P0.5`
- 담당자: `codex`
- 이 문서 작업에서는 백로그 JSON, 상태, 프로그램 코드를 수정하지 않는다.

## 목적

알림과 알람에 필요한 Android 권한 상태를 안내 화면에서 보여주고, 꺼진 권한은 해당 시스템 설정으로 이동시킨다. 앱으로 돌아오면 상태를 다시 읽어 권한이 박탈된 경우에도 재안내한다.

## 쉬운 설명

앱이 알림을 제대로 보내려면 알림, 정확한 알람, 잠금화면 전체화면 알림, 배터리 최적화 예외가 필요하다. 준비되지 않은 항목의 `허용하기` 버튼으로 휴대폰 설정을 열고, 설정을 바꾼 뒤 앱으로 돌아오면 결과를 다시 확인한다.

## 필요한 입력

- P3.1의 백로그 요약·`done_when`·의존성.
- `docs/research.md` 5-1의 권한 정의와 Doro 권한 박탈 감지 참고 방향.
- P0.4 일반 알림 PoC 및 P0.5 알람 모드 결정 결과.
- Android 권한 상태 API와 앱별 설정 화면 이동 API.
- 활성 테마의 색상·글자·터치 영역 토큰.
- 실기기 확인 시 기기 모델·Android 버전·확인 시각.

## 결과물

- `PermissionGuide` 권한 안내 UI.
- `notifications`, `exactAlarms`, `fullScreen`, `battery` 네 상태의 표시와 개별 설정 이동.
- 앱이 다시 활성화될 때 네 상태를 재조회하는 재안내 로직.
- 네이티브 권한 상태 조회 및 권한별 Android 설정 인텐트 연결.
- 필수 권한 미허용 시 알람 예약을 차단하는 기존 보호 흐름과의 연결 확인.

## 선행 작업

- `P0.4`: 일반 알림 권한·채널 동작 기준.
- `P0.5`: 전체 화면 알림과 자체 Kotlin 알람 경로 결정 기준.
- 백로그 기록상 두 의존성은 구현 기준으로 확인되었으나, P0.5 실기기 검증과 P3.1 완료 전이는 별도로 대조한다.

## 수행 순서

1. `docs/research.md`와 P3.1의 네 권한 범위를 확인한다.
2. 네 권한을 공통 상태 모델로 조회하고 Android 버전에 따라 적용되지 않는 권한은 허용 상태로 처리한다.
3. 권한별 안내 행과 `허용하기` 버튼을 활성 테마 및 최소 터치 영역에 맞춰 표시한다.
4. 버튼에서 각 Android 설정을 열고, 앱 복귀 시 상태를 다시 조회한다.
5. 알람 예약이 필수 권한 미허용 상태에서 차단·안내되는지 기존 보호 로직과 대조한다.
6. 네 권한의 허용/미허용 상태에서 안내, 설정 이동, 복귀 재확인을 확인한다.
7. 구현 검사와 독립 검토 결과를 반영한 뒤 `done_when`별 근거를 기록한다. 미검증 실기기 결과는 질문으로 남긴다.

## 현재 확인 기록

- 기준 입력 최신 로그에는 네 가지 Android 권한 상태 확인, 개별 설정 화면 이동, 앱 복귀 후 재확인 UI를 구현했다고 기록되어 있다.
- `src/components/PermissionGuide.tsx`는 네 항목을 표시하고, 허용되지 않은 항목에 설정 이동 버튼을 표시한다.
- `src/notifications/permissionStatus.ts`는 `notifications`, `exactAlarms`, `fullScreen`, `battery` 네 키를 필수 권한으로 판정한다.
- `android/.../AlarmPocModule.kt`는 알림 허용 여부, 정확한 알람 가능 여부, 전체 화면 알림 AppOp, `isIgnoringBatteryOptimizations`를 조회하고 각 설정 인텐트를 연다.
- `app/index.tsx`에서 `PermissionGuide`를 화면에 연결하고 있다.
- `app/manage.tsx`에서도 권한 안내를 렌더링하며, 앱 복귀 시 전체 화면 알림 상태를 다시 확인하는 경로가 있다.
- 알람 예약 경로는 알림·정확 알람·전체 화면 알림 미허용 시 예약을 거부한다.
- 백로그 최신 로그에는 `npm run check` 전체 통과 후 독립 검토를 진행한다고 기록되어 있다. 이는 기준 입력에 적힌 주장일 뿐이며, 이 문서 작업에서는 명령을 실행하지 않았다.
- 관련 코드 확인 기록: `PermissionGuide`의 네 항목 표시·설정 이동, `permissionStatus.ts`의 네 필수 키 판정, `AlarmPocModule.kt`의 상태 조회·설정 인텐트 연결, `app/manage.tsx`의 복귀 후 재조회 경로를 확인했다.
- 홈 화면 재안내, 네 권한 예약 차단, 설정 화면 대체 경로와 권한 상태 단위 테스트를 보완했고 lint·typecheck·Jest 80개·Android debug build를 통과했다.
- 최종 독립 검토 후 현재 상태는 `needs_info`다. 네 권한 각각의 실기기 설정 이동·복귀 갱신 확인을 받기 전에는 `done`으로 판단하지 않는다.
- 이 실행에서 `npm` 명령, 품질 검사, 상태 변경은 실행하지 않았다.
- 기준 입력의 P3.1 최신 로그에는 구현과 `npm run check` 통과 주장이 있으나, 독립 검토 완료 결과나 네 권한 각각의 실기기 허용/미허용·설정 이동·복귀 재확인 결과는 포함되어 있지 않다.
- 따라서 현재 문서는 구현 경로와 확인 방법을 정리한 상태이며, 기준 입력만으로 `done_when` 충족을 확정하지 않는다.

## done_when 확인 방법

`필수 권한 4종에 대한 안내·재안내 로직이 동작함`을 다음처럼 대조한다.

| 항목 | 확인 방법 | 현재 기록 |
|---|---|---|
| 알림 | 권한을 끄고 안내·설정 이동·복귀 후 재표시 확인 | 코드 경로 확인; 실기기 결과 미기록 |
| 정확한 알람 | 허용을 끄고 설정 이동·복귀 후 상태 재확인 | 코드 경로 확인; 실기기 결과 미기록 |
| 전체 화면 알림 | 특별 접근을 끄고 설정 이동·복귀 후 재안내 확인 | 코드 경로 확인; P0.5 결과와 별도 대조 필요 |
| 배터리 최적화 예외 | 예외를 끄고 설정 이동·복귀 후 재안내 확인 | 코드 경로 확인; 실기기 결과 미기록 |
| 공통 재안내 | 백그라운드 후 앱 활성화 시 네 상태 재조회 확인 | 코드 경로 확인; 실제 복귀 동작 미기록 |

완료 판단에는 네 항목 각각의 실제 동작 근거와 독립 검토 결과가 필요하다. 코드 존재만으로 실기기 동작을 확정하지 않는다. 현재 입력과 코드 확인만으로는 구현 경로의 존재까지 확인되며, `done_when` 충족 자체는 아직 확정되지 않는다.

## 확인 질문

- 네 권한 각각을 허용/미허용으로 바꾸고 앱 복귀 후 재안내까지 `SM-A245N(Android 16)`에서 확인한 기록을 완료 근거로 추가할 것인가?
- 배터리 최적화 예외의 완료 기준을 삼성 기기에서 `isIgnoringBatteryOptimizations`가 `true`가 되는 것으로 확정할 것인가?
- Android 버전에 따라 적용되지 않는 권한을 허용으로 처리하는 현재 정책을 요구사항으로 확정할 것인가?
- `P3.1` 완료 근거에 P0.5의 전체 화면 알림 실기기 확인을 재사용할지, P3.1 화면에서 설정 이동·복귀 재확인을 별도로 수행할지 결정이 필요한가?
