# 관리자 화면 컴팩트화 작업안

요청일: 2026-10-04. 현재는 작업 등록 단계이며 앱 UI는 아직 변경하지 않았다.

## 요청과 확인한 원인

- 할 일 반복 요일 7개가 두 줄로 내려감: `TaskEditor.tsx`의 요일 버튼 최소 너비가 56이고 행에 wrap이 적용된다. 관리자 바깥 여백과 카드 안쪽 여백도 각각 24다.
- 시간표 항목 전체가 세로로 나열됨: `TimetableEditor.tsx`가 요일 구분 없이 모든 항목을 `items.map`으로 표시한다. 폼도 이 목록 아래에 상시 표시한다.
- 저장한 시간표 3개가 지나치게 큼: `TimetableSetRow.tsx`의 28 크기 이름, 설명, 이름 변경·삭제 버튼이 매 항목에 상시 표시된다. 생성 폼도 항상 열린다.
- 색·아이콘 선택의 빈 공간: 색 10개와 아이콘 10개를 wrap 행으로 전부 펼치고, 아이용 56 높이 버튼을 사용한다.
- 관리자 전체 화면: `app/manage.tsx`가 할 일·보상·시간표 관리·교시·항목·요일 복사·진단 기능을 한 ScrollView에 모두 펼친다.
- 공통 크기 원인: `src/theme/layout.ts`는 아이용 글자 16/20/28과 최소 터치 크기 56을 공유한다.

## 적용할 화면 구조

PIN을 연 뒤 `시간표 | 할 일 | 보상 | 기타` 메뉴에서 한 영역만 표시한다. 진입 기본은 시간표다.
메뉴는 한 줄로 구성하고 좁으면 가로 스크롤한다. 권한 안내의 기존 접근 경로와 PIN 보호 범위를 유지한다.
시간표 영역에는 작은 현재 시간표 선택 필드, 요일별 항목 목록, `추가` 버튼을 둔다.
교시 설정과 요일 복사는 시간표 영역의 접힌 보조 메뉴로, 진단 버튼·색상 미리보기는 기타의 접힌 영역으로 둔다.
P9.2는 메뉴를 접는 것뿐 아니라 교시 설정·요일 복사·보상 목표·PIN·관리자 권한 안내·진단 영역에
관리자 전용 크기를 실제 적용하는 책임도 가진다. 공유 컴포넌트는 관리자용 옵션으로 적용하며,
보조 영역을 펼쳤을 때도 큰 제목·과도한 여백·짧은 버튼의 불필요한 wrap을 남기지 않는다.

### P9.2 — 모든 알람 권한 허용 시 상단 안내 접기

- 관리자 상단 `알림 준비`의 알림·정확한 알람·전체 화면 알림·배터리 최적화 예외가 모두 허용이면 상세 목록을 기본으로 접는다. 작은 한 줄 열기 버튼으로 수동 확인할 수 있게 한다.
- 필요한 권한이 하나라도 부족하면 안내를 펼쳐 필요한 설정과 허용 버튼을 표시한다. 상태 조회 실패는 허용 완료로 취급하지 않고 오류와 재확인 경로를 표시한다.
- 초기 상태 확인 전에는 허용 완료로 단정하지 않는다. 관리자 재진입과 휴대폰 설정에서 앱으로 돌아올 때 실제 상태를 다시 확인한다.
- 접힌 상태에서도 상태 갱신을 유지해 권한 해제가 감지되면 안내가 다시 보인다. 단순히 컴포넌트를 제거해 갱신을 중단하지 않는다.
- 모두 허용/일부 부족/권한 해제 후 복귀/조회 실패/수동 펼치기를 P9.2 기능 확인과 P9.7 화면 확인에 포함한다.

### P9.2 — 기기 검증용 알림·알람 테스트 분리

- `일반 알림 확인`의 1분 뒤 알림과 3분 뒤 재부팅 복구 확인, `잠금 화면 알람 확인`의 15초 뒤 알람 테스트를 기본 관리자 화면에서 뺀다.
- 테스트 버튼·설명·결과·잠금 확인 체크리스트는 PIN 뒤 `기타 → 기기 테스트`의 기본 접힌 영역으로 이동한다. 재진입할 때도 기본 접힘이다.
- 이 테스트들은 실제 기기 검증용이다. 일상 편집 화면에서 공간을 차지하지 않도록 하고, 필요할 때 명시적으로 열고 버튼을 눌러 실행한다. 메뉴 진입이나 펼치기만으로 알림/알람을 예약하지 않는다.
- 실제 일정 알림·알람 기능과 권한 부족 안내는 유지한다. 테스트의 기존 권한 확인·중복 예약 방지·오류/결과 표시도 유지한다.
- P9.7에서 기본 화면에 테스트 항목이 없는지, PIN 재잠금 후 접근이 보호되는지, 펼친 테스트 화면도 컴팩트한지 확인한다.

### 공통 크기와 요일 선택

- 관리자 전용 크기: 본문·입력·버튼 글자 14~16, 영역 제목 18~20, 바깥 여백 12~16, 내부 여백 8~12를 시작 기준으로 사용한다.
- 일반 관리자 조작 영역은 최소 48×48을 목표로 한다. 한 줄 요일 선택기는 수용된 구현 기준에 따라 최소 폭 40dp·높이 48dp로 하고, 넓은 화면에서는 폭도 늘린다. 아이 화면의 공통 56 토큰은 변경하지 않는다.
- 반복 요일은 `월 화 수 목 금 토 일` 순서의 공통 한 줄 선택기를 사용한다. DB의 일=0~토=6 값은 그대로 매핑한다.
- 360dp/393dp 세로 폭, 기본 글자 배율에서 7개를 모두 한 줄에 보여준다. 중첩 카드 여백을 줄이거나 요일 행을 카드 바깥으로 배치해 7개의 조작 영역을 확보한다.
- 더 좁은 폭·큰 시스템 글자에서는 한 줄 가로 스크롤로 모든 요일에 접근한다. 겹치는 hitSlop으로 조작 영역을 억지로 늘리지 않는다.
- 시간표 목록의 요일 필터는 단일 선택이고, 추가 폼의 반복 요일은 다중 선택이다. 기존 항목 수정은 단일 요일이라는 현재 규칙을 유지한다.

### 시간표 항목 편집

- 월~일 요일 필터에서 고른 하루의 항목만 표시한다. 기본은 오늘 요일이며, 토·일도 접근 가능하다.
- 현재 시간표 세트 안에서 교시의 실제 시작 시각 또는 직접 입력 시각 순으로 정렬한다. 없는 요일은 빈 상태와 추가 버튼을 보여준다.
- 한 행에 `시각 · 이름`과 편집 진입 표시를 두고, 기본 목록에서 긴 이름은 말줄임한다. 전체 이름과 메모는 편집 화면에서 확인한다.
- 선택 항목을 누르거나 추가를 누를 때만 편집 폼을 연다. 폼은 선택 항목에 집중하는 모달로 두어 목록 길이에 따라 아래로 찾아갈 필요를 없앤다.
- 목록 필터를 바꾸는 행동은 저장 데이터나 폼의 반복 요일을 변경하지 않는다.
- 새 항목 폼을 열 때는 목록에서 선택한 요일을 초기 반복 요일로 사용한다. 폼이 열린 뒤에는 목록 필터와 폼 선택값을 독립적으로 유지한다.
- 저장 전 폼 닫기·영역 전환·세트 전환은 변경이 있을 때 버림 확인을 거친다. 저장 중에는 전환과 중복 저장을 막는다.
- 하루 4개×평일 5일=20개 데이터에서 해당 하루 4개만 목록에 표시되는 것을 확인한다. 학교 항목도 해당 요일 목록에서는 편집 가능하다.

### 저장한 시간표 고르기

- 기본 화면에는 현재 이름과 선택 버튼만 한 줄로 보인다. 목록은 버튼을 눌렀을 때 연다.
- 펼친 목록은 이름·항목 수·적용 중 표시·더보기로 이루어진 48~56 높이의 작은 행이다.
- 기본 글자 배율에서 짧은 이름의 3개 행은 합계 180dp 이내다. 생성 폼과 관리 버튼은 이 목록의 기본 높이에 포함해 항상 펼치지 않는다.
- 이름 변경·삭제는 각 행의 더보기에서, 만들기·현재 세트 복제는 추가 버튼에서 연다.
- 적용 중 세트 삭제 차단, 삭제 확인, 중복 이름 오류, 생성 후 자동 적용 금지, 세트 간 데이터 분리, 적용 후 알림·위젯 갱신을 유지한다.

### 할 일과 시간표 폼

- 할 일은 공통 반복 요일 선택기를 사용한다. 특정 날짜와 반복 요일의 상호 배타성, 완료 이력 보호, 반복 종료 기능을 유지한다.
- 할 일 목록도 작은 요약 행으로 만들고 추가·편집 시에만 폼을 연다. 완료 이력 항목의 종료 작업은 더보기에서 접근 가능하게 한다.
- 시간표 색·아이콘은 선택값 요약만 기본 표시하고, 누르면 전체 선택지를 한 줄 가로 선택 목록으로 연다. 색과 아이콘은 별도로 고른다.
- 선택 이름과 접근성 라벨을 유지하고 모든 의미 키 10개씩 선택 가능하게 한다. 테마에 따라 표시만 바뀌며 저장 키는 바꾸지 않는다.
- 일정 종류·알림 방식·교시/직접 시간 선택은 짧은 레이블로 한 줄 구성한다. 긴 설명은 도움말에 넣고 오류·삭제 확인은 필요한 내용을 전부 표시한다.
- 제목·메모의 한글 controlled TextInput은 실제 값을 직접 바인딩한다. 폼을 닫거나 전환할 때 저장되지 않은 입력이 조용히 사라지지 않게 한다.

## 확인 기준

기본 폭 360dp/393dp, 세로·가로, 글자 배율 1.0에서 스크린샷으로 비교한다. P9.3·P9.4의 사용자 결정 기록에 따라 글자 배율 1.3 확인은 완료 필수 조건에서 제외했다. 실제 폰 설정은 보존하고 폭별 확인과 실제 기기 결과를 구분한다.
P9.7은 교시·요일 복사·보상·PIN·권한 안내·진단 영역을 펼친 상태의 밀도도 확인한다.
시간표 3개 행 높이 확인에는 짧은 이름 `평소`, `방학`, `2학기`를 사용하고, 긴 이름은 별도 사례로 확인한다.
기본 글자에서는 짧은 선택 항목·버튼을 의미 없이 두 줄로 줄바꿈하지 않는다.
확대 글자·긴 이름·오류·메모·삭제 확인처럼 내용 보존이 필요한 경우에는 가로 스크롤 또는 적절한 여러 줄 표시를 허용한다.
키보드가 열린 상태에서 입력·저장·취소 버튼을 사용할 수 있어야 한다.
확인 데이터는 평일 하루 4개 일정(총 20개), 저장 시간표 3개, 긴 한글 제목·메모, 토·일 일정, 반복/특정 날짜/완료 이력 할 일을 포함한다.
PIN 보호, 앱 백그라운드 후 재잠금, 세트 분리, CRUD, 요일 매핑, 알림·위젯 갱신, 기존 아이 화면을 회귀 확인한다.
UI 구현 완료에는 관련 테스트·전체 품질 검사·등록된 병렬 리뷰와 화면 확인 근거가 필요하다.
딸 폰 확인이 필요한 항목은 에뮬레이터 근거와 구별하고 사용자 확인 전 완료로 기록하지 않는다.
