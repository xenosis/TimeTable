# TimeTable 작업 목록

> 근거와 상세 설계는 [`research.md`](research.md)를 참고한다.
> 원칙: **위험한 것부터 검증**하고, **딸 폰 단독 버전을 먼저 완성**한 뒤 서버를 붙인다.

## 전체 흐름

| 단계 | 이름 | 끝나면 할 수 있는 것 |
|------|------|----------------------|
| 0 | 사전 확인 · 기술 검증 | 딸 폰 설치와 알람 방식에 대한 불확실성이 해소됨 |
| 1 | 프로젝트 기반 | 빈 앱이 딸 폰에 설치됨 |
| 2 | 시간표 | 딸 폰에서 시간표를 보고 수정할 수 있음 (로컬) |
| 3 | 알림 · 알람 | 시간표 시간에 알림과 알람이 울림 |
| 4 | 할 일 + 칭찬 스티커 | **← 첫 실사용 버전 (MVP)** |
| 5 | 서버 연동 · 아빠 원격 관리 | 아빠 폰에서 수정하면 딸 폰에 반영됨 |
| 6 | 마무리 · 배포 | 정식 설치, 업데이트 절차 확립 |
| 7 | 추가 기능 (선택) | 위젯, NEIS 시간표 가져오기 등 |

---

## 0단계: 사전 확인 · 기술 검증

- [ ] **0-1 딸 폰 정보 확인**: 모델명, 안드로이드 버전
- [ ] **0-2 APK 설치 확인**: 패밀리링크에서 "출처를 알 수 없는 앱"을 허용하고 아무 테스트 APK나 설치해 본다
  - 실패하면 Play Console 내부 테스트 방식을 검토한다 (research.md 4장)
- [ ] **0-3 결정**: 앱 이름 · 패키지명 (D1), 네비게이션 방식 (D2)
- [ ] **0-4 알림 PoC**: expo-notifications로 1분 뒤 알림을 예약하고 아래 상황에서 확인한다
  - 화면 꺼짐 / 앱 종료 / 무음 모드 / 절전 모드
- [ ] **0-5 알람 모드 PoC**: react-native-notify-kit로 잠금화면 위 전체화면 + 반복 소리 + 끄기 버튼을 만들어 본다
  - 딸 폰에서 전체화면 알림 권한이 기본으로 켜져 있는지 확인한다
  - 결과를 보고 D3을 결정한다: A(notify-kit) 채택 / B(자체 Kotlin 모듈)
- [ ] **0-6 패밀리링크 영향 확인**: 사용 시간 제한 · 잠자리 시간 중에 알림이 오는지 확인한다
- [ ] **0-7 재부팅 확인**: 알림을 예약하고 폰을 재부팅한 뒤에도 울리는지 확인한다

## 1단계: 프로젝트 기반

- [ ] **1-1 프로젝트 생성**: Expo SDK 57 + TypeScript
  - 현재 폴더에 문서가 있으므로 임시 폴더에 만든 뒤 옮긴다
- [ ] **1-2 개발 빌드 설정**: expo-dev-client를 넣고 `npx expo run:android`로 딸 폰 · 에뮬레이터에서 실행한다
- [ ] **1-3 기본 구성**: 폴더 구조(`src/db`, `store`, `utils`, `screens`, `components`, `theme`), Zustand, expo-sqlite
- [ ] **1-4 아이용 테마**: 큰 글씨, 과목 색상 팔레트, 큰 터치 영역
- [ ] **1-5 테스트 환경**: Jest(jest-expo) 설정
- [ ] **1-6 CLAUDE.md 작성**: Doro 교훈을 옮긴다 (한글 TextInput 규칙, Hermes 크래시, `npx expo install`, 버전 관리)
- [ ] **1-7 빌드 준비**: 새 서명 키를 만들어 안전하게 보관하고, Doro `build-apk.ps1`을 참고해 APK 빌드 스크립트를 만든다
- [ ] **1-8 설치 확인**: 빈 앱 릴리즈 APK를 딸 폰에 설치한다

## 2단계: 시간표 (로컬)

- [ ] **2-1 범위 결정 (D5)**: 학교만 / 학원 · 생활 일정 포함
- [ ] **2-2 로컬 DB**: `periods`, `timetable_items`, `day_exceptions` 스키마와 마이그레이션 (SQLite)
- [ ] **2-3 교시 시간 설정**: 1교시 몇 시~몇 시인지 정하는 화면
- [ ] **2-4 오늘 화면**: 현재 일정 강조, 다음 일정까지 남은 시간
- [ ] **2-5 주간 화면**: 요일 × 교시 격자
- [ ] **2-6 항목 편집**: 추가 · 수정 · 삭제
  - 입력: 요일(여러 개 선택), 교시 또는 시간, 과목 · 색 · 아이콘, 알림 방식, 미리 알림
- [ ] **2-7 요일 복사**: 월요일 시간표를 수요일로 복사하는 기능
- [ ] **2-8 임시 PIN 잠금**: 편집 화면 진입 시 PIN (expo-secure-store에 해시 저장)
- [ ] **2-9 단위 테스트**: 현재 교시 · 다음 일정 계산

## 3단계: 알림 · 알람

- [ ] **3-1 권한 안내 화면**: 알림 권한, 정확한 알람, 전체화면 알림, 배터리 최적화 예외
  - 권한이 꺼지면 다시 안내한다 (Doro의 권한 박탈 감지 방식 참고)
- [ ] **3-2 알림 채널**: 일반 알림용 · 알람용
- [ ] **3-3 롤링 예약 계산**: 앞으로 7일 알림 목록을 만드는 순수 함수 + 단위 테스트
  - 공휴일 · 방학 예외, 미리 알림, 알림 방식별 분기 포함
- [ ] **3-4 예약 실행**: 앱이 예약한 알림 전체 취소 → 다시 예약 (중복 없이)
- [ ] **3-5 재예약 시점 연결**: 앱 실행, 데이터 변경, 앱 복귀, 백그라운드 주기 작업(expo-background-task)
- [ ] **3-6 알람 모드 구현**: 0-5 결과에 따라 전체화면 + 계속 울림 + 끄기
- [ ] **3-7 알림 탭 이동**: 알림을 누르면 해당 일정 화면으로 이동 (Doro `navigationRef` 참고)
- [ ] **3-8 공휴일**: 공휴일에는 학교 알림을 끈다 (Doro `holidaySync` 참고)
- [ ] **3-9 수동 테스트 체크리스트 작성**: `docs/test-checklist.md`

## 4단계: 할 일 + 칭찬 스티커 → MVP

- [ ] **4-1 보상 규칙 결정 (D6)**: 할 일당 스티커 수, 전부 완료 보너스, 보상 목표
- [ ] **4-2 로컬 DB**: `tasks`, `task_completions`, `sticker_ledger`, `rewards`
- [ ] **4-3 할 일 편집 (PIN)**: 요일 반복 할 일 / 특정 날짜 할 일
- [ ] **4-4 오늘의 할 일 화면**: 체크 · 취소, 진행률 표시
- [ ] **4-5 날짜 전환**: 자정이 지나거나 앱으로 돌아올 때 오늘 목록으로 바꾼다 (Doro `RoutineScreen` 참고)
- [ ] **4-6 스티커 적립**: 완료하면 적립 + 애니메이션, 취소하면 회수
- [ ] **4-7 스티커판 · 보상 화면**: 모은 스티커와 보상 목표까지 남은 개수
- [ ] **4-8 할 일 알림**: 예: 저녁 7시 "숙제했니?", 미완료면 다시 알림 (롤링 예약에 포함)
- [ ] **4-9 연속 달성 칭찬**: "N일 연속 완료" (Doro `streakCalc` 참고)
- [ ] **4-10 MVP 배포**: 릴리즈 APK를 딸 폰에 설치하고 **1주일 실사용** 후 피드백을 반영한다

## 5단계: 서버 연동 · 아빠 원격 관리

- [ ] **5-1 결정**: Supabase 프로젝트 (D4), PIN 권한 확인 방식 (D7)
- [ ] **5-2 스키마**: Supabase 테이블 생성, SQL 파일을 `supabase/migrations`로 관리
- [ ] **5-3 RLS 정책**: 아빠 = 전체 쓰기 / 딸 = 읽기 + 오늘 완료 체크
- [ ] **5-4 로그인 · 역할 분기**: 로그인 화면, 역할에 따라 아빠 화면 / 딸 화면
- [ ] **5-5 기존 데이터 이전**: 딸 폰의 로컬 데이터를 서버로 최초 1회 업로드
- [ ] **5-6 동기화**: 서버 → SQLite → 알림 재예약
  - 오프라인일 때는 캐시를 쓰고, 완료 체크는 대기열에 넣었다가 나중에 올린다
- [ ] **5-7 Realtime + 앱 복귀 동기화**
- [ ] **5-8 아빠 화면**: 시간표 · 할 일 편집, 딸 완료 현황 · 스티커, 딸 폰 마지막 동기화 시각
- [ ] **5-9 변경 푸시**: Edge Function으로 딸 폰에 "시간표가 바뀌었어요" 알림 (Doro 푸시 가이드 재사용)
  - Firebase 앱을 추가하고 FCM 키를 등록한다
- [ ] **5-10 딸 폰 PIN 관리자 모드**: 서버 RPC로 PIN 확인
  - 실패 횟수 제한, 5분 뒤 자동 해제
  - 2-8의 임시 PIN을 대체한다
- [ ] **5-11 (선택) 완료 알림**: 딸이 할 일을 다 하면 아빠 폰으로 푸시
- [ ] **5-12 일시정지 대비**: Supabase가 일시정지돼도 딸 폰 알림이 계속 울리는지 확인한다

## 6단계: 마무리 · 배포

- [ ] **6-1 앱 꾸미기**: 아이콘, 스플래시, 알림 아이콘
- [ ] **6-2 설치**: 딸 폰 · 아빠 폰 릴리즈 APK 설치
- [ ] **6-3 문서화**: 빌드 · 업데이트 절차를 `docs/build-commands.md`에 정리
  - 서명 키 백업 위치 기록 포함
- [ ] **6-4 회귀 테스트**: 전체 체크리스트 수행
