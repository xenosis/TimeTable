# TimeTable 작업 목록

> 근거와 상세 설계는 [`research.md`](research.md)를 참고한다.
> 원칙: **위험한 것부터 검증**하고, **딸 폰 단독 버전을 먼저 완성**한 뒤 서버를 붙인다.

## 전체 흐름

| 단계 | 이름 | 끝나면 할 수 있는 것 |
|------|------|----------------------|
| 0 | 사전 확인 · 기술 검증 | 딸 폰 설치와 알람 방식에 대한 불확실성이 해소됨 |

## 5단계: 홈 화면 위젯 → MVP

앱을 일일이 열지 않아도 바탕화면에서 바로 오늘 시간표 · 할 일을 볼 수 있게 한다. (Doro `CalendarWidget*.kt` 경험 재사용)

- [ ] **5-1 위젯 크기 · 레이아웃 결정**: 오늘 시간표(현재/다음 일정) + 오늘 할 일 체크 리스트를 한 화면에. 활성 테마는 대비가 보장된 색·배경만 위젯에 반영한다
- [ ] **5-2 데이터 브릿지**: JS → 파일(`filesDir`) → Kotlin `AppWidgetProvider` (Doro `WidgetDataCache` 패턴)
- [ ] **5-3 위젯에서 할 일 체크**: RemoteViews 버튼 탭 → 완료 처리 (Doro는 보기 전용이었으므로 새로 설계 필요)
- [ ] **5-4 위젯 자동 갱신**: 시간이 지나 다음 교시로 바뀌면 위젯도 갱신 (주기적 갱신 또는 알림 트리거 시 갱신)
- [ ] **5-5 탭하면 앱 이동**: 위젯 탭 → 해당 화면으로 바로 이동 (Expo Router 경로 사용)
- [ ] **5-6 MVP 배포**: 릴리즈 APK를 딸 폰에 설치 + 위젯 추가하고 **1주일 실사용** 후 피드백 반영

## 6단계: 서버 연동 · 아빠 원격 관리

- [ ] **6-1 결정**: Supabase 프로젝트 (D4), PIN 권한 확인 방식 (D7)
- [ ] **6-2 스키마**: Supabase 테이블 생성, SQL 파일을 `supabase/migrations`로 관리
- [ ] **6-3 RLS 정책**: 아빠 = 전체 쓰기 / 딸 = 읽기 + 오늘 완료 체크
- [ ] **6-4 로그인 · 역할 분기**: 로그인 화면, 역할에 따라 아빠 화면 / 딸 화면
- [ ] **6-5 기존 데이터 이전**: 딸 폰의 로컬 데이터를 서버로 최초 1회 업로드
- [ ] **6-6 동기화**: 서버 → SQLite → 알림 재예약 → 위젯 갱신
  - 오프라인일 때는 캐시를 쓰고, 완료 체크는 대기열에 넣었다가 나중에 올린다
- [ ] **6-7 Realtime + 앱 복귀 동기화**
- [ ] **6-8 아빠 화면**: 시간표 · 할 일 편집, 딸 완료 현황 · 스티커, 딸 폰 마지막 동기화 시각
- [ ] **6-9 변경 푸시**: Edge Function으로 딸 폰에 "시간표가 바뀌었어요" 알림 (Doro 푸시 가이드 재사용)
  - Firebase 앱을 추가하고 FCM 키를 등록한다
- [ ] **6-10 딸 폰 PIN 관리자 모드**: 서버 RPC로 PIN 확인
  - 실패 횟수 제한, 5분 뒤 자동 해제
  - 2-8의 임시 PIN을 대체한다
- [ ] **6-11 (선택) 완료 알림**: 딸이 할 일을 다 하면 아빠 폰으로 푸시
- [ ] **6-12 일시정지 대비**: Supabase가 일시정지돼도 딸 폰 알림 · 위젯이 계속 동작하는지 확인한다
