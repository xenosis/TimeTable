## 2026-10-04 추가 요청: 관리자 화면 컴팩트화 (P9)

세부 작업안과 화면 확인 기준: [`admin-compact-plan.md`](admin-compact-plan.md).
아래 항목은 작업 등록 상태이며 기존 편집 기능의 완료 이력을 되돌리지 않는다.

- [ ] **P9.1 관리자 전용 크기·공통 월~일 선택기**: 아이용 공통 토큰과 분리하고 반복 요일 7개를 한 줄로 통일한다.
- [ ] **P9.2 관리자 영역 메뉴·보조 메뉴 접기**: 시간표/할 일/보상/기타 중 선택 영역만 표시하고 교시·요일 복사·보상·PIN·권한 안내·진단에도 관리자 전용 크기를 적용한다. 상단 알림 준비는 모든 권한 허용 시 기본 접힘, 부족하거나 확인에 실패하면 다시 표시한다.
- [ ] **P9.3 할 일 요약 목록·컴팩트 폼**: 반복 요일, 알림, 완료 이력 항목 종료 기능을 작은 관리 UI로 정리한다.
- [ ] **P9.4 시간표 요일별 편집 목록**: 전체 20개 목록 대신 선택 하루만 시간순 표시하고 추가·편집 폼은 모달로 연다.
- [ ] **P9.5 저장 시간표 작은 선택 목록**: 현재 시간표는 한 줄, 이름 변경·삭제·생성·복제는 필요할 때 연다.
- [ ] **P9.6 색·아이콘·시간·알림 폼 정리**: 선택값 요약과 한 줄 선택 목록, 짧은 버튼 문구로 기본 화면 높이를 줄인다.
- [ ] **P9.7 화면 밀도·입력·기능 회귀 확인**: 작은 화면, 확대 글자, 키보드, 주말, 긴 이름과 세트 전환을 확인한다.

P9는 이미 완료된 PIN/시간표/할 일/시간표 세트 편집 위의 개선 작업으로, 서버 연동 완료를 기다리지 않는다.
P9.2에는 기기 검증용 일반 알림·재부팅 복구·잠금 화면 알람 테스트를 기본 화면에서 빼고 PIN 뒤 `기타 → 기기 테스트` 접힌 영역으로 이동하는 작업도 포함한다.

## 2026-10-04 추가 요청: 시간표 시간축·현재 시각 가독성 (P10)

세부 기준: [`timetable-readability-plan.md`](timetable-readability-plan.md). 기존 P2.13/P2.15 완료 이력을 유지하는 후속 작업이다.

- [ ] **P10.1 모든 시각을 왼쪽 시간 칼럼으로 이동**: 일정 칸의 시간 값을 전부 왼쪽 칼럼에서 표시하고, 일정 칸에는 시간 문자열을 남기지 않는다. 요일별 실제 시작·종료 경계도 보존한다.
- [ ] **P10.2 현재 시각 강조**: 선택한 요일의 해당 시간대만 밝게, 나머지는 연하게 표시하고 전환·앱 복귀·시간 경계에 즉시 갱신한다.

요일별 다른 요일은 현재 시각 기준 미리보기로 구별하고, 주간표는 오늘 실제 진행 중 일정만 강조한다.

## 5단계: 홈 화면 위젯 → MVP

앱을 일일이 열지 않아도 바탕화면에서 바로 오늘 시간표 · 할 일을 볼 수 있게 한다. (Doro `CalendarWidget*.kt` 경험 재사용)

- [ ] **5-1 위젯 크기 · 레이아웃 결정**: 오늘 시간표(현재/다음 일정) + 오늘 할 일 체크 리스트를 한 화면에. 활성 테마는 대비가 보장된 색·배경만 위젯에 반영한다
- [ ] **5-2 데이터 브릿지**: JS → 파일(`filesDir`) → Kotlin `AppWidgetProvider` (Doro `WidgetDataCache` 패턴)
- [ ] **5-3 위젯에서 할 일 체크**: RemoteViews 버튼 탭 → 완료 처리 (Doro는 보기 전용이었으므로 새로 설계 필요)
- [ ] **5-4 위젯 자동 갱신**: 시간이 지나 다음 교시로 바뀌면 위젯도 갱신 (주기적 갱신 또는 알림 트리거 시 갱신)
- [ ] **5-5 탭하면 앱 이동**: 위젯 탭 → 해당 화면으로 바로 이동 (Expo Router 경로 사용)
- [ ] **5-6 MVP 배포**: 릴리즈 APK를 딸 폰에 설치 + 위젯 추가하고 **1주일 실사용** 후 피드백 반영

## 오늘 탭 정보 우선순위 변경 (P15, 2026-10-05 사용자 승인)

- 사용자가 critical-reviewer와 논의한 작은 날짜·응원 → 지금·다음 일정 → 할 일 → 다른 남은 일정 펼치기 구성을 승인했다. 오늘 보석 장부 요약은 제거하고 내 보석에서만 관리한다.
- 위 P11의 초기 큰 제목 기준은 이 새 오늘 화면에서는 대체한다. 작은 인사는 날짜 16·응원 14·캐릭터 52, 요약 카드 제목 18·일정 제목 20·시각/메모 16을 구현 기준으로 선택했다. 이는 승인된 축소 구성 안의 구현 선택이며 사용자가 숫자를 개별 지정한 것은 아니다. 시스템 글자 확대를 유지하고 내용은 줄바꿈해 보존한다.
- 할 일 제목·체크 글자와 72 이상 터치 영역은 유지한다. 추가 일정 펼치기/접기와 조회 재시도 버튼은 56 이상이다. 더 작은 추가 목록은 제목16·시각13으로 현재/다음과 위계를 구분한다.
- 보석·관리자·시간표 탭의 크기 기준과 정책은 이 변경 범위에 포함하지 않는다. PC 검증과 실기기에서 아이가 읽을 수 있는지 확인하는 범위는 구별한다.

## 보석 운영 정책 변경 (P13, 2026-10-04 사용자 최종 결정)

- 보석은 실물로 지급한다. 앱은 보유 개수 관리용이다.
- 오늘 할 일, 주간·월간 전체 완료 모두 일반·큰 보석을 자동 지급하지 않는다. 완료 체크·취소·할 일 편집으로 보유 개수를 바꾸지 않는다.
- 아이가 내 보석의 개수 수정에서 일반 보석과 큰 보석을 직접 입력한다. 숫자는 0~99,999 정수이며 저장은 원장 차액으로 기록하고 재시작 뒤 유지한다.
- 과거 자동 지급으로 기록된 보유량은 지우거나 재계산하지 않는다. 실제 보유 개수로 직접 맞출 수 있다.
- 전체 완료 칭찬·연속 완료·보상 목표는 유지한다. P11의 기존 주간·월간 지급 유지 문구는 이 최종 정책으로 대체한다.
- 캐릭터 테마는 P12에 별도로 등록하며 이번 P13에서 구현하지 않는다.
- 최종 범위 제한: 보석 수량 편집과 자동 지급 중단까지만 구현한다. 선물 교환·보상 목표의 추가 변경은 되돌렸고, 나머지 보석 체계는 Claude가 이어서 개발한다. 수량 입력은 마지막 저장의 절대 개수를 우선한다.
- 이후 Claude가 구현한 실물 보석 자격·요청·지급의 확정 정책은 `docs/backlog/P4.13.md`를 따른다. 오늘 표시는 `작은 보석 · 큰 보석`이며, 목표 달성도 장부를 차감하지 않는다. 새 할 일은 생성일부터 완료·연속 계산에 반영한다. 큰 보석 5개 환산은 캐릭터 그림 변화용이고 장부·보상 목표의 가치 계산을 변경하지 않는다.
